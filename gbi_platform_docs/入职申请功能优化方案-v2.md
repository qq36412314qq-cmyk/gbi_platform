# 入职申请审批自动建档功能优化方案

**文件路径**：`gbi_platform_docs/入职申请功能优化方案-v2.md`

**更新记录**：2026\-09\-10

---

## 一、现状问题诊断

### 1\.1 当前架构问题汇总

#### 前端问题（transfer/index\.vue）

- 入职表单字段缺失：仅包含工号、姓名、入职日期、用工类型，身份证、手机、性别、出生日期、组织、岗位、工资、银行卡等必填信息全部缺失。

- 无详情查看入口：已通过/已驳回的入职记录无法查看详情。

- 页面潜在报错：状态文本未定义`entryStatusType()` 状态映射函数。

- 展示异常：用工类型无中文映射文本，页面展示为原始编码。

#### 后端问题（HrTransferServiceImpl / HrEmployeeServiceImpl）

- `onEntryApproved()` 空实现：入职审批通过后，无任何建档业务逻辑。

- `createFromEntry()`空实现：仅打印日志，未实现员工档案自动创建逻辑。

- 缺少工号唯一性校验：`submitEntry()` 未做工号重复拦截，存在重复申请风险。

#### 流程回调链路断裂

- 系统流程引擎 `FlowEngineServiceImpl` 支持业务回调机制，审批完成会触发 `invokeHandler`。

- 系统已有多款业务处理器实现，但**`HrEntryFlowHandler`****缺少入职申请专属处理器 **。

- 最终导致：入职审批通过/驳回/撤回后，无任何业务回调执行，自动建档功能完全失效。

#### 员工页面问题（employee/index\.vue）

- 权限逻辑混乱：“新增员工”按钮对所有用户可见，与入职自动建档功能场景重复，易造成数据混乱。

## 二、优化目标

重构入职申请全流程，实现**审批驱动自动建档**，标准化业务闭环：

HR填写完整入职信息 → 提交审批流（hr\_entry）

✅ 审批通过：自动创建正式员工档案（hr\_employee）

❌ 审批驳回：申请标记已驳回，不建档

🔄 申请撤销：申请标记已撤回，不建档

### C001 HrEmployeeServiceImpl\.createFromEntry\(\) 实现

**文件位置**：`gbi_platform_server/src/main/java/com/gbi/platform/hr/service/impl/HrEmployeeServiceImpl.java`

**功能说明**：根据审批通过的入职申请，自动生成员工档案，包含防重、状态校验、日志记录。

#### 原代码（空实现）

```java
@Override
@Transactional(rollbackFor = Exception.class)
public void createFromEntry(Long entryApplyId) {
    log.info("createFromEntry called with entryApplyId={}", entryApplyId);
}
```

#### 优化后完整代码

```java
@Override
@Transactional(rollbackFor = Exception.class)
public void createFromEntry(Long entryApplyId) {
    HrEntryApply apply = entryApplyMapper.selectById(entryApplyId);
    if (apply == null) {
        throw new BizException("入职申请不存在，ID=" + entryApplyId);
    }
    if (!CommonConst.APPLY_STATUS_PASS.equals(apply.getStatus())) {
        throw new BizException("入职申请尚未审批通过，ID=" + entryApplyId + "，当前状态=" + apply.getStatus());
    }

    // 防重：同一公司同一工号禁止重复建档
    LambdaQueryWrapper<HrEmployee> dupCheck = new LambdaQueryWrapper<HrEmployee>()
            .eq(HrEmployee::getCompanyId, apply.getCompanyId())
            .eq(HrEmployee::getEmployeeNo, apply.getEmployeeNo());
    Long count = employeeMapper.selectCount(dupCheck);
    if (count != null && count > 0) {
        log.warn("员工档案已存在，跳过建档：company_id={}, employee_no={}", apply.getCompanyId(), apply.getEmployeeNo());
        return;
    }

    // 封装员工档案数据
    HrEmployee employee = new HrEmployee();
    employee.setCompanyId(apply.getCompanyId());
    employee.setEmployeeNo(apply.getEmployeeNo());
    employee.setName(apply.getName());
    employee.setIdCardNo(apply.getIdCardNo());
    employee.setPhone(apply.getPhone());
    employee.setGender(apply.getGender());
    employee.setBirthdate(apply.getBirthdate());
    employee.setEntryDate(apply.getEntryDate());
    employee.setEmploymentType(apply.getEmploymentType() != null ? apply.getEmploymentType() : 1);
    employee.setEmployeeStatus(CommonConst.STATUS_ENABLED);
    employee.setOrgId(apply.getOrgId());
    employee.setPostId(apply.getPostId());
    employee.setBankAccount(apply.getBankAccount());
    employee.setBasicSalary(apply.getBasicSalary());
    employee.setRemark(apply.getRemark());
    employee.setCreateBy(apply.getCreateBy());

    employeeMapper.insert(employee);
    auditLogUtil.record(CommonConst.MODULE_HR_EMPLOYEE, CommonConst.OPER_TYPE_ADD,
            String.valueOf(employee.getId()), null, employee);
    log.info("入职审批通过，自动建档成功：employeeId={}, employeeNo={}, name={}",
            employee.getId(), employee.getEmployeeNo(), employee.getName());
}
```

### C002 HrTransferServiceImpl 两处核心修改

#### 修改1：实现 onEntryApproved 审批通过逻辑

**位置**：审批通过回调方法，更新申请状态并触发自动建档

```java
@Override
@Transactional(rollbackFor = Exception.class)
public void onEntryApproved(Long entryApplyId) {
    HrEntryApply apply = entryApplyMapper.selectById(entryApplyId);
    if (apply == null) {
        log.warn("onEntryApproved: 入职申请不存在，ID={}", entryApplyId);
        return;
    }
    if (!CommonConst.APPLY_STATUS_AUDITING.equals(apply.getStatus())) {
        log.warn("onEntryApproved: 申请状态非审批中，ID={} 当前状态={}", entryApplyId, apply.getStatus());
        return;
    }
    // 更新为已通过状态
    apply.setStatus(CommonConst.APPLY_STATUS_PASS);
    entryApplyMapper.updateById(apply);
    // 触发自动建档
    hrEmployeeService.createFromEntry(entryApplyId);
    auditLogUtil.record(CommonConst.MODULE_HR_TRANSFER, CommonConst.OPER_TYPE_SUBMIT,
            String.valueOf(entryApplyId), null, apply);
}
```

#### 修改2：submitEntry 新增双重工号唯一性校验

**位置**：数据插入前，校验未作废申请 \& 已有员工档案

```java
// 1. 校验当前是否存在未作废的入职申请
LambdaQueryWrapper<HrEntryApply> noDupCheck = new LambdaQueryWrapper<HrEntryApply>()
        .eq(HrEntryApply::getCompanyId, loginUser.getCompanyId())
        .eq(HrEntryApply::getEmployeeNo, dto.getEmployeeNo())
        .ne(HrEntryApply::getStatus, CommonConst.APPLY_STATUS_VOID)
        .ne(HrEntryApply::getStatus, CommonConst.APPLY_STATUS_REJECT);
Long dupCount = entryApplyMapper.selectCount(noDupCheck);
if (dupCount != null && dupCount > 0) {
    throw new BizException("该工号[" + dto.getEmployeeNo() + "]已有未作废的入职申请，请勿重复提交");
}

// 2. 校验员工档案是否已存在该工号
LambdaQueryWrapper<HrEmployee> empDupCheck = new LambdaQueryWrapper<HrEmployee>()
        .eq(HrEmployee::getCompanyId, loginUser.getCompanyId())
        .eq(HrEmployee::getEmployeeNo, dto.getEmployeeNo());
Long empDupCount = employeeMapper.selectCount(empDupCheck);
if (empDupCount != null && empDupCount > 0) {
    throw new BizException("该工号[" + dto.getEmployeeNo() + "]已存在于员工档案中，请勿重复申请");
}
```

#### 补充：新增驳回回调方法 onEntryRejected

```java
@Override
public void onEntryRejected(Long entryApplyId) {
    HrEntryApply apply = entryApplyMapper.selectById(entryApplyId);
    if (apply == null) return;
    apply.setStatus(CommonConst.APPLY_STATUS_REJECT);
    entryApplyMapper.updateById(apply);
}
```

### C003 新增流程处理器 HrEntryFlowHandler

**文件路径**：`gbi_platform_server/src/main/java/com/gbi/platform/hr/service/impl/HrEntryFlowHandler.java`

**作用**：接入流程引擎回调，监听 hr\_entry 审批事件，驱动业务逻辑

```java
package com.gbi.platform.hr.service.impl;

import com.gbi.platform.common.constant.CommonConst;
import com.gbi.platform.hr.service.HrTransferService;
import com.gbi.platform.service.FlowBizHandler;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Component;

/**
 * 入职申请审批回调处理器
 * bizType = hr_entry 与流程定义匹配
 */
@Slf4j
@Component
@RequiredArgsConstructor
public class HrEntryFlowHandler implements FlowBizHandler {

    private final HrTransferService transferService;

    @Override
    public String bizType() {
        return CommonConst.FLOW_DEF_HR_ENTRY;
    }

    @Override
    public void onPass(Long sourceId, Long instanceId) {
        log.info("HrEntryFlowHandler.onPass: entryApplyId={}, instanceId={}", sourceId, instanceId);
        transferService.onEntryApproved(sourceId);
    }

    @Override
    public void onReject(Long sourceId, Long instanceId) {
        log.info("HrEntryFlowHandler.onReject: entryApplyId={}, instanceId={}", sourceId, instanceId);
        transferService.onEntryRejected(sourceId);
    }

    @Override
    public void onCancel(Long sourceId, Long instanceId) {
        log.info("HrEntryFlowHandler.onCancel: entryApplyId={}, instanceId={}", sourceId, instanceId);
    }
}
```

## 五、完整业务流程图

### 5\.1 入职申请提交流程

HR填写完整入职表单
↓
系统双重校验（无重复申请、无重复员工档案）
↓
写入 hr\_entry\_apply（草稿状态）
↓
提交流程引擎创建审批实例
↓
状态更新为【审批中】

### 5\.2 审批通过自动建档流程

审批人通过审批
↓
流程引擎触发 invokeHandler 回调 hr\_entry
↓
HrEntryFlowHandler\.onPass\(\)
↓
HrTransferService\.onEntryApproved\(\)
↓
更新申请状态为【已通过】
↓
调用 createFromEntry 自动建档
↓
查重通过后插入 hr\_employee 在职档案
↓
记录审计日志，流程闭环

### 5\.3 审批驳回流程

审批人驳回审批
↓
触发 onReject 回调
↓
更新申请状态为【已驳回】
↓
不创建员工档案，流程结束

## 六、风险与注意事项

|风险点|问题说明|缓解方案|
|---|---|---|
|循环依赖|Transfer 与 Employee 服务互相注入|单向调用，仅 Transfer 调用 Employee，无反向依赖|
|并发重复建档|多人同时审批可能重复建档|代码层查重 \+ 数据库唯一索引双重兜底|
|历史数据冲突|存量无索引数据可能导致新增索引失败|上线前提前排查重复工号数据|
|重复审批重试|已通过单据再次触发回调|代码内判断档案存在则自动跳过，不报错|
