# 多租户 company_id 架构与子公司创建工作流（修正版）

> 基于 org_type 组织架构模型，非市场模型。
> 适用：集团多业态、集团+子公司两级管控架构。

---

## 一、核心数据模型

### 1.1 组织架构表（sys_org）— 子公司归属的唯一来源

| 字段 | 含义 |
|---|---|
| id | 组织节点自增 ID |
| parent_id | 上级组织节点 ID，0 表示根节点 |
| company_id | 所属租户 ID，0=集团，>0=具体子公司 |
| org_name | 组织名称 |
| org_type | 1=集团 2=子公司 3=部门 |

**company_id 赋值规则：**
- org_type=1（集团）：company_id 恒为 0
- org_type=2（子公司）：company_id = MAX(sys_org.company_id) + 1（新分配独立租户 ID）
- org_type=3（部门）：company_id = 向上查找 parent_id 链中最近的 org_type=2 节点的 company_id

### 1.2 市场表（property_market）— 子公司下的物理场所

| 字段 | 含义 |
|---|---|
| id | 市场自增 ID |
| company_id | 所属子公司 ID（由登录用户上下文自动赋值，前端不可传） |
| market_name | 市场名称（如"飞宇汽车城A区"） |

**关系：** 子公司 → 下属多个市场 → 市场下属多个铺位

### 1.3 用户表（sys_user）— 绑定子公司

| 字段 | 含义 |
|---|---|
| id | 用户自增 ID |
| company_id | 所属子公司 ID，0=集团账号 |

**赋值规则：**
- 集团超级管理员添加用户：可指定任意 company_id（新建子公司账号或集团账号）
- 子公司管理员添加用户：company_id 强制锁定为登录人所属公司，dto.companyId 参数被忽略

## 二、完整工作流

### Step 1：创建子公司

`
操作人：集团超级管理员
接口：POST /org/org/add
入参：
  parentId = 1（琰越控股集团，根节点 ID）
  orgName = "飞宇汽车城"
  orgType = 2（子公司）
  status = 1（启用）

后端处理：
  1. 查询 MAX(company_id) WHERE company_id > 0 → 当前最大值为 10
  2. 新子公司 company_id = 10 + 1 = 11
  3. 写入 sys_org，company_id = 11
`

数据库结果：
`
id=13, parent_id=1, company_id=11, org_name="飞宇汽车城", org_type=2
`

### Step 2：创建子公司部门

`
操作人：集团超级管理员（或子公司管理员）
接口：POST /org/org/add
入参：
  parentId = 13（刚创建的子公司节点 ID）
  orgName = "飞宇运维部"
  orgType = 3（部门）
  status = 1（启用）

后端处理：
  1. 查询 parent_id=13 的节点，org_type=2，company_id=11
  2. 部门 company_id 继承父节点 company_id = 11
  3. 写入 sys_org
`

数据库结果：
`
id=14, parent_id=13, company_id=11, org_name="飞宇运维部", org_type=3
`

### Step 3：添加子公司管理员账号

`
操作人：集团超级管理员
接口：POST /org/user/add
入参：
  companyId = 11（新子公司 ID）
  username = "feiyu_admin"
  password = "初始密码"
  realName = "张三"
  status = 1
  roleIds = [2]（审计员角色，后续绑定业务角色）

后端处理：
  1. 集团管理员登录时 isSuperAdmin()=true，允许指定任意 companyId
  2. 写入 sys_user，company_id=11
`

### Step 4：创建市场（挂在新子公司下）

`
操作人：子公司管理员（feiyu_admin，company_id=11）
接口：POST /property/market/add
入参：
  marketName = "飞宇汽车城A区"
  （前端不传 company_id，由后端从 JWT 上下文自动赋值）

后端处理：
  1. UserContext.getLoginUser().getCompanyId() = 11
  2. 写入 property_market，company_id=11
`

### Step 5：数据隔离验证

`
子公司管理员（company_id=11）登录后：
  - 查看 sys_org：多租户拦截器自动追加 WHERE company_id=11
    → 只能看到 id=13（飞宇汽车城）和 id=14（飞宇运维部），看不到集团根节点和幼儿园组织
  - 查看 property_market：自动追加 WHERE company_id=11
    → 只能看到"飞宇汽车城A区"，看不到集团的"默认市场"
  - 查看 sys_menu / sys_dict：GLOBAL_TABLES 白名单，跳过自动过滤
    → 集团管理员可配置的全局菜单和字典仍可见

集团超级管理员（company_id=0, isSuperAdmin=true）登录后：
  - TenantLineInnerInterceptor.ignoreTable() 返回 true
    → 所有业务表查询均不追加 company_id 过滤
  - 可查看全部子公司的所有数据
`

## 三、OrgServiceImpl.add() 修复逻辑（待实施）

### 3.1 需要新增的私有方法

**getMaxCompanyId()**
`
查询 sys_org WHERE company_id > 0 的最大 company_id 值
若无任何子公司记录，返回 0
返回 maxCompanyId + 1 作为新子公司的 company_id
`

**getParentCompanyId(Long parentId)**
`
1. 查询 parentId 对应的 SysOrg 节点
2. 若该节点 org_type=2（子公司），直接返回其 company_id
3. 若该节点 org_type=3（部门）或 parentId=0，
   递归查询其 parent_id，向上查找直到找到 org_type=2 的节点
4. 若链路上没有 org_type=2 的节点，抛出异常（部门不能直接挂在集团根节点下）
`

### 3.2 add() 方法修改位置（第 64-93 行附近）

`
原逻辑：
  org.setCompanyId(UserContext.getLoginUser().getCompanyId());

新逻辑：
  if (orgType == 2（子公司）):
      dto.companyId = getMaxCompanyId() + 1
  else (orgType == 3（部门）):
      dto.companyId = getParentCompanyId(parentId)
  org.setCompanyId(dto.getCompanyId());
`

**注意：**
- 当前代码中引用了 CommonConst.ORG_TYPE_COMPANY，但该常量不存在，需改用硬编码整数 2
- getMaxCompanyId() 和 getParentCompanyId() 方法尚未实现，需同步添加
- DTO 中 companyId 字段为可选字段（@Schema 有描述但无 @NotNull），子部门和子公司创建时由后端自动计算，前端不应传此字段

## 四、现有脏数据修复方案

当前数据库中子公司节点 company_id 存在错误赋值，需通过 SQL 脚本修复：

`sql
-- 修复 sys_org 中的 company_id 错误赋值
-- 飞宇汽车城（id=6）原 company_id=0，应分配新 company_id
-- 幼儿园（id=10）原 company_id=0，应分配新 company_id

-- 1. 更新子公司节点 company_id
UPDATE sys_org SET company_id = 2 WHERE id = 6;   -- 飞宇汽车城
UPDATE sys_org SET company_id = 3 WHERE id = 10;  -- 幼儿园

-- 2. 更新子公司下属部门 company_id（继承子公司 company_id）
UPDATE sys_org SET company_id = 2 WHERE id IN (7, 8, 9);   -- 飞宇销售部/运维部/综合管理部
UPDATE sys_org SET company_id = 3 WHERE id IN (11, 12);    -- 幼儿园业务部/后勤部

-- 3. 同步修复 property_market 中的 company_id（如有已有市场数据）
-- UPDATE property_market SET company_id = 2 WHERE id = 1 AND company_id = 0;
`

## 五、权限与数据隔离矩阵

| 场景 | 集团超级管理员（company_id=0） | 子公司管理员（company_id=N） | 子公司员工（company_id=N） |
|---|---|---|---|
| 查看组织架构 | 全量（全局表不过滤） | 仅本公司节点（id=N 的子公司及其部门） | 仅本公司节点 |
| 查看市场列表 | 全量（无过滤） | 仅公司 N 的市场 | 仅公司 N 的市场 |
| 查看铺位/商户 | 全量 | 仅公司 N 的铺位 | 仅公司 N 的铺位 |
| 创建市场 | 可创建集团级市场（company_id=0） | 不可见创建入口（无权限） | 不可见创建入口 |
| 创建子公司 | 可创建（org_type=2 自动分配新 company_id） | 禁止（isSuperAdmin=false） | 禁止 |
| 创建部门 | 可创建（继承父节点 company_id） | 可创建（仅本公司下） | 不可见创建入口 |
| 创建用户 | 可指定任意 company_id | 强制锁定为本公司 company_id | 不可见创建入口 |
| 查看收费规则 | 全量只读 | 仅本公司规则 | 仅本公司规则 |
| 查看财务流水 | 全量汇总 | 仅本公司收支 | 仅本公司收支 |

## 六、红线禁止（不可违反）

1. 前端禁止透传 companyId 字段（market/tenant/stall 等新增接口，以服务端上下文为准）
2. 子公司节点不允许 org_type 从 2 改为 3，或跨公司迁移 parent_id（需级联更新所有子孙节点 company_id）
3. 删除子公司节点前，必须校验其下属部门、市场、铺位、商户是否全部清空
4. GLOBAL_TABLES 白名单外的业务表（property_market / property_stall_info 等）必须依赖多租户拦截器，禁止手动绕过
