# 第三方集成规范

## 文档描述

本规范统一集团多业态系统全部第三方对接标准，覆盖文件存储、支付、物联网水电、短信通知、钉钉考勤、金蝶财务、商户小程序、UI 主题配套第三方能力；统一对接封装、鉴权、幂等、异常重试、日志、权限、多租户隔离、版本迭代规则。
**重要说明**：钉钉考勤、金蝶财务两套第三方对接仅完成架构方案预留、接口设计、数据表预留，本期开发不落地实现，标注【暂保留方案，本期不开发】；OSS、微信 / 支付宝支付、NB-IoT 智能水电、短信为必须落地第三方能力。
规范对齐《整体业务方案》《后端编码规范》《API 日志规范》《安全开发规范》，单人独立开发统一第三方集成逻辑，避免对接代码零散、无统一管控、对账追溯缺失。

## 编译与运行说明

- 编译前端：`npm run build`（在 gbi_platform_admin 目录下执行）
- 编译打包后端：`mvn clean package -DskipTests -s "C:\Users\Admin\.m2\settings.xml"`（在 gbi_platform_server 目录下执行）
- 附：`taskkill /PID <pid> /F` 终止旧进程
- 运行后端：`C:\Users\Admin\jdk-21.0.12+8\bin\java.exe "-Dfile.encoding=UTF-8" -jar gbi_platform_server\target\gbi_platform_server-1.0.0.jar --spring.profiles.active=prod`

# 一、第三方集成整体通用设计规范

## 1.1 集成设计核心原则

1. **统一工具封装**：所有第三方 HTTP/SDK 对接逻辑统一放入`util`独立工具类，禁止 Controller、Service 内直接编写对接代码；

2. **解耦预留设计**：钉钉、金蝶做完整方案架构、字段、接口预留，代码分支、数据表、配置字段预先定义，迭代二期 / 三期再开发；

3. **幂等与重试**：所有第三方写入、推送、回调接口强制幂等校验，调用失败统一 3 次重试机制；

4. **配置外置**：AppKey、Secret、域名、额度、开关全部放入`application-dev/application-prod`，禁止代码硬编码；

5. **全链路日志**：第三方调用入参、出参、耗时、异常全部写入调试日志，关键财务 / 同步操作同步入库审计日志；

6. **多租户隔离**：第三方资源、文件、单据绑定`company_id`，分公司数据互不穿透；

7. **安全加密**：密钥密文存储，传输全程 HTTPS，入参 XSS/SQL 过滤；

8. **降级容错**：第三方服务不可用时，返回友好业务提示，不阻断核心租赁、缴费流程。

## 1.2 第三方集成分层架构

1. **配置层**：yml 全局开关、密钥、地址、阈值；

2. **工具封装层**：统一 Util 静态类，封装鉴权、请求、异常解析、重试；

3. **业务调用层**：Service 按需调用工具，增加业务前置校验（商户 / 铺位 / 公司权限）；

4. **日志审计层**：打印运行日志 + 高危同步操作入库审计；

5. **回调处理层**：统一回调拦截器，验签、幂等、状态更新、消息推送；

6. **扩展预留层**：钉钉、金蝶接口、表、DTO/VO 预先定义，功能开关控制是否启用。

## 1.3 第三方配置统一规范

### 1.3.1 yml 配置标准格式

所有第三方统一分组配置，区分全局总开关、业务参数、密钥、重试、日志：

```yaml
third:
  oss:
    enable: true
    access-key: 加密密钥
    secret-key: 加密密钥
    bucket-name: 集团公共桶
    expire-time: 3600
  pay:
    enable: true
    wx-v3-appid: xxx
    alipay-appid: xxx
  iot-meter:
    enable: true
    gateway-url: http://xxx
  sms:
    enable: true
    template-map: {"bill_remind":"模板ID"}
  dingtalk:
    enable: false # 关闭，暂不开发
    app-key: xxx
  kingdee:
    enable: false # 关闭，暂不开发
    api-host: xxx
```

### 1.3.2 环境区分约束

1. dev 环境：可使用第三方测试账号，打印完整请求日志；

2. prod 环境：密钥加密存储，关闭调试日志，仅保留 ERROR/WARN；

3. 禁用生产环境测试渠道，避免混淆正式商户数据。

## 1.4 通用工具类开发规范

1. 命名规则：第三方名称 + Util，如`OssUtil、PayUtil、IotMeterUtil、DingTalkUtil、KingdeeUtil`；

2. 全部静态方法，无成员变量，无业务耦合；

3. 内置统一 http 请求工具，统一超时时间（5s）、重试 3 次、间隔 1s；

4. 自定义 BizException 封装第三方异常，统一错误码（5001 = 第三方调用失败）；

5. 所有调用方法强制入参校验，过滤特殊字符防注入。

## 1.5 幂等、重试、回调通用规范

1. **幂等规则**
缴费、凭证推送、考勤同步、账单推送、点位保存等接口传入唯一`requestId`，Redis 缓存请求记录，5 分钟内重复请求直接拦截；

2. **重试机制**
网络超时、第三方 5xx 错误自动重试 3 次；业务逻辑失败（参数错误、无数据）不重试；

3. **回调统一处理**
所有第三方回调接口统一加验签、时间戳防重放，先幂等判断再执行业务；回调逻辑单独拆分 Service，不写 Controller；

4. **失败兜底**
调用失败写入第三方失败记录表，后台支持手动重推、批量重推。

## 1.6 日志与审计通用规范

1. 调试日志：打印第三方接口名、入参、返回、耗时、异常堆栈，敏感密钥脱敏；

2. 审计日志强制记录场景：文件上传、支付回调、考勤同步、凭证推送、智能表数据采集。

# 二、OSS 文件存储对接规范

## 2.1 业务定位

合同附件、市场底图、巡检照片、办公文档统一 OSS 存储，禁止本地磁盘存储业务文件。

## 2.2 整体集成方案

1. 工具类：`OssUtil`封装上传、下载、删除、URL生成；

2. 多租户：文件目录按 company_id 隔离，`{company_id}/{biz_type}/{uuid}.{ext}`；

3. 权限：上传/下载接口校验 JWT，禁止未登录访问 OSS 直链；

4. 审计：文件上传/删除记录审计日志（oper_module=file_upload）。

## 2.3 接口清单

1. 上传文件：`POST /base/upload`，返回 OSS URL；

2. 删除文件：`POST /base/upload/delete`，校验文件归属 company_id；

3. 生成临时访问 URL：`GET /base/upload/url`，有效期 30 分钟。

## 2.4 一期开发约束

1. 接入阿里云 OSS / 腾讯云 COS（按 yml 配置切换）；

2. 上传接口限流：单账号每分钟 10 次，防止滥用；

3. 文件类型校验：禁止 exe/html/js/php 等可执行文件上传。

# 三、支付对接规范（微信 / 支付宝）

## 3.1 业务定位

租户通过小程序或 H5 完成租金、物业费、水电费在线支付，支付成功后自动核销账单、写资金流水。

## 3.2 整体集成方案

1. 工具类：`PayUtil`封装微信 V3 支付、支付宝 SDK 支付；

2. 支付流程：生成缴费单 → 调用支付接口 → 异步回调 → 幂等核销 → 写 finance_pay_flow 流水；

3. 幂等：以 finance_pay_order.pay_order_no 为唯一键，重复回调直接返回成功；

4. 退款：调用支付渠道退款接口，写负向流水（flow_type=2），关联原流水 ID；

5. 对账：每日拉取微信/支付宝对账单，与 finance_pay_flow 自动核对差异。

## 3.3 接口清单

1. 发起支付：`POST /property/unifiedPay/create`；

2. 支付回调：`POST /property/unifiedPay/callback`（微信 + 支付宝分开）；

3. 查询支付状态：`GET /property/unifiedPay/status`；

4. 申请退款：`POST /property/unifiedPay/refund`（敏感权限，二次确认）。

## 3.4 一期开发约束

1. 微信 V3 + 支付宝当面付为主，暂不支持银行卡直连；

2. 回调接口严格验签，失败返回 400；

3. 支付金额变更需重新生成缴费单，禁止直接修改已支付订单金额。

# 四、NB-IoT 智能水电表对接规范

## 4.1 业务定位

远程抄表、欠费预警、远程断电/合闸，与 water_elec_bill 联动。

## 4.2 整体集成方案

1. 工具类：`IotMeterUtil`封装网关 HTTP 接口；

2. 抄表：定时任务每日拉取智能表读数，自动生成 water_elec_bill（category=3/4）；

3. 远程控制：欠费超阈值远程断电（需二次确认 + 审计日志），缴费后自动合闸；

4. 数据映射：智能表 MAC 地址 ↔ property_water_elec_meter.meter_no。

## 4.3 接口清单

1. 远程抄表：`POST /waterElec/meter/read`（网关主动上报或后端轮询）；

2. 远程控制（断电/合闸）：`POST /waterElec/meter/control`（敏感操作，二次确认 + 审计）；

3. 设备状态查询：`GET /waterElec/meter/status`。

## 4.4 一期开发约束

1. 网关协议预留（Modbus/TCP 或 HTTP REST），具体协议按实际设备厂商调整；

2. 远程控制属高危操作，必须二次确认 + 写审计日志（oper_module=water_elec_control）；

3. 抄表失败不阻塞账单生成，人工补录兜底。

# 五、短信通知对接规范

## 5.1 业务定位

欠费提醒、缴费成功通知、到期预警、审批待办提醒，复用第三方短信网关。

## 5.2 整体集成方案

1. 工具类：`SmsUtil`封装阿里云短信 / 腾讯云短信；

2. 模板管理：短信模板 ID 存入 sys_config，按场景（欠费提醒/缴费成功/到期预警）配置；

3. 发送异步：短信发送不阻塞主流程，失败记录待重试队列；

4. 频率控制：同一手机号每天最多 5 条，防骚扰。

## 5.3 接口清单

1. 发送短信：`POST /base/sms/send`（内部接口，Service 调用）；

2. 短信发送记录：sms_send_record 表（可选，便于追溯）。

## 5.4 一期开发约束

1. 接入阿里云短信（按 yml 配置切换厂商）；

2. 敏感场景（欠费断电提醒）必须二次确认，禁止自动发送；

3. 短信内容禁止包含链接、密钥等敏感信息。

# 六、钉钉考勤对接模块（预留方案）

## 6.1 文档标注：完整对接架构、数据表、DTO 预留，二期上线开发，一期仅占位

## 6.2 业务定位

员工考勤数据双向同步：钉钉打卡数据拉取到系统，审批通过的请假/出差状态同步回钉钉。

## 6.3 整体集成方案

1. 配置层：dingtalk 开关、AppKey、AppSecret、corpId；

2. 工具类：`DingTalkUtil`封装部门同步、人员同步、打卡记录同步、审批拉取；

3. 定时任务：每日凌晨拉取前一日考勤数据；

4. 数据映射：钉钉部门→系统分公司 / 部门，钉钉用户→sys_user；

5. 多租户：同步数据绑定 company_id，各分公司考勤隔离；

6. 幂等：以钉钉打卡 ID 作为唯一键，重复同步覆盖；

7. 审计：批量同步、手动同步操作记录审计日志；

8. 数据表预留：sys_ding_sync_record（同步日志表，一期建表无业务写入）；

9. 控制开关：系统全局参数控制是否开启同步，一期默认 false，不执行任何拉取逻辑。

### 6.4 预留接口清单（代码预留，不实现逻辑）

1. 同步钉钉部门；

2. 同步钉钉员工；

3. 批量拉取打卡记录；

4. 拉取钉钉请假出差审批；

5. 手动触发全量同步接口。

### 6.5 一期开发约束

1. 仅新增 yml 配置、DingTalkUtil 空壳类、同步记录表、同步 DTO/VO；

2. 定时任务、Controller 接口添加`if(enable) return;`拦截，不执行同步；

3. 前端考勤页面隐藏钉钉同步按钮，仅展示本地考勤数据。

# 七、金蝶财务凭证对接模块（预留方案）

## 7.1 文档标注：完整对接架构、数据表、DTO、接口预留，三期财务一体化迭代开发，一期完全不开发

## 7.2 业务定位

租赁、水电、营销收支流水自动推送金蝶，生成会计凭证，实现业务财务一体化对账。

## 7.3 整体集成方案

1. 配置层：kingdee 开关、API 地址、账套 ID、密钥、凭证推送重试次数；

2. 工具类：`KingdeeUtil`封装凭证推送、科目查询、对账接口；

3. 业务触发：财务流水新增支持手动 / 定时批量推送凭证；

4. 幂等：以 finance_flow_id 作为推送唯一标识，防止重复生成凭证；

5. 多租户：分公司对应金蝶独立账套，推送数据隔离；

6. 失败处理：推送失败存入推送失败表，后台手动重推；

7. 审计：凭证推送、重推、对账全部记录审计日志；

8. 数据表预留：biz_kingdee_push（凭证推送记录表，一期仅建表无数据）；

9. 开关控制：全局参数关闭，所有推送逻辑拦截返回。

### 7.4 预留接口清单（代码占位，无业务实现）

1. 获取金蝶会计科目；

2. 单条流水推送凭证；

3. 批量凭证推送；

4. 凭证对账核对接口；

5. 手动重推失败凭证接口。

### 7.5 一期开发约束

1. 仅新增配置、KingdeeUtil 工具类、推送记录表、DTO；

2. 财务页面隐藏金蝶推送相关按钮、菜单；

3. 业务流程不触发推送逻辑，财务流水仅本地存储。

# 八、前端第三方集成统一规范（PC + 小程序）

1. 所有第三方请求统一封装`api/xxx.ts`，复用 request 拦截器统一处理 401/500；

2. 上传、支付、画布底图上传复用全局通用组件，禁止单独封装第三方逻辑；

3. 钉钉、金蝶相关页面、按钮、路由通过全局开关隐藏，一期不展示；

4. 小程序仅集成支付、OSS 图片能力，无钉钉 / 金蝶入口；

5. 第三方弹窗、提示文案统一规范，失败提示不展示底层密钥、接口地址。

# 九、第三方安全开发红线

1. 禁止第三方密钥、接口地址硬编码在前后端代码；

2. 第三方入参、回调不拼接 SQL，全部参数化；

3. 画布 JSON、钉钉同步内容、金蝶凭证内容过滤 XSS 脚本；

4. 生产环境第三方接口强制 HTTPS；

5. 第三方批量导出、批量同步增加权限校验，高危操作需二级复核；

6. 禁止前端直接调用第三方原生接口，全部后端中转代理；

7. 钉钉、金蝶虽暂不开发，但其配置接口、同步接口必须添加 @PreAuthorize 权限注解。

# 十、迭代开发区分规则

## 10.1 一期（当前开发）必须落地第三方

OSS 文件存储、微信 / 支付宝支付、NB-IoT 智能水电网关、短信通知。

## 10.2 二期上线开发：钉钉考勤同步

现有预留配置、工具、数据表启用，关闭全局开关逻辑，新增定时同步任务、前端同步操作页面。

## 10.3 三期上线开发：金蝶财务凭证对接

启用 Kingdee 相关配置、推送逻辑，新增财务对账页面、批量重推功能，打通业务流水与金蝶凭证。

# 十一、开发强制禁止行为

1. 第三方对接逻辑分散写在 Controller/Service，不统一封装 Util；

2. 钉钉、金蝶本期直接编写同步推送业务代码；

3. 第三方密钥明文提交 git 仓库；

4. 第三方调用无重试、无幂等机制；

5. 跨 company_id 操作第三方单据、文件、同步数据；

6. 高危第三方操作（断电、凭证推送、批量考勤同步）不写入审计日志；

7. 前端直接暴露第三方接口、密钥、业务内部地址；

8. 数据表不预留钉钉、金蝶同步记录表，后期新增表破坏版本迭代。
