## 一、业务背景与目标

### 1.1 现状问题

当前 `HrSalaryServiceImpl.generateMonth()` 仅从 `hr_salary_archive` 读取应发工资结构，直接计算：

```
gross = basicSalary + performanceSalary + positionAllowance + otherAllowance
net = gross - socialSecurity - housingFund
```

**缺失项：**
- 无考勤数据接入，无法扣减旷工、迟到、早退、事假
- `hr_salary_month.deductionAmount` 字段预留但从未使用
- `hr_attendance_record.leaveDays` 无类型区分，无法识别有薪假/无薪假
- 无最低工资保护逻辑
- 无"不计算考勤"员工豁免机制

### 1.2 升级目标

1. 月度薪资生成时，**可选同步考勤数据**并据此计算扣款
2. 支持**有薪假/无薪假/旷工/迟到/早退**分类扣减
3. 支持**部分员工豁免考勤核算**（如计件/销售岗位）
4. 正常员工实发金额**不得低于当地最低工资**（新员工首月不满整月除外）
5. 完整审计记录，扣款明细可追溯

## 二、计算公式

### 2.1 基础日薪

```
日薪 = basicSalary / 21.75
```

`21.75` 为国家法定月计薪天数（365天−104天休息日）÷ 12月。

### 2.2 各项扣款明细

| 扣款类型 | 计算公式 | 说明 |
|----------|----------|------|
| **旷工扣款** | `Σ(absent) × 日薪` | `absent` 为旷工天数（整数） |
| **迟到扣款** | `Σ(lateMinutes) × (日薪 / 480) × latePenaltyRate` | 480 = 日薪对应分钟数（8小时×60），可按规则配置倍数 |
| **早退扣款** | `Σ(earlyMinutes) × (日薪 / 480) × earlyPenaltyRate` | 同上 |
| **事假扣款** | `Σ(leaveDays WHERE leave_type=0) × 日薪` | 仅无薪事假扣全额日薪 |
| **有薪年假扣款** | `0` | 有薪假不扣款 |
| **其他有薪假扣款** | `0` | 婚假、产假、病假等按国家法规不扣款 |

### 2.3 扣款合计与实发

```
attendanceDeduction = 旷工扣款 + 迟到扣款 + 早退扣款 + 事假扣款
grossAmount = basicSalary + performanceSalary + positionAllowance + otherAllowance
netAmount = grossAmount − socialSecurity − housingFund − taxAmount − attendanceDeduction − otherDeduction
```

> **注意：** `socialSecurity`、`housingFund`、`taxAmount` 仍由现有社保核算服务计算后回填，本规范仅新增 `attendanceDeduction` 部分。

### 2.4 最低工资保护

```
if (员工非新员工首月) and (netAmount < 当地最低工资):
    允许扣款上限 = grossAmount − socialSecurity − housingFund − 当地最低工资
    if (attendanceDeduction > 允许扣款上限):
        attendanceDeduction = 允许扣款上限
        netAmount = 当地最低工资
        remark += "（已触发最低工资保护，扣款调减）"
```

**新员工首月豁免规则：**
- 入职日期（`entry_date`）在当月15日之后，且为该公司在该月的**第一次**生成薪资记录 → 视为"首月不满整月"
- 首月不满整月员工，**不执行最低工资保护**，允许实发低于最低工资
- 判断依据：`hr_employee.entry_date` 与 `hr_salary_month.salary_month` 比较

## 三、请假类型定义

### 3.1 leave_type 枚举

在 `hr_attendance_record.leave_days` 字段旁新增 `leave_type` 字段（TINYINT），枚举如下：

| leave_type | 含义 | 是否扣款 |
|------------|------|----------|
| 0 | 无薪事假 | ✅ 扣全额日薪 |
| 1 | 有薪年假 | ❌ 不扣 |
| 2 | 婚假 | ❌ 不扣 |
| 3 | 产假/陪产假 | ❌ 不扣 |
| 4 | 病假 | ❌ 不扣（按法规） |
| 5 | 工伤假 | ❌ 不扣 |
| 6 | 公差/出差 | ❌ 不扣 |
| 7 | 调休假 | ❌ 不扣 |

### 3.2 数据结构设计（JSON 聚合）

考勤汇总时，`hr_attendance_record` 的 `leaveDays` 字段保持原有字符串格式，**新增** `leaveType` 字段记录本次汇总中占主导的请假类型（用于审计）。

**聚合查询示例（Mapper SQL）：**

```sql
-- 按员工+月份聚合考勤数据
SELECT
  employee_id,
  SUM(absent)                           AS total_absent,          -- 旷工总天数
  SUM(late_minutes)                     AS total_late_minutes,    -- 迟到总分钟
  SUM(early_minutes)                    AS total_early_minutes,   -- 早退总分钟
  SUM(CASE WHEN leave_type = 0 THEN leave_days ELSE 0 END) AS unpaid_leave_days,  -- 无薪事假天数
  SUM(CASE WHEN leave_type != 0 THEN leave_days ELSE 0 END)  AS paid_leave_days,   -- 有薪假天数
  MAX(work_days)                        AS work_days,
  MAX(actual_days)                      AS actual_days
FROM hr_attendance_record
WHERE company_id = ?
  AND attendance_month = ?
  AND is_delete = 0
GROUP BY employee_id
```

## 四、员工分类：是否参与考勤核算

### 4.1 skip_attendance 字段

在 `hr_salary_rule` 表新增 `skip_attendance` 字段：

| skip_attendance | 含义 |
|-----------------|------|
| 0 | 正常参与考勤核算（默认） |
| 1 | 跳过考勤核算，不扣减任何考勤相关款项 |

**适用场景：**
- 计件工资制员工
- 销售岗位（提成制）
- 外勤/免打卡岗位
- 高管固定年薪制

### 4.2 判断逻辑

```
if (salaryRule.skipAttendance == 1):
    attendanceDeduction = 0
    skip 考勤数据读取
else:
    正常读取考勤数据并计算扣款
```

## 五、流程设计

### 5.1 月度薪资生成完整流程

```
用户选择月份 + 勾选员工 → 点击"生成薪资"
         │
         ▼
  ┌─────────────────────┐
  │  syncAttendance?    │ ← 前端新增复选框
  │  (是否同步考勤数据)   │
  └──────────┬──────────┘
             │
      ┌──────┴──────┐
      │ 是           │ 否
      ▼              ▼
  读取考勤数据    跳过考勤
  聚合统计        计算
      │              │
      └──────┬───────┘
             ▼
  ┌─────────────────────────┐
  │ 读取薪资档案 hr_salary_  │
  │ archive（当前版本）      │
  └───────────┬─────────────┘
              │
              ▼
  ┌─────────────────────────┐
  │ 读取员工 hr_employee     │
  │ 获取 city_code           │
  └───────────┬─────────────┘
              │
              ▼
  ┌─────────────────────────┐
  │ 调用社保核算服务          │
  │ HrSocialCalcService      │
  │ .generateMonthSalary()   │
  │ 回填社保/公积金分项       │
  └───────────┬─────────────┘
              │
              ▼
  ┌─────────────────────────┐
  │ 计算考勤扣款             │
  │   - 判断 skipAttendance  │
  │   - 计算旷工/迟到/早退/事假│
  │   - 应用最低工资保护      │
  └───────────┬─────────────┘
              │
              ▼
  ┌─────────────────────────┐
  │ 写入 hr_salary_month     │
  │ 保留审计快照             │
  └─────────────────────────┘
```

### 5.2 最低工资保护判断时序

```
Step1: 计算 grossAmount（应发合计）
Step2: 计算社保公积金个人扣款（由社保核算服务完成）
Step3: 计算考勤扣款 attendanceDeduction
Step4: 初步计算 netAmount = gross − 社保 − 公积金 − 考勤扣款
Step5: 判断是否需要最低工资保护：
        if (!isNewEmployeeFirstMonth) and (netAmount < minWage):
            调减考勤扣款，netAmount = max(netAmount, minWage)
Step6: 写入 hr_salary_month
```

## 八、风险点与应对

| 风险点 | 说明 | 应对措施 |
|--------|------|----------|
| **考勤数据缺失** | 员工当月无考勤记录 | 考勤聚合返回 null 时，`attendanceDeduction = 0`，不报错，记录日志警告 |
| **重复生成** | 同一员工同月生成两次 | `hr_salary_month` 已有唯一索引 `(employee_id, salary_month, is_delete)`，第二次生成走 `update` 而非 `insert`，并覆盖考勤扣款字段 |
| **最低工资误保护** | 新员工首月被错误保护 | 通过 `entry_date` 与 `salary_month` 精确比较，首月不满整月豁免 |
| **扣款后为零或负** | 极端情况下 netAmount ≤ 0 | 强制 `netAmount = max(netAmount, 0.01)`，并记录告警日志 |
| **并发生成** | 多人同时点击生成 | `@Transactional` + 行级锁（`SELECT ... FOR UPDATE` 或 MP 乐观锁） |
| **历史数据回填** | 旧考勤记录无 `leave_type` | 脚本将存量数据 `leave_type` 默认设为 0（无薪事假），HR 确认后批量修正 |
| **漏算风险** | 应算考勤但 syncAttendance=0 | 前端默认勾选，操作前二次确认弹窗提示"本次生成不包含考勤扣款" |

## 十、部署注意事项

1. **升级顺序：** 先执行 SQL 升级脚本（v2.10），再部署后端代码，最后更新前端
2. **存量数据处理：** 执行 SQL 后，需 HR 人工审核 `hr_attendance_record` 中 `leave_type` 为默认值 0 的记录，修正为正确类型
3. **首次启用：** 建议先用一个子公司试运行一个月，对比手工算薪结果，确认无误后再全量启用
4. **回滚方案：** 若发现计算结果异常，可通过 `pay_status` 字段判断（`pay_status=0` 的纪录可安全删除重生成）
5. **性能：** 考勤聚合查询按 `company_id + attendance_month` 索引，预计万级员工规模 < 1秒

## 十一、附录：完整计算伪代码

```java
// 核心计算逻辑伪代码（供开发参考）

BigDecimal dailyWage = archive.getBasicSalary().divide(new BigDecimal("21.75"), 4, RoundingMode.HALF_UP);

// 1. 旷工扣款
BigDecimal absentDeduction = attendance.getTotalAbsent()
    .multiply(dailyWage)
    .setScale(2, RoundingMode.HALF_UP);

// 2. 迟到扣款
BigDecimal lateDeduction = attendance.getTotalLateMinutes()
    .multiply(dailyWage)
    .divide(new BigDecimal("480"), 4, RoundingMode.HALF_UP)
    .multiply(rule.getLatePenaltyRate())
    .setScale(2, RoundingMode.HALF_UP);

// 3. 早退扣款
BigDecimal earlyDeduction = attendance.getTotalEarlyMinutes()
    .multiply(dailyWage)
    .divide(new BigDecimal("480"), 4, RoundingMode.HALF_UP)
    .multiply(rule.getEarlyPenaltyRate())
    .setScale(2, RoundingMode.HALF_UP);

// 4. 事假扣款（仅 leave_type=0）
BigDecimal unpaidLeaveDeduction = attendance.getUnpaidLeaveDays()
    .multiply(dailyWage)
    .setScale(2, RoundingMode.HALF_UP);

// 5. 考勤扣款合计
BigDecimal attendanceDeduction = absentDeduction.add(lateDeduction)
    .add(earlyDeduction)
    .add(unpaidLeaveDeduction);

// 6. 初步 netAmount
BigDecimal netAmount = grossAmount
    .subtract(socialSecurity)
    .subtract(housingFund)
    .subtract(taxAmount)
    .subtract(attendanceDeduction)
    .subtract(otherDeduction);

// 7. 最低工资保护（新员工首月豁免）
boolean isFirstMonth = employee.getEntryDate() != null
    && isSameMonthOrAfter(employee.getEntryDate(), salaryMonth);
boolean minWageProtected = false;

if (!isFirstMonth && minWage.compareTo(BigDecimal.ZERO) > 0
        && netAmount.compareTo(minWage) < 0) {
    BigDecimal maxAllowedDeduction = grossAmount
        .subtract(socialSecurity)
        .subtract(housingFund)
        .subtract(minWage);
    if (attendanceDeduction.compareTo(maxAllowedDeduction) > 0) {
        attendanceDeduction = maxAllowedDeduction;
        netAmount = minWage;
        minWageProtected = true;
    }
}

// 8. 兜底：netAmount 不得为负
if (netAmount.compareTo(BigDecimal.ZERO) <= 0) {
    log.warn("员工{} {}月薪资netAmount<=0, 强制置0.01", employeeId, salaryMonth);
    netAmount = new BigDecimal("0.01");
}
```
