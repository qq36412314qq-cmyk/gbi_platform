# API \& 日志规范

## 文档描述

本规范统一系统全部前后端交互接口标准、请求响应格式、传参校验、分页规则、第三方对接接口约束；同时整合调试日志、业务审计日志两套完整标准，区分开发调试日志与合规审计日志，覆盖集团多租户、财务、地图、权限等高敏感场景，统一日志输出、存储、脱敏、溯源规则，适配 SpringBoot 后端、Vue3 前端整体技术栈，与《整体业务方案》《后端编码规范》《前端开发规范》《权限清单》完全对齐，单人独立开发统一接口与日志写法，降低联调、线上排查、审计对账成本。

## 一、API 通用基础规范

### 1\.1 接口分层与归属原则

1. 接口按业务模块拆分 controller：中台组织、租赁摊位、市场地图、水电、物资、OA 人事考勤、营销、财务、第三方集成（钉钉 / 金蝶 / OSS）；

2. 单一 controller 只处理对应业务接口，禁止跨模块混合接口；

3. 集团专属配置接口、子公司业务接口、全局统计接口做区分，数据权限自动携带`company_id`过滤；

4. 新增摊位地图 marketMap 控制器接口严格与前端`marketMap.ts`一一对应，前后端字段完全对齐。

### 1\.2 请求方式统一标准

|请求类型|方法|使用场景|
|---|---|---|
|数据查询、列表分页、详情|@GetMapping|仅查询，无数据变更|
|新增、编辑、删除、缴费、核销、点位保存、审批提交|@PostMapping|产生数据变更、事务操作、高危操作|
|禁止使用 @Put/@Delete 原生注解，统一 POST 提交，适配前端 axios 统一请求封装。|||

### 1\.3 全局统一返回结构体（强制所有接口遵循）

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

#### 固定错误码定义（存入 common\.constant\.ResultCode，禁止硬编码）

- 200：正常成功

- 400：参数校验失败

- 401：未登录 / Token 过期 / 登录失效

- 403：无菜单 / 按钮权限、越权访问

- 404：接口不存在、数据不存在

- 500：系统业务异常（资金、第三方调用、数据错误）

- 5001：第三方对接异常（钉钉、金蝶、智能表）

- 5002：幂等重复操作（重复缴费、重复核销）

### 1\.4 入参统一约束

1. 所有接口入参必须使用 DTO 接收，禁止零散形参；

2. DTO 增加校验注解：@NotNull、@NotBlank、@Pattern、@Size、@Digits，后端全局自动校验，不合法直接返回 400；

3. 查询 DTO 统一包含 pageNum、pageSize 分页参数，默认分页大小不超过 100；

4. 高危接口（地图点位保存、财务核销、批量删除）入参增加特殊字符过滤，防 XSS、JSON 注入；

5. 前端所有请求 Header 固定携带 token，后端全局 JWT 拦截校验，无 token 直接 401。

### 1\.5 分页返回统一标准

data 内固定结构：

```json
{
  "records": [], // 当前页数据列表
  "total": 0,    // 总条数
  "pageNum": 1,
  "pageSize": 10,
  "pages": 0
}
```

所有列表接口必须分页，禁止一次性全量返回上万条数据，防止内存溢出、接口超时。

### 1\.6 字段传输脱敏规范

VO 返回前端时自动脱敏，统一工具类 format 处理：

- 手机号：138\\*\\*\*\*1234

- 身份证：410\\*\\*\\*\\*\\*\\*\*\*1234

- 银行卡、商户对公账号仅展示后四位

- 密钥、数据库内部 ID、数据库字段不对外返回

- 地图点位 JSON 不返回数据库原始完整字符串给普通导出接口

### 1\.7 权限注解强制规范

所有业务接口必须添加`@PreAuthorize("hasPermission('模块:操作')")`
示例：

- 摊位地图列表：`stall:map:list`

- 地图编辑保存：`stall:map:edit`

- 地图导出：`stall:map:export`
无权限接口后端直接拦截返回 403，不依赖前端隐藏按钮。

### 1\.8 多租户数据隔离 API 规则

1. 登录 JWT 中永久存储 userId、companyId，全局上下文可获取；

2. 所有列表查询自动通过 MyBatis-Plus 拦截器拼接`company_id = #{当前公司ID}`；

3. 集团账号自动关闭过滤，可查全部分公司数据；

4. 新增单据、地图、营销活动等自动赋值当前登录 companyId，前端不可传递、不可篡改；

5. 跨子公司调拨、集团报表等特殊场景，代码注释说明并手动关闭数据过滤。

### 1\.9 摊位地图专属 API 约束（marketMap 控制器）

7 个固定接口，前后端一一对应：

1. getMarketList：分页查询本公司全部市场地图，自动过滤 company\_id

2. addMarket：新增地图，接收 OSS 底图 url，事务入库

3. updateMarket：修改地图名称、替换底图

4. deleteMarket：逻辑删除地图，高危操作，需二次确认 \+ 审计

5. saveMapPoints：接收前端序列化点位 JSON，过滤脚本字符后入库 point\_json

6. getMarketDetail：返回底图 \+ 完整点位 JSON 用于画布还原

7. getStallStatusByMarket：返回摊位状态集合，用于画布自动上色
约束：点位保存时校验 stallId 合法性，禁止跨市场、不存在摊位绑定。

### 1\.10 财务自定义收费规则专属 API 约束（feeRule 控制器）

收费规则归属【子公司可操作、集团可查看】，接口按模块拆分 `feeItem / feeRule / feeBill` 三个控制器，权限标识统一 `fee:*`：

1. 收费项接口（fee:item:list / add / edit / delete）：子公司自主维护收费项目，集团账号仅 list 只读；新增 / 编辑 / 删除均写入审计日志（oper\_module=fee\_rule）；

2. 收费规则接口（fee:rule:list / add / edit / delete / status）：支持六种计费模式（固定金额 / 按面积 / 仪表计量 / 按租金百分比 / 逾期违约金 / 公摊分摊），周期（月 / 季 / 年 / 一次性）、生效失效时间、折扣率、免租期配置；`rule_config_json` 阶梯 / 违约金条件由前端表单生成，后端过滤脚本后入库，禁止接收自由文本公式；

3. 规则绑定接口（fee:rule:bind）：绑定 / 解绑摊位、单摊位特殊规则覆盖（override\_price / override\_config\_json）；保存时校验 stall 归属 company 与当前登录账号一致，禁止跨子公司绑定；变更写入审计日志；

4. 周期账单接口（fee:bill:list / detail）：账单分页查询与明细查询，明细展示收费项快照（名称 / 单价 / 计费基数 / 金额小计）；历史账单锁定，规则修改不回溯旧账单；

5. 账单批量生成接口（fee:bill:generate）：按月 / 季 / 年批量生成周期账单，**强制幂等**——同一公司同一摊位同一周期已存在账单直接跳过，重复请求不重复生成；生成金额 real\_amount = original\_amount \- discount\_amount + adjust\_amount，同步写入 biz\_finance\_flow 统一流水（business\_type=fee\_bill）；

6. 账单人工调账接口（fee:bill:adjust）：敏感操作，前端二次确认弹窗，后端强制审计日志（oper\_module=fee\_bill）记录调账前后金额，大额调账（超集团配置阈值）必须走二级复核流程后再执行；

7. 账单删除仅逻辑删除，缴费完成的账单禁止删除；账单缴费联动 waterElec:pay / 通用缴费幂等接口（requestId 唯一校验）。

### 1\.11 第三方对接 API 规范（钉钉 / 金蝶 / OSS / 水电表）

1. 第三方地址、AppKey、密钥全部配置 yml，禁止硬编码；

2. 鉴权 Token 统一存入 Redis 定时刷新，避免重复请求授权接口；

3. 第三方调用统一重试机制（最多 3 次），失败写入审计日志；

4. 接口出入参封装独立 DTO，统一异常捕获封装为 BizException；

5. 金蝶凭证、钉钉考勤同步接口实现幂等，通过业务唯一 ID 防重复同步；

6. 第三方接口不暴露给前端，全部由后端中转。

### 1\.12 文件上传下载 API 规范

1. 统一复用 OssUtil，上传接口只接收 MultipartFile；

2. 限制格式 jpg/png/webp/pdf/doc/xlsx，拦截 exe/html/js 等危险文件；

3. 上传文件自动绑定 company\_id，分公司文件隔离存储；

4. 导出接口统一返回二进制流，文件名按规范`模块_年月日.xlsx`；

5. 地图底图上传复用通用上传接口，单独记录审计日志。

### 1\.13 幂等性 API 强制场景

以下接口必须增加幂等校验，传入唯一 requestId：

- 租金 / 物业费缴费、退款

- 营销优惠核销

- 地图点位批量保存

- 收费规则周期账单批量生成（同一公司同一摊位同一周期唯一，防重复生成）

- 金蝶凭证推送

- 钉钉考勤批量同步

- 批量新增 / 批量删除摊位、商户

### 1\.14 接口限流规范

高频导出、批量查询、登录接口添加 Redis 限流，限制单账号每分钟请求次数，防刷库、暴力破解。

## 二、日志分层整体设计

系统日志分为两大体系：**调试运行日志（开发 / 线上排查）**、**业务审计日志（合规、财务、权限、地图高危操作，永久留存）**，两套日志分开存储、分开打印、分开查询。

## 三、调试运行日志规范（logback 输出控制台 \+ 日志文件）

### 3\.1 日志分级

- ERROR：系统异常、第三方调用失败、SQL 错误、空指针

- WARN：参数异常、库存预警、欠费提醒、接口超时

- INFO：正常业务流程、接口进出参、定时任务启动完成

- DEBUG：开发环境打印 SQL、入参详情；生产环境关闭 DEBUG

### 3\.2 打印强制规则

1. 所有 controller 进入、退出打印接口名称、请求耗时；

2. 第三方调用前后打印入参、返回、耗时；

3. 资金操作、地图点位保存打印关键业务数据；

4. 禁止打印完整手机号、身份证、密钥明文；

5. 生产环境关闭 SQL 打印，开发环境开启用于调试；

6. 日志文件按日期分割，自动压缩，保留 30 天自动清理。

### 3\. 禁止打印内容

- 完整数据库密码、JWT 密钥、第三方密钥

- 用户完整身份证、银行卡号

- 完整画布点位 JSON（超长文本，避免日志膨胀）

## 四、业务审计日志规范（存入数据库 sys\_audit\_log 表，永久不可删除）

### 4\.1 审计日志记录范围（所有高危操作必须记录）

1. 账号权限类：新增 / 禁用账号、角色修改、敏感权限二级审核全流程

2. 全局配置类：流程模板、系统参数、营销全局规则、UI 主题修改

3. 财务资金类：缴费、退费、核销、凭证推送、财务导出

4. 摊位地图专项（重点）：底图上传 / 替换、画布点位保存、地图删除、地图导出打印

5. 租赁业务：新增 / 删除合同、摊位退租、批量修改摊位

6. 物资类：集团调拨、大额采购、报废审批

7. OA 人事：考勤批量同步、人事异动、批量导出员工信息

8. 第三方配置：钉钉 / 金蝶密钥修改、OSS 配置变更

### 4\.2 审计日志数据库固定字段

- 日志 ID、company\_id、操作人 userId、操作人姓名

- 操作 IP、操作模块、操作类型（新增 / 编辑 / 删除 / 导出 / 审核）

- 操作前 JSON、操作后 JSON、操作时间、审核人（二级复核场景）

- 单据 ID / 地图 ID / 摊位 ID 关联业务主键，便于溯源

### 4\.3 审计日志写入规则

1. 封装统一 AuditUtil 工具类，所有高危操作一行代码写入，禁止重复写入库逻辑；

2. 事务同步写入，业务操作成功才新增审计记录，业务回滚同步删除审计；

3. 地图高危操作单独标记模块 type=market\_map，便于筛选查询；

4. 敏感权限二级审核完整记录：发起、驳回、通过全流程；

5. 审计数据永久归档，不开启逻辑删除，不自动清理，满足内审、等保、财务对账。

### 4\.4 审计日志权限控制

- 集团超级管理员：可查看全平台所有审计记录，支持导出

- 分公司管理员：仅查看本 company\_id 下业务审计日志

- 普通员工：无审计日志查看菜单权限

## 五、前后端日志联动规范

1. 前端捕获接口异常（403/500），弹窗友好提示，不展示后端原始堆栈；

2. 前端关键操作（删除地图、批量核销）增加埋点，可选上传简易操作日志；

3. 页面销毁、画布销毁等前端资源释放日志仅本地调试打印，不上传后端；

4. 地图画布 JS 报错前端打印控制台，重要报错携带 stallId 上报后端调试日志。

## 六、环境差异化日志配置

1. 开发环境 dev：开启 DEBUG，打印完整入参、SQL、第三方返回；

2. 生产环境 prod：仅保留 INFO/WARN/ERROR，关闭 SQL 打印，脱敏敏感字段，日志压缩存储；

3. 生产环境禁止打印完整商户隐私、财务明细明文。

## 七、开发红线（禁止行为）

1. API 层面

    - 禁止接口无分页一次性返回全量数据

    - 禁止硬编码错误码、权限标识、业务状态字符串

    - 禁止前端直接操作 company\_id、绕过后端数据过滤

    - 禁止地图点位接口不做特殊字符过滤，存在注入风险

2. 日志层面

    - 禁止调试日志打印用户敏感隐私明文

    - 禁止高危业务操作不写入审计日志

    - 禁止审计日志定期清理、物理删除

    - 禁止第三方密钥、数据库密码打印至任何日志
