### 1.2 六大核心问题

| 序号 | 问题 | 影响 |
|------|------|------|
| P1 | `hr_salary_archive.socialSecurityPersonal` 静态快照 | 费率变更后历史档案失真，无法准确回溯 |
| P2 | `hr_salary_archive.housingFundPersonal` 静态快照 | 同上，且与月度实际扣款可能不一致 |
| P3 | `hr_social_security` 手工台账 | 数值由HR手动填写，不与算薪联动，数据不可信 |
| P4 | `HrSocialCalcServiceImpl.generateMonthSalary()` 为 TODO | 分项明细表从未被写入，明细查询页面无数据 |

| P6 | 前端 `social/index.vue` 手工台账页面与 `socialCalc/index.vue` 核算明细页面并行 | 用户困惑：哪个是正确的数据来源 |

## 三、数据库变更方案

### 3.1 `hr_salary_archive` 表变更

**移除两个动态字段**（静态快照不应存在于档案表）：

```sql
ALTER TABLE hr_salary_archive
  DROP COLUMN social_security_personal,
  DROP COLUMN housing_fund_personal;
```

**说明：** 移除后，档案表仅保留应发工资构成字段（basicSalary/performanceSalary/positionAllowance/otherAllowance），符合 v6/v7 设计规范。

### 3.2 `hr_social_security` 表处理

**策略：逻辑停用，不物理删除。**

```sql
-- 添加停用标记列
ALTER TABLE hr_social_security
  ADD COLUMN deprecated TINYINT NOT NULL DEFAULT 0 COMMENT '是否已停用 0否 1是';

-- 将所有记录标记为停用
UPDATE hr_social_security SET deprecated = 1 WHERE is_delete = 0;
```

**理由：** 历史数据可能已被引用，保留但不展示；后续运维清理时可物理删除。

### 3.3 `hr_social_calc_detail` 表索引补充

```sql
-- 补充 company_id 复合索引（当前缺少，影响分页查询性能）
ALTER TABLE hr_social_calc_detail
  ADD INDEX idx_company_month (company_id, salary_month, is_delete);
```

### 4.3 HrSocialCalcServiceImpl.generateMonthSalary() 实现要点

输入：salaryMonth（如2026-09）、companyId

完整流程：

1. 查询该月所有需核算的员工
   WHERE company_id = companyId AND employee_status IN (1,2)

2. 对每个员工：
   a. 读取当前生效薪资档案（isCurrent=1）
      → 取 basicSalary/performanceSalary/positionAllowance/otherAllowance
   b. 读取员工申报基数
      → 优先取 hr_employee.social_declare_base / housing_fund_declare_base
      → 兜底取 hr_employee.socialSecurityBase / basicSalary
   c. 查询该员工城市+当月对应的费率配置
      → hr_social_param_config WHERE city_code = 员工城市
        AND period_start <= 当月首日 AND (period_end IS NULL OR period_end >= 当月末日)
        AND is_active = 1
      → hr_housing_fund_config 同理
   d. clamp 基数到上下限
      socialBase = clamp(declareBase, config.baseMin, config.baseMax)
      housingFundBase = clamp(declareBase, config.baseMin, config.baseMax)
   e. 计算各险种分项金额（个人+单位）
   f. 计算个税
      grossAmount = basic + perf + allowance
      socialTotal = sum(各险种个人部分)
      housingFundTotal = housingFundPersonal
      taxableIncome = grossAmount - socialTotal - housingFundTotal - 5000
      taxAmount = 累计预扣法查表计算
      netAmount = grossAmount - socialTotal - housingFundTotal - taxAmount
   g. 写入 hr_social_calc_detail（含费率快照）
   h. 写入/更新 hr_salary_month（聚合值从 calc_detail 取）

3. 返回统计：总数/成功数/失败数

### 4.4 HrSalaryServiceImpl.generateMonth() 变更

原代码（第149-175行）：
```java
public void generateMonth(SalaryMonthDTO dto) {
    for (Long empId : dto.getEmployeeIds()) {
        // 逐个员工手工计算，直接读档案的社保字段
        HrSalaryMonth month = new HrSalaryMonth();
        month.setSocialSecurity(archive.getSocialSecurityPersonal());
        month.setHousingFund(archive.getHousingFundPersonal());
        salaryMonthMapper.insert(month);
    }
}
```

修改后：
```java
public void generateMonth(SalaryMonthDTO dto) {
    // 委托给核算服务统一计算，生成 hr_salary_month + hr_social_calc_detail
    socialCalcService.generateMonthSalary(dto.getSalaryMonth(), loginUser.getCompanyId());
}
```

## 七、关键风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 存量 archive 记录含旧社保字段值 | 移除字段后历史查询报错 | SQL DROP 前先备份，确认无外键引用 |
| 首次运行 generateMonthSalary() | 大量员工一次性核算耗时较长 | 分批执行，每批50人，加进度日志 |
| 月度表已有旧逻辑生成的数据 | 与新逻辑数据可能不一致 | 新逻辑追加新月份，旧月份保留只读 |
| social/security 手动台账历史数据 | 被废弃后无法查看 | 停用前导出备份，停用后仅保留查询 |
| 前端页面切换期间用户感知 | 页面突然变化 | 废弃页面保留7天过渡期，顶部置顶公告 |
