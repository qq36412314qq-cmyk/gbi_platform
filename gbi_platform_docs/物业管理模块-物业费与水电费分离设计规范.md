# 物业管理模块设计规范：物业费与水电费分离

## 文档描述

本规范对现有物业管理模块进行结构性拆分，将原有的混合账单管理（water_elec_bill 单表 + category 字段区分）拆分为**物业费管理**和**水电费管理**两个独立模块，分别对应不同的业务场景、生成逻辑和数据表。

> **核心拆分原则**：
> - 物业费：规则驱动，定额/按面积，无需抄表，按月批量生成，复用现有收费规则体系
> - 水电费：读数驱动，用量×单价，需抄表，按月批量生成
> - 两模块共享底层应收应付计划引擎和统一缴费入口，不重复建设

> **关键说明**：`biz_fee_item` 表通过 `fee_item_name`（字符串）区分收费类型（租金/物业费/水费/电费/押金/其他），无 `category_type` 数字字段；收费规则 `biz_fee_rule` 通过 `fee_item_id` 关联收费类型，`calc_mode`（1定额/2按面积）和 `period_type`（0不使用/1按年/2按月/3按日）驱动计费逻辑。

## 一、模块定位与拆分总览

### 1.1 现有架构问题

| 问题 | 说明 |
|------|------|
| 单表多态 | water_elec_bill 用 category 字段区分水/电/物业，业务逻辑耦合严重 |
| 生成逻辑混杂 | 一次生成循环内同时处理三种不同计费规则，难以独立演进 |
| 前端页面拥挤 | 物业页面需展示三类账单，筛选复杂，用户体验差 |
| 缴费入口混乱 | 缴费管理页需按 category 筛选才能定位对应账单 |

### 1.2 拆分后架构

```
物业管理模块
├── 水电费管理（water_elec_bill）
│   ├── 水电表管理（/property/meter）
│   ├── 水电费账单（/property/bill）← 标题改为"水电费管理"
│   └── 缴费管理（/property/pay）← 统一入口，billType 参数区分
├── 物业费管理（property_bill）
│   └── 物业费账单（/property/feeBill）← 新增
└── 合同/摊位/市场/租户（现有，不变）
```

> **统一缴费入口**：`/property/pay` 缴费管理页保持不变，通过 `billId` + `billType` 路由参数定位，不区分物业费/水电费账单来源。

## 二、数据表设计

### 2.1 底层收费规则体系（已有，不修改）

物业费计费完全复用现有收费规则体系：

| 表名 | 说明 |
|------|------|
| `biz_fee_item` | 收费类型表，`fee_item_name` 区分类型（租金/物业费/水费/电费/押金/其他） |
| `biz_fee_rule` | 收费规则表，关联 `fee_item_id`，定义 `calc_mode`（1定额/2按面积）、`price`（单价）、`period_type`（0不使用/1按年/2按月/3按日）、`overdue_rate` |
| `biz_fee_rule_stall_rel` | 规则-摊位绑定表，`uk_rule_stall` 保证同规则同一摊位只绑定一次；`override_flag` 预留单摊位覆盖 |

**关键约束**：
- 同一收费类型（`biz_fee_item`）在同一摊位只能绑定一条规则（`biz_fee_rule_stall_rel` 服务层校验）
- `biz_fee_item.fee_item_name = "物业费"` 对应物业费计费类型
- 规则启用状态 `status=1` 时才参与账单生成

### 2.2 物业费账单表 `property_bill`

```sql
DROP TABLE IF EXISTS `property_bill`;
CREATE TABLE `property_bill` (
  `id` bigint unsigned NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `company_id` bigint NOT NULL DEFAULT 0 COMMENT '所属子公司ID',
  `stall_id` bigint NOT NULL COMMENT '摊位ID',
  `merchant_id` bigint NOT NULL DEFAULT 0 COMMENT '商户ID',
  `bill_month` varchar(32) NOT NULL COMMENT '账单月份 yyyy-MM',
  `rule_id` bigint NOT NULL DEFAULT 0 COMMENT '计费规则ID（biz_fee_rule，快照）',
  `fee_item_id` bigint NOT NULL DEFAULT 0 COMMENT '收费类型ID（biz_fee_item，固定=物业费）',
  `calc_mode` tinyint NOT NULL DEFAULT 1 COMMENT '收费方式 1定额 2按面积',
  `period_type` tinyint NOT NULL DEFAULT 2 COMMENT '收费周期 0不使用 1按年 2按月 3按日',
  `usage` decimal(12,2) NOT NULL DEFAULT 0.00 COMMENT '用量：定额=0，按面积=摊位面积（快照）',
  `unit_price` decimal(12,2) NOT NULL DEFAULT 0.00 COMMENT '计费单价快照（规则修改不回溯）',
  `period_factor` decimal(10,4) NOT NULL DEFAULT 1.0000 COMMENT '周期系数（按年/12、按日×当月天数、按月=1）',
  `amount` decimal(12,2) NOT NULL DEFAULT 0.00 COMMENT '本条账单金额',
  `pay_status` tinyint NOT NULL DEFAULT 0 COMMENT '缴费状态 0待缴 1已缴 2部分缴费',
  `pay_time` datetime DEFAULT NULL COMMENT '缴费完成时间',
  `plan_id` bigint DEFAULT NULL COMMENT '关联应收应付计划ID',
  `create_by` bigint NOT NULL DEFAULT 0 COMMENT '创建人用户ID',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by` bigint DEFAULT NULL COMMENT '更新人用户ID',
  `update_time` datetime NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `is_delete` tinyint NOT NULL DEFAULT 0 COMMENT '逻辑删除 0正常 1删除',
  PRIMARY KEY (`id`),
  INDEX `idx_company_id_is_delete` (`company_id`,`is_delete`),
  INDEX `idx_stall_id` (`stall_id`),
  INDEX `idx_bill_month` (`bill_month`),
  UNIQUE KEY `uk_stall_month` (`company_id`,`stall_id`,`bill_month`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='物业费月度账单表';
```

**字段设计说明：**

| 字段 | 说明 |
|------|------|
| `rule_id` | 快照绑定规则，规则修改不影响已生成账单 |
| `fee_item_id` | 固定指向 `biz_fee_item` 中 `fee_item_name="物业费"` 的记录 |
| `calc_mode` | 从规则快照，1=定额（固定月费），2=按面积（单价×面积） |
| `period_type` | 从规则快照，0=不使用周期，1=按年，2=按月，3=按日 |
| `usage` | 定额时=0，按面积时=摊位面积（快照，规则修改不回溯） |
| `period_factor` | 周期折算系数：按年=1/12，按日=当月天数，按月=1，不使用=1 |
| `amount` | 最终金额：定额=price×period_factor，按面积=price×stallArea×period_factor |
| `uk_stall_month` | 同公司同摊位同月份只能有一条物业费账单（幂等键） |

### 2.3 水电费账单表（现有 `water_elec_bill`，调整用途）

| 字段 | 说明 |
|------|------|
| `category=3` | 水费：usage=读数差，unit_price=水费规则单价 |
| `category=4` | 电费：usage=读数差，unit_price=电费规则单价 |
| `category=2` | 物业费（历史数据，迁移后不再使用，新账单写入 property_bill） |

> **迁移说明**：`water_elec_bill` 中已有 `category=2` 的历史物业费账单，新模块上线后需通过数据迁移脚本将历史数据导入 `property_bill`，原表中 `category=2` 的记录停止生成。

### 2.4 两表与共享能力关系

| 能力 | 物业费 (property_bill) | 水电费 (water_elec_bill) |
|------|----------------------|-------------------------|
| 账单生成 | 规则驱动，按月批量 | 读数驱动，按月批量 |
| 缴费入口 | `/property/pay` | `/property/pay` |
| 应收计划 | `biz_recv_pay_plan` (`biz_type=property`) | `biz_recv_pay_plan` (`biz_type=water_elec`) |
| 账单-计划关联 | `bill_plan_rel` (`bill_type=property_fee`) | `bill_plan_rel` (`bill_type=water_elec`) |
| 缴费记录 | `water_elec_pay_record`（共用） | `water_elec_pay_record`（共用） |
| 财务流水 | `biz_finance_flow` (`business_type=property_fee`) | `biz_finance_flow` (`business_type=water_elec`) |

### 3.5 批量生成逻辑

**入口**：「批量生成」按钮 → 弹窗

**弹窗内容：**
```
[账单月份 picker (必填)]
[所属市场 select (可选，null=全部市场)]
提示：将自动为已绑定物业费规则的摊位生成账单，已存在的账单跳过
```

**后端逻辑（`PropertyFeeBillServiceImpl.generateBatch()`）：**
```
1. 获取目标摊位列表（按 marketId 过滤，null 则取全部摊位）
2. 批量加载摊位绑定收费规则（FeeRuleStallRelService.listByStallIds）
3. 遍历每个摊位：
   a. 查找 categoryType=2（物业费）的规则
   b. 幂等检查：同公司同摊位同月份已存在则跳过
   c. 计算金额：定额=price×periodFactor，按面积=price×area×periodFactor
   d. 插入 property_bill 记录
   e. 调用 recvPayPlanService.generatePlanForPropertyBill() 创建应收计划
   f. 插入 bill_plan_rel 关联记录
4. 返回生成数量
```

**API 定义：**
```typescript
// propertyFee.ts
export interface PropertyFeeBillGenerateDTO {
  billMonth: string        // 账单月份 yyyy-MM（必填）
  marketId?: number        // 市场ID（可选，null=全部）
}

// 后端
@PostMapping("/generate")
public Result<Integer> generateBatch(@Valid @RequestBody PropertyFeeBillGenerateDTO dto)
```

### 3.6 单条生成逻辑

**入口**：列表行操作 → 「单条生成」按钮

**弹窗内容：**
```
[账单月份 picker (必填)]
[摊位 select filterable (必填)]
预估金额预览区（生成后展示计费详情）
```

**后端逻辑（`PropertyFeeBillServiceImpl.generateSingle()`）：**
```
1. 校验 stallId 不为 null
2. 查询该摊位的物业费规则（categoryType=2）
3. 幂等检查：已存在则返回已有 billId
4. 计算金额（同批量生成）
5. 插入 property_bill + 关联应收计划 + 关联记录
6. 返回新账单 ID（或已有账单 ID）
```

**API 定义：**
```typescript
// propertyFee.ts
export interface PropertyFeeBillGenerateSingleDTO {
  billMonth: string
  stallId: number          // 单条生成必填
}

// 后端
@PostMapping("/generateSingle")
public Result<Long> generateSingle(@Valid @RequestBody PropertyFeeBillGenerateSingleDTO dto)
```

### 3.7 收费规则联动规则

| 场景 | 行为 |
|------|------|
| 规则启用→停用 | 已生成账单不受影响（快照单价已固化） |
| 规则价格修改 | 已生成账单不受影响 |
| 规则绑定到摊位 | 下月生成时自动生效 |
| 规则从摊位解绑 | 下月生成时该摊位跳过（无规则=不生成） |
| 收费类型重命名 | 已有账单不受影响（快照 fee_item_id） |

## 六、应收应付计划对接

### 6.1 计划类型

| 账单类型 | biz_recv_pay_plan.biz_type | bill_plan_rel.bill_type |
|----------|--------------------------|------------------------|
| 物业费 | `property`（已有常量 PLAN_BIZ_PROPERTY） | `property_fee`（新增） |
| 水电费 | `water_elec`（已有常量 PLAN_BIZ_WATER_ELEC） | `water_elec`（现有） |

### 6.2 generatePlanForPropertyBill 逻辑

```
1. 幂等检查：同公司同账单ID同期次已存在则返回已有 planId
2. 查询摊位有效合同，获取 tenantId/merchantId
3. 创建 BizRecvPayPlan：
   - bizType = PLAN_BIZ_PROPERTY ("property")
   - sourceType = PLAN_SOURCE_BILL ("bill")
   - sourceId = String.valueOf(bill.getId())
   - periodNo = bill.getBillMonth()
   - planAmount = bill.getAmount()
   - planStatus = PLAN_STATUS_PENDING
4. 插入计划，返回 planId
5. 调用方负责插入 bill_plan_rel 关联记录（bill_type = BIZ_TYPE_PROPERTY_FEE）
```

### 6.3 缴费核销

物业费账单缴费复用现有 `WaterElecPayServiceImpl`，缴费记录写入 `water_elec_pay_record`，财务流水写入 `biz_finance_flow`（`business_type="property_fee"`），核销调用 `recvPayPlanService.writeOff()` 传入对应的 property 计划 ID。

## 十、注意事项

1. **历史数据兼容**：`water_elec_bill` 中 `category=2`（物业费）的历史数据，上线后需通过迁移脚本导入 `property_bill`，原表中 `category=2` 的记录停止生成。
2. **缴费入口统一**：两模块共用 `/property/pay` 缴费页，通过 `billId` + `billType` 路由参数定位，不区分账单来源。
3. **收费规则快照**：`property_bill` 生成时固化 `rule_id`/`calc_mode`/`period_type`/`unit_price`，规则后续修改不影响已生成账单。
4. **审计日志**：物业费生成记录审计日志，模块标识 `MODULE_PROPERTY_FEE = "propertyFee"`，操作类型 `OPER_TYPE_ADD`。
5. **多租户隔离**：所有查询自动附加 `company_id` 条件（MyBatis-Plus 多租户拦截器），跨公司账单不可操作。
6. **幂等保证**：`property_bill.uk_stall_month` 唯一索引保证同摊位同月份不重复生成。
7. **water_elec_pay_record 复用**：物业费和水电费共用缴费记录表，通过 `billId` 关联对应账单表。
8. **biz_finance_flow.business_type**：物业费缴费流水 `business_type="property_fee"`，水电费 `business_type="water_elec"`，便于财务分账统计。
9. **文件编码**：所有新增 Java 文件使用 UTF-8 无 BOM 编码，避免编译时 `\ufeff` 错误。
10. **字符串换行**：Java 源码中禁止使用反引号（`` ` ``）作为换行符，必须使用真正的 `\n` 转义字符。
