# 后端编码规范

## 文档描述

本规范基于项目 SpringBoot3 + MyBatis-Plus 技术栈制定，统一 Java 后端全流程编码标准，包含包分层、命名、注释、分层业务写法、事务、定时任务、异常、工具、参数校验、权限、多租户隔离、第三方对接、财务资金专项约束、安全编码、日志审计等内容。单人独立开发统一代码风格，减少后期迭代维护成本，所有业务、中台、第三方对接代码必须严格遵循本规范，同时对齐《集团多业态一体化管控系统》整体业务方案、数据库规范、API & 日志规范、权限多租户规范。

## 一、整体分层与工程包规范

### 1.1 固定项目目录（不可修改包根路径）

根包统一：`com.gbi.platform`

### 1.2 分层职责强制约束

1. **controller**：只做三件事 —— 接收 DTO 参数、调用 service 方法、返回统一 Result；禁止写 SQL、循环、事务、业务判断、文件处理；

2. **service（接口）**：仅定义抽象方法，无任何业务实现代码；

3. **service.impl**：所有多表、资金、调拨、审批、复杂业务、事务逻辑全部在此；禁止在 controller、mapper 写业务；

4. **mapper**：仅做数据 CRUD，禁止业务逻辑；复杂多表 SQL 写 mapper.xml；

5. **entity**：严格映射数据库字段，所有业务实体必须包含`company_id`、create_by、create_time、update_by、update_time、is_delete；

6. **dto**：接收前端新增 / 编辑 / 查询参数，添加校验注解；

7. **vo**：数据查询封装，脱敏敏感字段，禁止直接返回 entity 给前端；

8. **common**：全局通用能力，全模块复用，禁止业务重复实现；

9. **util**：支付、钉钉、金蝶、OSS、水表等第三方工具，静态方法，无业务状态。

### 1.3 分包规则

1. controller、service、mapper 按业务模块分包：`base`、`finance`、`flow`、`lease`（property.lease 子包）、`oa`、`org`、`property`、`property.lease`、`sys`、`waterElec`、`hr`；

2. 新增模块独立新建分包，不与原有模块混杂；

3. 第三方对接统一放入 util 独立工具类，不耦合业务 service。

## 二、统一命名规范（强制）

### 2.1 包名

全小写，多单词横线分隔：stall-map、market-map

### 2.2 类命名

1. controller：`StallController`大驼峰，后缀统一 Controller；

2. service 接口：`StallService`；

3. 实现类：`StallServiceImpl`；

4. mapper：`StallMapper`；

5. entity：大驼峰，财务类加 Biz 前缀（如`BizFeeBill`、`BizFinanceFlow`（table:finance_pay_flow）、`BizRecvPayPlan`（table:finance_recv_pay_plan）、`BizDiscountPolicy`、`BizDiscountApply`、`BizPayOrder`、`BizFinanceWriteoff`），物业类加 Property 前缀（如`PropertyFeeBill`（table:property_fee_bill）、`PropertyStallInfo`（table:property_stall_info）），水电类加 WaterElec 前缀（如`WaterElecBill`（table:property_water_elec_bill）），HR 类加 Hr 前缀（如`HrEmployee`（table:hr_employee）、`HrAttendanceRecord`（table:hr_attendance_record）），租赁类加 Stall 前缀（如`StallInfo`、`StallContract`）；

6. DTO：`StallAddDTO`/`StallQueryDTO`；

7. VO：`StallListVO`；

8. 工具类：`OssUtil`、`KingdeeUtil`；

9. 配置类：`SecurityConfig`、`MyBatisPlusConfig`。

### 2.3 方法命名

1. 查询：getXXX、listXXX、pageXXX；

2. 新增：addXXX、saveXXX；

3. 修改：updateXXX；

4. 删除：deleteXXX（逻辑删除）；

5. 批量：batchXXX；

6. 导出：exportXXX；

7. 统计：summaryXXX；

8. 业务操作：submitXXX、auditXXX、refundXXX。

### 2.4 变量、参数

小驼峰：stallId、marketPointJson；
常量：全大写下划线 `STATUS_RENTED`，统一放在 common.constant 包，禁止硬编码字符串。

### 2.5 数据库相关命名对齐

entity 字段与数据库字段完全匹配，使用`@TableField("company_id")`映射；
表、字段命名遵循数据库规范：小写下划线。

## 三、注释规范

1. **类注释**：所有 controller、service、mapper、entity、工具类顶部添加 JavaDoc，说明模块用途；

2. **方法注释**：public 接口必须注释入参、返回、业务含义；私有简单方法可省略；

3. **参数注释**：DTO 中每个字段添加`@Schema`说明用途；

4. **关键业务代码**：资金、调拨、审批、权限二级审核等高风险逻辑添加行内注释；

5. **禁止无意义冗长注释**：注释应简洁明了，说明业务意图而非重复代码。

## 四、Controller 层编码规范

1. 所有接口添加权限注解 `@PreAuthorize("hasPermission('xxx:xxx')")`，无权限接口拦截；

2. 禁止直接返回 entity，必须封装 VO 脱敏手机号、身份证、密钥；

3. 入参统一使用 DTO 接收，不直接使用 entity、零散参数；

4. 自动参数校验：DTO 添加`@NotNull/@NotBlank/@Pattern`，非法参数全局异常统一返回；

5. 所有接口统一 try-catch 由全局异常处理器处理，controller 不单独捕获异常；

6. 文件上传接口统一复用 OssUtil，单独处理二进制流。

## 五、Service 业务层编码规范

### 5.1 接口与实现分离

禁止 A 模块直接调用 B 模块 mapper；跨业务只能调用对方 service 接口。

### 5.2 事务管理

1. 涉及多表写入、资金操作的方法必须添加`@Transactional(rollbackFor = Exception.class)`；

2. 禁止在 controller 层编写事务逻辑；

3. 事务内禁止调用外部 HTTP 接口（第三方调用应在事务外）。

### 5.3 审计日志强制要求

1. 所有新增、编辑、删除、审批操作必须记录审计日志；

2. 使用 AuditLogUtil 统一封装，禁止重复写入库逻辑；

3. 财务操作、地图操作、权限变更必须记录操作前后 JSON 快照。

## 六、Mapper & MyBatis-Plus 持久层规范

1. 所有 mapper 继承`BaseMapper<T>`，单表增删改查直接使用内置方法，禁止重复写简单 SQL；

2. 多表联查、统计、复杂报表 SQL 统一放入 resources/mapper/*.xml；

3. 开启全局逻辑删除，字段 is_delete=1 代表删除，财务、合同、审计数据禁止物理删除；

4. 禁止 LambdaQueryWrapper 忽略 company_id 查询，自动填充公司隔离条件。

## 七、DTO / VO 数据传输规范

1. DTO 必须添加校验注解，禁止空值传入业务逻辑；

2. VO 禁止直接返回 entity，必须转换并脱敏敏感字段；

3. 日期类型统一使用 LocalDateTime，禁止使用 Date；

4. 金额类型统一使用 BigDecimal，禁止使用 float/double。

## 八、异常处理规范

1. 自定义业务异常`BizException`用于业务校验不通过场景；

2. 全局异常处理器统一捕获，返回标准错误码；

3. 第三方调用统一捕获异常，封装 BizException 抛出上层。

## 九、常量与字典编码规范

1. 所有业务状态码、类型码统一放在 common.constant 包；

2. 禁止在业务代码中硬编码状态值；

3. 字典数据通过 SysDictData 表统一管理，禁止硬编码字典值。

## 十、定时任务规范

1. 所有定时任务统一注册在 config.TaskConfig；

2. 使用`@Scheduled`，cron 表达式统一配置 yml，禁止写死代码；

3. 定时任务业务逻辑放入 service，不在 config 写业务；

4. 增加分布式锁（Redis）防止多实例重复执行；

5. 典型定时任务：月度账单生成、到期铺位预警、同步钉钉考勤、清理过期临时文件。

## 十一、多租户 company_id 强制编码规则

1. 所有业务 entity 必须包含 company_id，全局公共表（字典、角色模板）除外；

2. 新增单据自动从登录上下文获取当前用户 company_id 赋值，前端不传递；

3. 所有列表查询自动过滤 company_id，不允许前端传参覆盖数据隔离条件；

4. 跨分公司调拨、集团汇总报表手动关闭自动过滤，代码注释说明用途。

## 十二、权限二级审核专项编码规范

1. 敏感权限变更不即时生效，存入中间审核表；

2. 复用统一轻量表驱动审批引擎（flow_definition/flow_instance/flow_task/flow_record）发起审核待办；（与《应收应付计划+统一审批引擎+优惠管理模块设计规范》保持一致）

3. 仅复核通过后才更新角色权限数据；

4. 权限变更前后数据存入审计日志，记录操作人、复核人、IP、时间。

## 十三、财务资金专项强制编码规则

1. 所有租金、物业费、押金、营销减免收支必须写入 finance_fee_pay_bill 全局账单表（统一聚合表），资金流水写入 finance_pay_flow 全局流水表；

2. 一笔业务多条收支统一事务，要么全部入库要么全部回滚；

3. 优惠核销自动计算原价 - 优惠 = 实收，流水标记营销抵扣类型；

4. 支付回调、退款接口实现幂等，通过业务单号防重复入账；

5. 财务流水禁止逻辑删除，只允许查询导出，无删除、修改接口。

## 十四、第三方对接编码规范（钉钉 / 金蝶 / OSS / 地图）

1. 密钥、接口地址全部配置 application-dev/application-prod，禁止硬编码；

2. 鉴权 token 统一缓存 Redis，定时刷新，避免重复请求第三方授权接口；

3. 入参、出参统一 DTO 封装，统一字段映射；

4. 调用日志存入数据库审计表，便于对账排查；

5. 金蝶凭证推送失败自动重试，失败记录待人工处理；

6. 钉钉考勤双向同步：后端定时拉取打卡数据，审批完成同步休假状态。

## 十五、操作审计日志编码规范

1. 需记录操作：登录退出、新增 / 编辑 / 删除单据、权限变更、财务操作、批量导出、第三方同步；

2. 日志字段：操作人 userId、companyId、操作 IP、操作模块、操作类型、变更前 JSON、变更后 JSON、操作时间；

3. 日志永久存储，不做清理，支持后台分页导出。

## 十六、安全编码强制约束

1. 禁止拼接 SQL，参数化查询防注入；

2. 所有入参过滤 HTML、JS 脚本字符，防 XSS；

3. 接口限流：高频查询、导出接口 Redis 限流；

4. 防重复提交：缴费、调拨、合同提交携带 requestId 校验；

5. 文件上传校验后缀，禁止 exe/html/js；

6. 密码、商户证件敏感字段数据库加密存储；

7. 生产环境关闭 SQL 打印，禁止暴露数据库信息；

8. 禁止接口直接返回完整手机号、身份证，VO 统一脱敏。

## 十七、环境与部署编码规范

1. 区分 dev/prod 两套 yml 配置；

2. dev 开启 SQL 日志、热更新、简化日志；

3. prod 关闭调试日志，密钥加密，定时任务正常运行；

4. 打包 Maven 过滤 dev 配置，只保留生产配置；

5. 不将测试接口、测试打印语句提交代码仓库。

## 十八、开发红线（禁止操作）

1. 禁止跨层直接调用 mapper（controller、util 直接操作数据库）；

2. 禁止业务代码硬编码常量、地址、密钥；

3. 禁止业务实体缺少 company_id；

4. 禁止财务、审计数据物理删除；

5. 禁止第三方对接逻辑散落 controller，必须封装 util；

6. 禁止高风险敏感权限单人直接生效；

7. 禁止拼接 SQL、HTML 脚本传入数据库；

8. 禁止 controller 写入事务、循环、复杂业务逻辑；

9. 禁止直接返回 entity 实体给前端，脱敏缺失；

10. 禁止前端传入 company_id 直接作为查询条件。
