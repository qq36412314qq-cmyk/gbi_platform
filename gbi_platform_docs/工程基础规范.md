# 工程基础规范

## 文档描述

本规范为项目整体工程统一标准，覆盖前后端项目目录分层、多环境配置管理、打包发布回滚流程、统一中台公共能力约束四大核心内容。统一单人独立开发下工程组织方式，消除目录混乱、环境配置不一致、公共逻辑重复开发问题，所有业务模块、中台能力、第三方集成均需遵循本规范，作为后端编码、数据库、前后端开发等所有细分规范前置通用准则。

## 一、整体工程架构统一标准

### 1\.1 分层架构定义

系统采用四层标准化分层架构，前后端完全分离，所有开发工作严格分层执行，禁止跨层直接调用逻辑

1. 前端交互层：Vue3 PC 管理后台 \+ 微信商户小程序，纯视图交互，无业务计算逻辑

2. 应用服务层：Java SpringBoot3 后端服务，承载所有业务、中台、第三方对接逻辑

3. 数据持久层：MySQL8\.0 主库 \+ Redis 缓存，统一多租户数据隔离存储

4. 第三方外部服务层：智能水电网关、支付、OSS 文件、钉钉、金蝶等外部对接能力

### 1\.2 中台化强制原则

组织、权限、流程引擎、消息中心、审计日志、字典参数、文件存储统一抽离为公共中台能力，全业务模块（租赁 / 水电 / 物资 / OA / 营销 / 铺位地图）复用，禁止各业务单独实现同类公共逻辑。

### 1\.3 多租户底层标准

一套数据库支撑集团 \+ 多子公司，所有业务表统一携带`company_id`字段做逻辑隔离，不采用分库分表方案，架构预留幼儿园、建筑、园林等业态扩展，新增业态仅新增业务代码，不动底层中台与数据隔离逻辑。

### 1\.4 前后端分离约束

后端仅输出标准 JSON 接口，不渲染页面；前端仅处理视图展示、交互请求，禁止前端写业务计算、数据过滤核心逻辑，数据权限、事务、校验全部由后端兜底。

## 二、后端 SpringBoot 工程目录规范

### 2\.1 项目根目录结构（固定不可修改）

```Plain Text
gbi_platform_server
├─ pom.xml           # Maven全局依赖管理，统一锁定所有第三方版本
└─ src/main
    ├─ java/com/gbi/platform  # 根包名固定，不允许自定义修改
    │  ├─ GbiPlatformApplication.java  # 唯一程序启动入口
    │  ├─ config                 # 全局配置类集合
    │  ├─ controller             # 接口控制层，按模块分包
    │  ├─ service / service.impl # 业务接口+业务实现分层
    │  ├─ mapper                 # MyBatis-Plus持久层
    │  ├─ entity                 # 数据库实体，一一对应数据表
    │  ├─ dto                    # 前端入参接收对象
    │  ├─ vo                     # 后端返回前端封装对象
    │  ├─ common                 # 全局公共底层（返回体、异常、常量、鉴权）
    │  └─ util                   # 通用工具类，第三方统一封装
    └─ resources
        ├─ application.yml        # 公共基础配置
        ├─ application-dev.yml    # 开发环境
        ├─ application-prod.yml   # 生产环境
        ├─ mapper                 # 复杂SQL xml文件
        └─ static                 # 静态资源（前后端分离基本空置）
```

### 2\.2 各包统一职责约束

1. config：存放 JWT 鉴权、MyBatis-Plus、Redis、定时任务、流程引擎、跨域等 Bean 配置，所有全局拦截器统一在此定义；

2. controller：只做参数接收、权限校验、调用 service、返回结果，禁止写 SQL、业务判断、事务；按业务分包：org、stall、marketMap、waterElec、material、oa、marketing、finance；

3. service：接口层仅定义方法，impl 实现层编写完整业务逻辑，所有多表、资金操作加事务；

4. entity：每张表对应一个实体，业务实体必须包含 company\_id、创建人、创建时间、更新人、更新时间、逻辑删除字段；

5. dto：新增 / 编辑 / 查询入参，增加 @NotBlank、@NotNull 参数校验注解；

6. vo：查询返回封装，敏感字段统一脱敏，禁止直接返回 entity 给前端；

7. common：统一返回 Result、全局异常处理器、权限常量、数据权限拦截工具；

8. util：OSS、支付、钉钉、金蝶、水电表、日期等独立工具类，第三方对接全部封装此处，不散落业务代码。

### 2\.3 模块分包规则

新增业务（营销、铺位地图、人事考勤）必须独立新建 controller、service 包，禁止和原有租赁等模块混合；第三方对接逻辑统一放入 util 独立工具，不耦合业务代码。

## 三、前端 Vue3 PC \+ 小程序工程目录规范

### 3\.1 PC 管理端前端目录（固定标准）

```Plain Text
gbi_platform_admin
├─ public            静态图片、全局图标
├─ src
│  ├─ api             接口文件，后端controller一一对应（新增marketMap.ts地图接口）
│  ├─ assets/style    全局CSS主题变量，禁止硬编码色值
│  ├─ components      通用组件+业务组件（新增MarketCanvas画布组件）
│  ├─ hooks            复用组合逻辑
│  ├─ layout           系统侧边、顶部布局
│  ├─ router           路由，与后台菜单权限一一对应
│  ├─ store/theme      全局主题状态管理
│  ├─ views            页面，分platform/ business/oa/finance四大目录
│  └─ utils/fabricUtil  铺位画布Fabric工具类
└─ main.ts
```

### 3\.2 商户小程序目录约束（gbi_platform_miniapp）

1. 仅实现缴费、账单、活动、铺位静态查看功能，无后台编辑操作；

2. 复用 Vant Weapp，不引入复杂画布组件，仅展示静态图片；

3. 配色同步后台自定义主题主色，共用一套配色变量规则。

### 3\.3 前端文件命名强制规范

1. 目录全小写，横线分隔；页面小驼峰、组件大驼峰、API 文件小驼峰；

2. 路由 name 与页面文件名保持一致，meta 必须携带 title、icon、permission 权限标识；

3. 全局组件统一在 main\.ts 注册，页面无需重复引入。

## 四、多环境配置统一规范

### 4\.1 环境划分

开发环境 \(dev\)、生产环境 \(prod\)，禁止新增测试、预发等多余环境，简化单人开发维护成本。

### 4\.2 配置区分规则

1. application\.yml：存放通用不变配置（文件路径、线程池、全局开关）；

2. dev：开启 SQL 打印、热更新、简化日志、关闭密钥加密；

3. prod：关闭 SQL 日志、数据库密码加密、开启定时任务、启用 HTTPS、限流防护；

### 4\.3 敏感配置约束

数据库密码、OSS 密钥、支付密钥、钉钉 / 金蝶对接密钥统一放环境配置文件，禁止硬编码在 Java/JS 代码，禁止提交至代码仓库。

### 4\.4 前端环境区分

前端通过\.env\.development、\.env\.production 区分接口域名，生产环境全部使用 HTTPS 请求。

## 五、项目打包、部署、备份与回滚规范

### 5\.1 后端打包流程

1. Maven 执行 package，输出单一可执行 jar 包；

2. 打包前自动过滤 dev 环境配置，仅保留 prod 配置；

3. 启动命令统一：java \-jar xxx\.jar \-\-spring\.profiles\.active=prod

### 5\.2 前端打包流程

1. npm run build 生成 dist 静态资源；

2. Nginx 反向代理托管静态文件，区分后台 / 小程序接口路由；

### 5\.3 部署规范

1. 服务使用独立 Linux 进程运行，配置 JVM 基础内存参数；

2. Nginx 统一处理跨域、SSL 证书、静态资源缓存；

3. 数据库每日定时全量备份，备份文件留存 7 天；

### 5\.4 故障回滚标准

1. 版本迭代保留上一版 jar/dist 包，出现 bug 直接替换文件重启回滚；

2. 数据库回滚：优先使用当日备份文件恢复，生产环境禁止手动删改业务数据；

3. 回滚后核对财务流水、铺位合同、营销优惠等核心数据完整性。

## 六、统一中台公共工程能力规范（全工程复用约束）

所有业务模块（租赁、水电、物资、营销、铺位地图、OA 人事）必须复用以下中台能力，禁止重复开发：

1. 组织与 RBAC 权限中台：菜单权限、数据 company\_id 过滤、二级敏感权限审核；

2. 统一 Flowable 流程引擎：合同、采购、营销活动、请假等所有审批共用一套流程配置；

3. 全局消息中心：站内信、小程序通知、待办统一推送；

4. OSS 文件存储：铺位底图、合同、巡检、附件全部统一上传存储；

5. 全局字典、参数配置：费用、状态、铺位类型等统一读取；

6. 审计日志中台：地图编辑、权限变更、财务操作、删除动作自动记录日志；

7. UI 主题配置中台：集团 / 子公司自定义配色全局统一存储渲染。

## 七、第三方集成工程统一约束

钉钉考勤、金蝶财务、Fabric 铺位画布、物联网水电、支付全部遵循统一工程规范：

1. 后端：独立 util 工具类封装，统一异常重试、幂等处理；

2. 前端：独立 api 文件、独立业务组件，不侵入原有页面代码；

3. 配置全部写入环境 yml，接口地址、密钥可动态修改；

4. 所有第三方操作写入审计日志，可追溯调用记录；

5. 对接费用、额度配置统一在工程说明文档备注，便于后期扩容评估。

## 八、工程迭代与扩展规范

1. 新增业态（幼儿园 / 建筑）：仅在前后端新增对应 controller、views 页面，中台、数据隔离逻辑完全复用，不修改底层工程结构；

2. 新增功能模块（营销、人事、铺位地图）：遵循原有目录分层，不打乱原有工程分包；

3. 迭代顺序固定：一期汽车城基础业务 → 二期 OA、营销、人事 → 三期财务金蝶对接、多业态拓展；

4. 所有新增代码必须遵循后端编码、数据库、前端开发等细分规范，保持工程风格统一。

## 九、工程开发红线（禁止行为）

1. 禁止随意修改根包名、目录分层结构；

2. 禁止业务代码硬编码密钥、地址、固定色值、固定 ID；

3. 禁止业务模块自建文件存储、自建审批流程、独立权限体系；

4. 禁止开发环境与生产环境配置混用；

5. 禁止前后端分离项目在 Java 内写页面模板；

6. 禁止新增业务绕过 company\_id 数据隔离规则；

7. 禁止第三方对接逻辑散落页面 / 业务方法，必须统一封装工具类。
