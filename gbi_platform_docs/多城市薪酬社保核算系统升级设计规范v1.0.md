## 一、背景与升级目标

### 1.1 现状问题

| 问题 | 说明 |
|------|------|
| 单城市单费率 | 现有 `hr_salary_rule.social_security_rate` 为固定百分比，不支持按城市、行业差异化配置 |
| 无基数上下限 | 社保、公积金无缴费基数上下限控制，不符合各地政策差异 |
| 无年度重算机制 | 员工基数无年度重算逻辑，无法按"上年月均工资"自动调整 |
| 险种不细分 | 养老/医疗/失业/工伤/生育及长护险无独立费率配置 |
| 历史不可回溯 | 每次修改费率直接覆盖，无历史费率存档，无法回溯核算 |
| 个税计算缺失 | 当前月度薪资未实现个税计算，不符合合规要求 |
| 社保台账与算薪脱节 | `hr_social_security` 台账为手工维护，不与薪资核算联动 |

### 1.2 升级目标

1. **城市维度**：支持集团下属多个城市子公司，各城市社保公积金政策独立配置
2. **险种维度**：法定五险 + 长护险试点 + 补充福利分离管理
3. **基数规则**：新入职临时基数 + 年度重算自动调整 + 上下限截断
4. **费率历史**：每次费率变更生成历史快照，支持按时间回溯
5. **个税计算**：统一全国个税公式，应发工资 - 社保公积金 - 5000起征点 = 应纳税所得额
6. **明细台账**：每月生成薪酬明细记录，留存分项扣款和单位缴纳金额


### 5.2 计算逻辑

```
应发工资 = basic_salary + performance_salary + position_allowance + other_allowance + bonus
社保个人合计 = pension_personal + medical_personal + unemployment_personal + long_care_personal
公积金个人 = housing_fund_personal
应纳税所得额 = 应发工资 - 社保个人合计 - 公积金个人 - 5000 - 专项附加扣除
个人所得税 = 应纳税所得额 × 适用税率 - 速算扣除数（按国税累计预扣法）
实发工资 = 应发工资 - 社保个人合计 - 公积金个人 - 个人所得税
```

## 七、年度基数重算流程

### 7.1 重算触发时机

- **手动触发**：HR在每年6月15日-30日期间手动执行
- **定时任务**：每年7月1日0点自动执行（需开启分布式锁）

### 7.2 重算逻辑

```
FOR EACH 员工 WHERE city_code IS NOT NULL:
  1. 查询上年1-12月全部税前收入（基本工资+奖金+津贴）
  2. 计算月均 = 总收入 / 实际发薪月份数
  3. 截断：base = clamp(月均, 城市下限, 城市上限)
  4. 更新 hr_employee.social_declare_base = base
  5. 更新 hr_employee.housing_fund_declare_base = base（公积金同理）
  6. 更新 hr_employee.base_effective_year = 当年年度
  7. 记录审计日志
```

### 7.3 幂等性保证

以 `employee_id + base_effective_year` 作为幂等键，已处理过的员工不重复处理。

## 八、核算规则

### 8.1 社保计算规则

```
社保实际缴费基数 = clamp(员工申报基数, 城市下限, 城市上限)
养老个人 = 社保实际缴费基数 × 养老个人比例
养老单位 = 社保实际缴费基数 × 养老单位比例
医疗个人 = 社保实际缴费基数 × 医疗个人比例
医疗单位 = 社保实际缴费基数 × 医疗单位比例
失业个人 = 社保实际缴费基数 × 失业个人比例
失业单位 = 社保实际缴费基数 × 失业单位比例
工伤单位 = 社保实际缴费基数 × 工伤行业费率
生育单位 = 社保实际缴费基数 × 生育单位比例
长护险个人 = 社保实际缴费基数 × 长护险个人比例（仅试点城市）
长护险单位 = 社保实际缴费基数 × 长护险单位比例（仅试点城市）
```

### 8.2 公积金计算规则

```
公积金实际缴费基数 = clamp(员工申报基数, 城市下限, 城市上限)
公积金个人 = 公积金实际缴费基数 × 公积金个人比例
公积金单位 = 公积金实际缴费基数 × 公积金单位比例
```

### 8.3 个税计算规则（全国统一）

```
应纳税所得额 = 应发工资 - 社保个人合计 - 公积金个人 - 5000 - 专项附加扣除
适用税率 = 按国税累计预扣法查表
个人所得税 = 应纳税所得额 × 税率 - 速算扣除数
```

> 专项附加扣除从 `sys_config` 读取默认值，或从员工档案扩展字段读取

### 8.4 模板比例与全局参数优先级

```
if (模板.social_security_rate IS NOT NULL) {
  使用模板比例
} else {
  从 hr_social_param_config 查询当前城市+对应险种+当前时期的比例求和
}
```

## 十、审计日志设计

> 本模块所有关键操作统一复用系统现有 `AuditLogUtil.record()` 机制，遵循《后端编码规范》第十五章要求。审计日志**永久存储，禁止删除**。

### 10.1 审计模块与操作类型常量

在 `CommonConst.java` 中新增以下常量：

```java
// 新增模块标识
public static final String MODULE_HR_SOCIAL_PARAM = "hr_social_param";   // 社保公积金参数配置
public static final String MODULE_HR_SOCIAL_CALC = "hr_social_calc";     // 社保公积金核算

// 新增操作类型
public static final String OPER_TYPE_PARAM_ADD = "参数新增";
public static final String OPER_TYPE_PARAM_UPDATE = "参数变更";
public static final String OPER_TYPE_PARAM_ACTIVATE = "参数激活";
public static final String OPER_TYPE_PARAM_DEACTIVATE = "参数停用";
public static final String OPER_TYPE_RECALC_BASE = "基数重算";
public static final String OPER_TYPE_CALC_MONTH = "月度核算";
```

### 10.2 审计触发点

#### 10.2.1 `hr_social_param_config` 参数配置

| 操作 | 触发时机 | beforeJson | afterJson |
|------|---------|------------|-----------|
| **新增**（INSERT） | 保存新参数记录时 | null | 新记录全字段快照 |
| **停用旧记录**（is_active=0） | 激活新记录前，先将原记录置0 | 原记录全字段快照 | `{"id":N,"is_active":0}` |
| **激活新记录**（INSERT+is_active=1） | 保存新版本参数时 | null | 新记录全字段快照 |
| **直接停用**（无新版本） | 手动停用某条记录时 | 记录全字段快照 | `{"id":N,"is_active":0}` |

> **强制约束**：修改生效费率时，必须先关停旧记录再新增记录，**禁止直接 UPDATE 当前生效记录**。审计日志必须同时记录两条操作（停用+新增），bizId 使用相同值（新记录的 id）关联。

#### 10.2.2 `hr_housing_fund_config` 公积金参数配置

审计触发点与 `hr_social_param_config` 相同，oper_module 使用 `MODULE_HR_SOCIAL_PARAM`，bizId 为 config 记录 id。

#### 10.2.3 年度基数重算

| 操作 | 触发时机 | 审计内容 |
|------|---------|---------|
| **重算执行** | 手动触发或定时任务执行完毕 | beforeJson=null；afterJson=`{totalCount:N,successCount:M,failCount:K,employeeIdList:[...]}` |
| **单员工基数变更** | 每个员工基数更新后 | beforeJson=`{socialBase:旧值,housingFundBase:旧值,baseEffectiveYear:旧年度}`；afterJson=`{socialBase:新值,housingFundBase:新值,baseEffectiveYear:新年度}`；bizId 为员工ID |

> 基数重算为批量操作，建议在事务提交后逐条记录审计日志，失败不影响主流程。

#### 10.2.4 月度薪资核算

| 操作 | 触发时机 | 审计内容 |
|------|---------|---------|
| **月度核算生成** | 每次调用 `generateMonth()` 生成完一个员工后 | beforeJson=null；afterJson=`{salaryMonth,employeeId,grossAmount,netAmount,taxAmount,社保险种汇总}`；bizId 为 `hr_salary_month.id` |
| **薪资发放** | 调用 `payMonth()` 时 | 复用现有 `MODULE_HR_SALARY` + `OPER_TYPE_PAY_SALARY` |

#### 10.2.5 员工基数字段变更

| 操作 | 触发时机 | 审计内容 |
|------|---------|---------|
| **员工档案修改基数** | HR 手动修改 `social_declare_base` / `housing_fund_declare_base` | beforeJson/afterJson 包含变更前后基数值；bizId 为员工ID |

### 10.3 审计代码调用示例

```java
// 示例：社保参数配置新增（关停旧记录 + 插入新记录）
auditLogUtil.record(
    CommonConst.MODULE_HR_SOCIAL_PARAM,
    CommonConst.OPER_TYPE_PARAM_DEACTIVATE,
    String.valueOf(oldRecord.getId()),
    oldRecord,                          // before: 原记录完整快照
    Map.of("id", oldRecord.getId(), "isActive", 0)  // after: 仅记录状态变更
);

auditLogUtil.record(
    CommonConst.MODULE_HR_SOCIAL_PARAM,
    CommonConst.OPER_TYPE_PARAM_ADD,
    String.valueOf(newRecord.getId()),
    null,                               // before: 新增操作无旧数据
    newRecord                           // after: 新记录完整快照
);
```

```java
@RestController
@RequestMapping("/hr/city")
@RequiredArgsConstructor
@PreAuthorize("@permission.hasPermission(PermissionConst.HR_CITY_LIST)")
public class HrCityController {

    private final HrCityService cityService;

    @GetMapping("/page")
    public Result<IPage<HrCityVO>> getPage(@RequestParam(defaultValue = "1") Integer pageNum,
                                           @RequestParam(defaultValue = "20") Integer pageSize,
                                           HrCityDTO dto) {
        return Result.ok(cityService.getPage(pageNum, pageSize, dto));
    }

    @PostMapping
    @PreAuthorize("@permission.hasPermission(PermissionConst.HR_CITY_ADD)")
    public Result<Void> add(@RequestBody @Validated HrCityDTO dto) {
        cityService.add(dto);
        return Result.ok();
    }

    @PutMapping
    @PreAuthorize("@permission.hasPermission(PermissionConst.HR_CITY_EDIT)")
    public Result<Void> update(@RequestBody @Validated HrCityDTO dto) {
        cityService.update(dto);
        return Result.ok();
    }

    @DeleteMapping("/{id}")
    @PreAuthorize("@permission.hasPermission(PermissionConst.HR_CITY_DELETE)")
    public Result<Void> delete(@PathVariable Long id) {
        cityService.delete(id);
        return Result.ok();
    }
}
```

## 十七、风险提示

1. **存量数据兼容**：`hr_employee` 新增字段均为 NULLABLE，存量员工 `city_code` 为空时需HR手动补充
2. **基数重算历史数据**：2026年7月前入职员工无上年度工资数据，首年基数重算以当前 `social_security_base` 为准
3. **长护险试点**：仅部分城市启用，需通过 `hr_social_param_config` 中 `insurance_code=LONG_CARE` 控制，未配置的城市自动跳过
4. **个税累计预扣法**：需按员工当年累计收入计算，涉及跨月状态，建议单独开发个税计算服务
5. **费率历史存档**：每次修改 `hr_social_param_config` 的当前记录时，必须将原记录 `is_active` 置0并新增记录，禁止直接 UPDATE
6. **审计日志强制要求**：参数配置新增/停用/激活、基数重算、月度核算均须写入 `sys_audit_log`，详见§十审计日志设计
7. **基数重算幂等性**：年度重算可重复执行，每次执行以 `base_effective_year` 作为幂等键，已处理过的年度员工不重复处理
8. **多租户隔离**：所有 HR 社保接口必须携带 company_id，后端从 UserContext 获取，不信任前端传入

【社保参数配置流程】
用户登录 → 集团中台 → 城市字典/险种字典/行业字典（CRUD）
    ↓
用户登录 → 集团中台 → 社保参数配置
    ↓
选择城市+险种+行业 → 输入基数上下限+费率比例 → 保存
    ↓
[自动] 关停旧生效记录(is_active=0) → 新增新记录(is_active=1)
    ↓
[审计日志] 记录两条操作：停用+新增
    ↓
前端提示"激活成功"

【年度基数重算流程】
用户登录 → 人力资源 → 年度基数重算
    ↓
选择重算年度 → 点击"执行重算"
    ↓
[后端] 查询所有city_code不为空的员工
    ↓
FOR EACH 员工:
  1. 查询上年1-12月全部税前收入
  2. 计算月均 = 总收入 / 实际发薪月份数
  3. 截断：base = clamp(月均, 城市下限, 城市上限)
  4. 更新 hr_employee.social_declare_base
  5. 更新 hr_employee.housing_fund_declare_base
  6. 更新 hr_employee.base_effective_year
  7. 写入审计日志
    ↓
返回执行结果：总数/成功数/失败数/员工ID列表
