# 收费规则逻辑描述规范

## 一、概述

收费规则模块是集团业务一体化管控平台财务管理的核心子模块，支撑多业态、多子公司的差异化计费需求。该模块包含三层核心概念：**收费类型 → 收费规则 → 铺位绑定**，形成"定义计费项目 → 配置计费方式 → 绑定到标的"的完整链路。

- 前端路由：`/finance/feeItem`（收费类型管理）、`/finance/feeRule`（收费规则管理）
- 后端包路径：`com.gbi.platform.controller.finance` / `com.gbi.platform.service.impl` / `com.gbi.platform.entity`
- 权限标识：`fee:item:*` / `fee:rule:*`（子公司可配置增删改，集团账号仅只读 list）

## 二、数据模型

### 2.1 收费类型表（biz_fee_item）

> 定义"收什么费"，是收费规则的底层分类依据。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | bigint unsigned | PK, AUTO_INCREMENT | 主键 |
| company_id | bigint | NOT NULL, 默认 0 | 所属子公司 ID，0 = 集团模板（全分子公司可见） |
| fee_item_name | varchar(128) | NOT NULL | 收费类型名称（如：租金、物业费、水费、电费、押金、其他） |
| calc_unit | varchar(32) | NULL | 计量单位（如：元/月、元/平米、元/吨） |
| remark | varchar(500) | NULL | 备注 |
| 全局基础字段 | — | — | company_id / create_by / create_time / update_by / update_time / is_delete |

**业务约束**：
- 同公司（company_id）内 `fee_item_name` 唯一
- 删除前置校验：被 `biz_fee_rule` 引用时禁止删除，抛出 `BizException("该收费类型已被收费规则引用，禁止删除")`

### 2.2 收费规则表（biz_fee_rule）

> 定义"怎么收费"，关联收费类型，配置计费方式、单价、周期、滞纳金。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | bigint unsigned | PK, AUTO_INCREMENT | 主键 |
| company_id | bigint | NOT NULL, 默认 0 | 所属子公司 ID，0 = 集团模板 |
| rule_name | varchar(128) | NOT NULL | 规则名称（如：月度租金规则、按面积物业费） |
| fee_item_id | bigint | NOT NULL | 关联收费类型 ID（biz_fee_item） |
| calc_mode | tinyint | NOT NULL, 默认 1 | 收费方式：1=定额 / 2=按面积 |
| price | decimal(12,2) | NOT NULL, 默认 0.00 | 单价：定额=固定金额/周期；按面积=每平米单价 |
| period_type | tinyint | NOT NULL, 默认 2 | 收费周期：0=不使用周期 / 1=按年 / 2=按月 / 3=按日 |
| overdue_rate | decimal(5,2) | NOT NULL, 默认 0.00 | 滞纳金百分比（0=不收，最大 100） |
| status | tinyint | NOT NULL, 默认 1 | 规则状态：0=停用 / 1=启用 |
| remark | varchar(500) | NULL | 备注 |
| 全局基础字段 | — | — | company_id / create_by / create_time / update_by / update_time / is_delete |

**业务约束**：
- 同公司（company_id）内 `rule_name` 唯一
- 新增/编辑时校验 `fee_item_id` 存在（通过 `feeItemMapper.selectById`，受 company_id 拦截器约束，跨公司不可引用）
- 仅 `status=1`（启用）的规则可被铺位绑定

### 2.3 收费规则-铺位绑定关联表（biz_fee_rule_stall_rel）

> 将收费规则绑定到具体铺位，一个铺位可绑定多条规则（不同收费类型各一条）。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | bigint unsigned | PK, AUTO_INCREMENT | 主键 |
| company_id | bigint | NOT NULL | 所属子公司 ID |
| rule_id | bigint | NOT NULL | 收费规则 ID（biz_fee_rule） |
| stall_id | bigint | NOT NULL | 铺位 ID（stall_info） |
| override_flag | tinyint | NOT NULL, 默认 0 | 是否特殊覆盖：0=普通绑定 / 1=单铺位覆盖（预留，本期界面不启用） |
| override_price | decimal(12,2) | NULL | 覆盖单价（预留） |
| override_config_json | varchar(500) | NULL | 覆盖配置 JSON（预留） |
| 全局基础字段 | — | — | company_id / create_by / create_time / update_by / update_time / is_delete |

**业务约束**：
- 同一收费类型（fee_item_id）限选一条规则：绑定校验时按 `fee_item_id` 分组计数，超过 1 条则拒绝
- 绑定前校验：每条规则必须存在且 status=1（停用/跨公司规则拒绝绑定）
- 全量替换策略：保存时先物理删除该铺位全部旧绑定（含历史软删行，规避唯一键冲突），再插入新绑定
- 铺位 + 绑定操作在同一事务内（@Transactional），任一失败整体回滚

## 三、核心业务逻辑

### 3.1 收费规则计费公式

根据 `calc_mode`（收费方式）和 `period_type`（收费周期）的不同组合，费用计算公式如下：

#### 收费方式 1：定额（calc_mode = 1）

> 固定金额，与铺位面积无关。

```
应收金额 = price
```

- `price` 含义：每个收费周期固定收取的金额
- 适用场景：月租、年租、一次性押金、固定物业费等

#### 收费方式 2：按面积（calc_mode = 2）

> 按铺位面积 × 单价计算。

```
应收金额 = price × stall_area
```

- `price` 含义：每平米单价
- `stall_area` 来源：stall_info.stall_area（铺位面积，单位：平方米）
- 适用场景：按面积计费的物业费、租金等

#### 收费周期与计费频率

| period_type | 含义 | 计费频率说明 |
|-------------|------|-------------|
| 0 | 不使用周期 | 一次性计费（如押金、一次性费用），不关联账单周期 |
| 1 | 按年 | 每年计费一次 |
| 2 | 按月 | 每月计费一次（默认值，适用租金/物业费） |
| 3 | 按日 | 每日计费一次（适用日租铺位等场景） |

> 注：`period_type=0` 适用于押金、一次性其他费用等无需周期滚动的场景。水费/电费通过抄表账单独立计费，不通过此规则体系。

#### 滞纳金计算

```
滞纳金 = 欠款金额 × overdue_rate% × 逾期周期数
```

- `overdue_rate = 0`：不收取滞纳金
- `overdue_rate` 范围：0.00 ~ 100.00（前端限制最大 100%）
- 逾期周期数：按 `period_type` 对应周期累计计算（按月缴费逾期 N 月，则 N 为周期数）

### 3.2 收费类型 → 收费规则 关联逻辑

```
biz_fee_item (fee_item_id) ←——— biz_fee_rule (fee_item_id)
```

- 收费规则必须关联一个已存在的收费类型
- 收费类型被收费规则引用后禁止删除（`FeeItemServiceImpl.delete` 中校验）
- 收费类型命名建议：租金 / 物业费 / 水费 / 电费 / 押金 / 其他（示例，可自定义）

### 3.3 收费规则 → 铺位 绑定逻辑

```
biz_fee_rule (rule_id) ←——— biz_fee_rule_stall_rel (rule_id, stall_id) ←——— stall_info (id)
```

**绑定校验流程**（`FeeRuleStallRelServiceImpl.saveBindings`）：

1. **铺位校验**：铺位必须存在（`leaseStallService.getOptionsByIds`，受 company_id 自动隔离）
2. **规则校验**：
   - 所有传入的 ruleId 必须存在且 status=1（启用）
   - 规则数量必须与传入 ruleIds 数量一致（不一致说明有停用/跨公司规则）
   - 同一 fee_item_id 只能有一条规则（按 fee_item_id 分组去重校验）
3. **全量替换**：先物理清空旧绑定，再插入新绑定（幂等操作，重复提交结果一致）
4. **审计日志**：绑定变更记录审计日志（oper_module=fee_rule，oper_type=绑定）

**铺位新增/编辑时触发绑定**（`LeaseStallServiceImpl.add/update`）：

- 铺位新增/编辑操作与收费规则绑定操作在同一事务内（`@Transactional`）
- 任一失败整体回滚，保证数据一致性

### 3.4 多租户数据隔离

- 所有查询通过 MyBatis-Plus 多租户拦截器自动注入 `company_id` 条件
- 集团账号（company_id=0）可见所有子公司数据；子公司账号仅可见本公司数据
- 收费规则绑定校验时，跨公司规则通过 `feeRuleService.listOptionsByIds` 自动过滤（查不到即视为无效）

## 四、计费流程说明

### 4.1 自定义收费规则计费流程

```
铺位绑定收费规则
    ↓
规则按 period_type 周期触发计费
    ↓
应收金额 = calc_mode=1 ? price : price × stall_area
    ↓
写入 biz_finance_flow（财务流水，flow_type=收入）
    ↓
逾期则按 overdue_rate 累加滞纳金
```

> **注意**：当前一期收费规则主要用于租金、物业费、押金等场景的定额/按面积计费；水费/电费仍走独立抄表账单体系（`WaterElecBillServiceImpl`，按集团配置单价 × 用量计算）。

### 4.2 水电账单计费流程（独立体系，不经过收费规则）

```
抄表（water_elec_meter.current_read）
    ↓
用量 = 本次读数 - 上期账单读数（首期从零起算）
    ↓
金额 = 用量 × 集团配置单价（sys_config: water_elec.water_price / water_elec.elec_price）
    ↓
物业费 = 集团配置每铺位每月固定费用（sys_config: water_elec.property_price）
    ↓
写入 biz_finance_flow
```

## 七、关键枚举值说明

### calc_mode（收费方式）

| 值 | 含义 | 说明 |
|----|------|------|
| 1 | 定额 | price 为固定金额，不乘面积 |
| 2 | 按面积 | price 为每平米单价，金额 = price × stall_area |

### period_type（收费周期）

| 值 | 含义 | 典型场景 |
|----|------|----------|
| 0 | 不使用周期 | 押金、一次性其他费用 |
| 1 | 按年 | 年租金 |
| 2 | 按月 | 月租金、月物业费（默认值） |
| 3 | 按日 | 日租铺位、短期租赁 |

### status（规则状态）

| 值 | 含义 | 影响 |
|----|------|------|
| 0 | 停用 | 不可被新绑定，已绑定铺位不受影响（历史账单沿用原规则） |
| 1 | 启用 | 可被铺位绑定 |

## 八、扩展预留

1. **override_flag=1 单铺位覆盖**：本期预留字段，界面不启用；后续可支持对特定铺位设置特殊单价（override_price）
2. **override_config_json**：预留扩展配置 JSON，支持后续复杂计费规则（如阶梯价、满减等）
3. **集团模板（company_id=0）**：集团可配置全局默认规则，子公司可在此基础上自定义覆盖
