# 文件上传存储模块架构设计方案

> 文档版本：v1.0
> 编制日期：2026-09-18
> 状态：**仅方案设计，等待审核通过后进入代码开发阶段**

## 一、需求拆解与复述

### 1.1 原始需求

基于适配器模式 + 工厂模式，搭建支持三存储驱动（本地磁盘 / 阿里云OSS / 天翼云ZOS）的文件上传存储架构，实现业务代码无侵入、动态切换、历史文件自适应。

### 1.2 必做项（硬性约束）

| 序号 | 必做项 | 约束说明 |
|------|--------|----------|
| 1 | 统一接口 `FileStorageService` | 四个核心方法：上传、删除、获取预览地址、驱动匹配校验 |
| 2 | 三套独立驱动实现类 | `LocalFileStorageServiceImpl` / `AliOssFileStorageServiceImpl` / `TianyOssFileStorageServiceImpl` |
| 3 | 工厂类 `FileStorageFactory` | 读取 `sys_config` 中 `file.storage.type` 动态获取激活驱动 |
| 4 | 动态刷新机制 | 后台修改配置后无需重启服务即可切换存储驱动 |
| 5 | `sys_file` 表设计 | 仅存储 `file_key`，新增 `md5` 字段，存租户+业务元数据 |
| 6 | 统一对外三个接口 | `/file/upload`、`/file/preview/{fileId}`、`/file/delete/{fileId}` |
| 7 | 多租户隔离 | `file_key` 自动拼接 `company_id` 前缀 |
| 8 | 敏感配置加密 | AK/SK 在 `sys_config` 中加密存储，禁止明文日志打印 |
| 9 | 私有存储签名URL | 阿里云OSS / 天翼云ZOS 私有链接生成时效签名临时预览URL |
| 10 | file_key 跨存储统一规则 | 三套驱动共用同一 file_key 相对路径，历史文件自动适配 |
| 11 | 文件上传校验 | 文件大小限制、后缀白名单、非法文件拦截 |
| 12 | 审计日志全覆盖 | 上传、预览、删除全部记录 `sys_audit_log` |
| 13 | 本地静态资源映射 | upload 目录静态访问映射保留 |

### 1.3 可选项（待确认后实现）

- [ ] 文件迁移工具类（批量从本地迁至OSS，或OSS ↔ ZOS互迁）
- [ ] 定时清理过期临时文件任务
- [ ] 文件压缩/缩略图处理（OSS内置，本地/ZOS需单独处理）
- [ ] 多文件并发上传队列

### 1.4 不做项

- 不修改现有 `UploadController` 的业务逻辑主体，而是重构为新的三驱动架构
- 不增加新的数据库连接或缓存中间件（复用现有 MySQL + Redis）
- 前端不做改动（接口契约不变，前端无感知）

## 二、业务流程方案

### 2.1 文字流程图

#### 上传流程

```
[前端 POST /file/upload]
        │
        ▼
[UploadController.upload()]
        │  ① 校验 MultipartFile 非空
        │  ② 校验文件大小（全局配置 maxFileSize）
        │  ③ 校验后缀白名单（FileUploadConst.FILE_WHITELIST）
        │  ④ 计算文件 MD5（防重复上传 / 完整性校验）
        │  ⑤ 生成 file_key：
        │       {company_id}/{biz_type}/{yyyyMMdd}/{UUID}.{ext}
        │  ⑥ 调用 FileStorageFactory.getFileStorage() 获取当前驱动
        │  ⑦ 驱动.upload(fileKey, inputStream, contentType, fileSize)
        │        ├─ 本地 → 写入 projectRoot/upload/...
        │        ├─ OSS → 阿里云SDK上传
        │        └─ ZOS → AWS S3 SDK上传
        │  ⑧ 事务内插入 sys_file 记录（file_key + md5 + 元数据）
        │  ⑨ 记录审计日志
        │  ⑩ 返回 FileUploadVO（含 fileId、fileKey、fileName、fileSize）
        │
        ▼
[返回 Result<FileUploadVO>]
```

#### 预览流程

```
[前端 GET /file/preview/{fileId}]
        │
        ▼
[FileController.preview(fileId)]
        │  ① 查询 sys_file 记录（校验 company_id 隔离）
        │  ② 校验 is_delete = 0
        │  ③ 调用 FileStorageFactory.getFileStorage().getPreviewUrl(fileKey)
        │        ├─ 本地 → 返回 /upload/{fileKey}（静态资源路径）
        │        ├─ OSS → 生成阿里私有签名URL（带过期时间）
        │        └─ ZOS → 生成 S3 预签名URL（带过期时间）
        │  ④ 记录审计日志
        │  ⑤ 重定向至预览URL（HTTP 302）
        │
        ▼
[浏览器加载文件]
```

#### 删除流程

```
[前端 POST /file/delete/{fileId}]
        │
        ▼
[FileController.delete(fileId)]
        │  ① 查询 sys_file 记录（校验 company_id 隔离 + 权限）
        │  ② 调用 FileStorageFactory.getFileStorage().delete(fileKey)
        │        ├─ 本地 → Files.deleteIfExists(物理Path)
        │        ├─ OSS → ossClient.deleteObject()
        │        └─ ZOS → s3Client.deleteObject()
        │  ③ 业务逻辑删除 sys_file（is_delete = 1）
        │  ④ 记录审计日志
        │
        ▼
[返回 Result<Void>]
```

#### 动态切换流程

```
[管理员 POST /sys/config/update]
        │
        ▼
[ConfigServiceImpl.update()]
        │  ① 更新 sys_config 中 file.storage.type 值
        │  ② 触发 FileStorageFactory.cache.clear()
        │  ③ 下次请求 getFileStorage() 时重新读取配置，加载新驱动
        │
        ▼
[下次文件操作自动使用新驱动，无需重启]
```

### 2.2 分支逻辑

| 场景 | 处理逻辑 |
|------|----------|
| 文件后缀不在白名单 | 直接拒绝，返回错误码 FILE_SUFFIX_NOT_ALLOW |
| 文件大小超限 | 直接拒绝，返回错误码 FILE_SIZE_OVER_LIMIT |
| MD5 已存在（相同文件重复上传） | 可选：提示"文件已存在"，返回已有 fileId（避免重复存储） |
| 云存储驱动配置缺失 | 返回 OSS_CONFIG_EMPTY / ZOS_CONFIG_EMPTY |
| 文件删除时物理文件不存在（本地） | 静默忽略，仅标记 sys_file is_delete=1 |
| 云存储文件删除失败 | 记录 ERROR 日志，sys_file 仍做逻辑删除（文件可后续手动清理） |
| fileKey 切换存储后历史文件找不到 | 正常行为——前提是已完成全量迁移；未迁移则返回 404 |

### 2.3 权限边界

| 操作 | 所需权限标识 | 说明 |
|------|-------------|------|
| 文件上传 | `base:file:upload` | 登录用户均可上传 |
| 文件预览 | `base:file:preview` | 登录用户均可预览本公司文件 |
| 文件删除 | `base:file:delete` | 需二级审核（敏感操作） |
| 存储配置修改 | `sys:config:update` | 仅集团管理员可修改 file.storage.type |

### 2.4 风险点

| 风险 | 等级 | 应对措施 |
|------|------|----------|
| 切换存储后历史文件无法访问 | 高 | 迁移工具 + file_key 不变原则保障 |
| 云存储 AK/SK 泄露 | 高 | 加密存储 + 日志脱敏 |
| 恶意文件上传（webshell等） | 高 | 后缀白名单 + MIME二次校验 + 文件名清洗 |
| 并发上传同一文件产生重复记录 | 中 | MD5 查重机制 |
| 本地磁盘空间耗尽 | 中 | 定时检查磁盘用量 + 告警 |
| 云存储临时签名URL被共享泄露 | 低 | 短时效签名（默认1小时） |

## 三、数据库模型变更

### 3.1 表结构：`sys_file`

> ⚠️ 需确认：该表是否已存在。若已存在，需评估字段兼容性后决定 `ALTER TABLE` 还是新建。

#### 新建 SQL（若表不存在）

```sql
CREATE TABLE `sys_file` (
  `id`                BIGINT UNSIGNED  NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `company_id`        BIGINT           NOT NULL DEFAULT 0   COMMENT '租户ID，0=集团全局',
  `biz_type`          VARCHAR(32)      NOT NULL DEFAULT ''  COMMENT '业务类型：contract/oa/hr/finance/property/audit等',
  `biz_id`            BIGINT           NOT NULL DEFAULT 0   COMMENT '关联业务单据ID',
  `file_key`          VARCHAR(512)     NOT NULL DEFAULT ''  COMMENT '跨存储统一相对路径唯一标识（不含域名）',
  `md5`               VARCHAR(32)      NOT NULL DEFAULT ''  COMMENT '文件MD5值，用于去重和完整性校验',
  `file_name`         VARCHAR(256)     NOT NULL DEFAULT ''  COMMENT '原始文件名（含后缀）',
  `file_size`         BIGINT           NOT NULL DEFAULT 0   COMMENT '文件大小（字节）',
  `file_type`         VARCHAR(64)      NOT NULL DEFAULT ''  COMMENT 'MIME类型，如 image/png application/pdf',
  `file_ext`          VARCHAR(16)      NOT NULL DEFAULT ''  COMMENT '文件后缀，如 .jpg .pdf',
  `storage_type`      VARCHAR(16)      NOT NULL DEFAULT 'local' COMMENT '存储类型快照：local/alioss/tianyoss（记录上传时的驱动类型）',
  `is_delete`         TINYINT          NOT NULL DEFAULT 0   COMMENT '逻辑删除 0=正常 1=已删除',
  `create_by`         BIGINT           NOT NULL DEFAULT 0   COMMENT '创建人user_id',
  `create_time`       DATETIME         NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by`         BIGINT           NULL DEFAULT NULL    COMMENT '更新人user_id',
  `update_time`       DATETIME         NULL DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_file_key` (`file_key`),
  KEY `idx_company_biz` (`company_id`, `biz_type`, `biz_id`),
  KEY `idx_md5` (`md5`),
  KEY `idx_create_time` (`create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='系统文件记录表';
```

### 3.2 字段说明

| 字段 | 类型 | 必选 | 说明 |
|------|------|------|------|
| `id` | bigint unsigned | ✅ | 雪花ID，MyBatis-Plus ASSIGN_ID |
| `company_id` | bigint | ✅ | 多租户隔离，集团全局为 0 |
| `biz_type` | varchar(32) | ✅ | 业务类型枚举，见下方常量定义 |
| `biz_id` | bigint | ✅ | 关联业务单据ID，0表示无关联 |
| `file_key` | varchar(512) | ✅ | **核心字段**：跨存储统一相对路径，格式 `{companyId}/{bizType}/{yyyyMMdd}/{uuid}.{ext}` |
| `md5` | varchar(32) | ✅ | 小写32位MD5，用于去重和完整性校验 |
| `file_name` | varchar(256) | ✅ | 原始文件名，如"合同.pdf" |
| `file_size` | bigint | ✅ | 字节数 |
| `file_type` | varchar(64) | ✅ | MIME类型 |
| `file_ext` | varchar(16) | ✅ | 小写后缀，如 jpg、pdf |
| `storage_type` | varchar(16) | ✅ | **快照字段**：记录上传时的存储类型，便于历史追溯 |
| `is_delete` | tinyint | ✅ | 逻辑删除 |
| `create_by/create_time/update_by/update_time` | — | ✅ | 标准审计字段 |

### 3.3 索引策略

| 索引名 | 类型 | 字段 | 用途 |
|--------|------|------|------|
| `uk_file_key` | 唯一索引 | `file_key` | 防止重复file_key，迁移校验 |
| `idx_company_biz` | 普通索引 | `company_id, biz_type, biz_id` | 按业务查询文件列表 |
| `idx_md5` | 普通索引 | `md5` | 重复文件查重 |
| `idx_create_time` | 普通索引 | `create_time` | 按时间排序 / 过期清理 |

### 3.4 sys_config 新增配置项

| config_key | config_name | config_value（示例） | 说明 |
|------------|-------------|---------------------|------|
| `file.storage.type` | 文件存储类型 | `local` | 枚举：local / alioss / tianyoss |
| `file.max.size` | 单文件最大大小（字节） | `20971520` | 20MB |
| `file.whitelist` | 允许的文件后缀 | `jpg,jpeg,png,gif,bmp,webp,pdf,doc,docx,xls,xlsx,ppt,pptx,zip,rar,txt,csv` | 逗号分隔 |
| `file.local.base.dir` | 本地存储根目录 | `./upload` | 固定为项目根目录下的 upload 文件夹 |
| `file.local.access.prefix` | 本地文件访问前缀 | `/upload` | 与 WebConfig 映射保持一致 |
| `file.oss.endpoint` | 阿里云OSS Endpoint | `oss-cn-hangzhou.aliyuncs.com` | |
| `file.oss.bucket.name` | 阿里云OSS Bucket名称 | `gbi-platform-file` | |
| `file.oss.domain` | 阿里云OSS访问域名 | `https://gbi-platform-file.oss-cn-hangzhou.aliyuncs.com` | |
| `file.oss.path.prefix` | OSS路径前缀 | `gbi-platform/` | |
| `file.oss.sign.expire-seconds` | OSS签名过期时间（秒） | `3600` | 1小时 |
| `file.zos.endpoint` | 天翼云ZOS Endpoint | `oss-cn-shanghai-internal.api.tianyi.cloud` | 内网地址优先 |
| `file.zos.bucket.name` | 天翼云ZOS Bucket名称 | `gbi-platform-file` | |
| `file.zos.domain` | 天翼云ZOS访问域名 | `https://gbi-platform-file.tyjcloud.com` | |
| `file.zos.path.prefix` | ZOS路径前缀 | `gbi-platform/` | |
| `file.zos.sign.expire-seconds` | ZOS签名过期时间（秒） | `3600` | 1小时 |

> 🔒 `file.oss.access.key.id`、`file.oss.access.key.secret`、`file.zos.access.key.id`、`file.zos.access.key.secret` **在 sys_config 中以 AES 加密存储**，代码层读取后解密使用，禁止明文落库、禁止日志打印。

### 3.5 风险评估

| 风险 | 描述 | 应对 |
|------|------|------|
| `file_key` 长度超限 | varchar(512) 足够覆盖嵌套子目录场景 | 上限校验防止超长路径 |
| 切换存储后历史数据丢失 | 未迁移的文件在新存储中不存在 | 提供迁移工具 + 切换前强制校验 |
| `storage_type` 快照字段 | 切换后旧记录的 storage_type 保留原值 | 预览时按原 storage_type 查询（或统一用当前驱动 + 迁移保证一致性） |

## 四、接口设计

### 4.1 接口总览

| 接口 | 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|------|
| 文件上传 | POST | `/file/upload` | `base:file:upload` | 单文件上传，返回 fileId 和 fileKey |
| 文件预览 | GET | `/file/preview/{fileId}` | `base:file:preview` | 返回302重定向到实际访问地址 |
| 文件删除 | POST | `/file/delete/{fileId}` | `base:file:delete` | 逻辑删除 + 物理文件清理（敏感操作） |
| 文件列表 | POST | `/file/list` | `base:file:list` | 分页查询本公司文件，按业务类型筛选 |
| 存储配置获取 | GET | `/file/storage/config` | `sys:config:view` | 仅集团管理员，查看当前存储配置（脱敏AK/SK） |

### 4.2 接口详细设计

#### 4.2.1 上传接口

**路径**：`POST /file/upload`

**入参（FormData）**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `file` | MultipartFile | ✅ | 文件实体 |
| `bizType` | String | ✅ | 业务类型，如 `contract` / `oa` / `hr` |
| `bizId` | Long | ❌ | 关联业务ID，无关联传 0 |

**出参（FileUploadVO）**：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "fileId": 100001,
    "fileKey": "1/contract/20260918/a1b2c3d4e5f6.jpg",
    "fileName": "合同扫描件.jpg",
    "fileSize": 1048576,
    "fileType": "image/jpeg",
    "fileExt": ".jpg",
    "md5": "5d41402abc4b2a76b9719d911017c592",
    "storageType": "local"
  }
}
```

**错误码**：

| 错误码 | 错误信息 |
|--------|----------|
| 10001 | 上传文件不能为空 |
| 10002 | 文件大小超出限制（当前限制：{maxSize}字节） |
| 10003 | 不支持的文件格式 |
| 10004 | 禁止上传危险文件 |
| 10005 | 文件内容与格式不匹配，校验失败 |
| 10006 | 文件名包含非法字符 |
| 10008 | 文件上传失败，请稍后重试 |

#### 4.2.2 预览接口

**路径**：`GET /file/preview/{fileId}`

**入参**：路径参数 `fileId`（Long）

**出参**：HTTP 302 重定向至实际文件访问地址

- 本地存储：`http://host:port/upload/{fileKey}`
- 阿里云OSS：带签名的临时URL（时效 {signExpireSeconds} 秒）
- 天翼云ZOS：带签名的临时URL（时效 {signExpireSeconds} 秒）

**前置校验**：
1. fileId 必须存在且 is_delete=0
2. 文件所属 company_id 必须与当前登录用户一致（集团管理员例外）
3. 记录审计日志

#### 4.2.3 删除接口

**路径**：`POST /file/delete/{fileId}`

**入参**：路径参数 `fileId`（Long）

**出参**：`Result<Void>`

**业务逻辑**：
1. 查询 sys_file，校验 company_id 隔离
2. 调用对应存储驱动执行物理删除
3. 执行逻辑删除（is_delete=1）
4. 记录审计日志（before: 文件记录，after: null）

**风险提示**：删除为敏感操作，建议加二级复核（复用权限审核流程）。

#### 4.2.4 文件列表接口

**路径**：`POST /file/list`

**入参（FileQueryDTO）**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| pageNum | Integer | ✅ | 页码 |
| pageSize | Integer | ✅ | 每页条数，最大100 |
| bizType | String | ❌ | 业务类型筛选 |
| bizId | Long | ❌ | 业务ID筛选 |
| fileName | String | ❌ | 文件名模糊查询 |

**出参**：分页 VO 列表，含 fileId、fileKey、fileName、fileSize、fileType、fileExt、createTime

### 4.3 事务与权限校验规范

| 接口 | 事务 | 权限校验 | 说明 |
|------|------|----------|------|
| `/file/upload` | ✅ 需要 | `base:file:upload` | 上传 + 入库必须同一事务 |
| `/file/preview/{fileId}` | ❌ | `base:file:preview` | 只读，不需要事务 |
| `/file/delete/{fileId}` | ✅ 需要 | `base:file:delete`（敏感，建议二级复核） | 物理删除 + 逻辑删除需同一事务 |
| `/file/list` | ❌ | `base:file:list` | 只读查询 |

## 五、核心架构设计详解

### 5.1 分层结构（严格对齐项目规范）


### 5.2 统一接口 `FileStorageService`（适配器核心）

```
interface FileStorageService {

    /**
     * 上传文件
     * @param fileKey       跨存储统一相对路径
     * @param inputStream   文件输入流
     * @param contentType   MIME类型
     * @param fileSize      文件大小（字节）
     * @return 上传后的实际访问URL（本地返回相对路径，云存储返回完整URL）
     */
    String upload(String fileKey, InputStream inputStream, String contentType, long fileSize);

    /**
     * 删除文件
     * @param fileKey 跨存储统一相对路径
     * @return 是否删除成功
     */
    boolean delete(String fileKey);

    /**
     * 获取预览地址（临时签名URL或静态路径）
     * @param fileKey 跨存储统一相对路径
     * @return 可访问的URL
     */
    String getPreviewUrl(String fileKey);

    /**
     * 驱动类型匹配校验（工厂用）
     * @return 驱动类型枚举字符串
     */
    String getStorageType();
}
```

### 5.3 工厂类 `FileStorageFactory`

**核心机制**：

1. 启动时读取 `sys_config` 中 `file.storage.type` 的当前值
2. 根据值实例化对应的 `FileStorageService` 实现类
3. 缓存当前驱动实例（`ConcurrentHashMap` 或 `@Scope("prototype")` + 手动缓存）
4. 提供 `refresh()` 方法：清除缓存，下次 `getFileStorage()` 重新读取配置

**动态刷新流程**：

```
管理员更新 sys_config.file.storage.type
        │
        ▼
ConfigServiceImpl.update() 成功后
        │
        ▼
FileStorageFactory.refresh() 调用
        │
        ▼
清除缓存 → 下次请求自动加载新驱动
```

**注意**：由于 `sys_config` 数据量小，每次 `getFileStorage()` 时直接从 DB 读取最新值并缓存 60 秒（Redis），平衡性能与实时性。

### 5.4 file_key 命名规则（三存储统一）

```
{company_id}/{biz_type}/{yyyyMMdd}/{8位UUID}.{ext}

示例：
  1/contract/20260918/a1b2c3d4e5f6.jpg
  2/hr/20260918/b2c3d4e5f6a1.pdf
  0/oa/20260918/c3d4e5f6a1b2.docx
```

**规则说明**：
- `company_id`：多租户隔离前缀
- `biz_type`：业务类型，便于按业务分类管理
- `yyyyMMdd`：日期子目录，便于文件组织和定期清理
- `8位UUID`：保证同天同业务下文件名不冲突
- `.ext`：原始文件后缀，小写

**关键**：三套驱动使用完全相同的 `file_key` 规则，确保切换存储后历史文件路径不变。

### 5.5 三套驱动实现差异说明

#### 5.5.1 本地存储 `LocalFileStorageServiceImpl`

| 项目 | 说明 |
|------|------|
| 物理路径 | 项目根目录 `/upload` + file_key 拼接 |
| 自动创建目录 | `Files.createDirectories(dir)` |
| 写入方式 | `Files.copy(inputStream, path, StandardCopyOption.REPLACE_EXISTING)` |
| 删除方式 | `Files.deleteIfExists(path)`（不存在不报错） |
| 预览URL | 返回 `/upload/{fileKey}`（静态资源路径，由 WebConfig 映射） |
| 依赖 | 仅 JDK NIO，无需额外依赖 |

#### 5.5.2 阿里云OSS `AliOssFileStorageServiceImpl`

| 项目 | 说明 |
|------|------|
| SDK | `aliyun-sdk-oss`（官方 SDK） |
| 上传方式 | `ossClient.putObject(bucketName, fileKey, inputStream)` |
| 删除方式 | `ossClient.deleteObject(bucketName, fileKey)` |
| 预览URL | `ossClient.generatePresignedUrl(bucketName, fileKey, expiration)`（阿里私有签名规则） |
| 图片处理 | OSS自带图片处理能力（缩略图、格式转换等），通过 URL 参数实现 |
| 依赖 | `com.aliyun.oss:aliyun-sdk-oss` |

#### 5.5.3 天翼云ZOS `TianyOssFileStorageServiceImpl`

| 项目 | 说明 |
|------|------|
| SDK | `aws-java-sdk-s3`（标准 S3 SDK，天翼云ZOS兼容S3协议） |
| 上传方式 | `s3Client.putObject(bucketName, fileKey, inputStream, metadata)` |
| 删除方式 | `s3Client.deleteObject(bucketName, fileKey)` |
| 预览URL | `s3Client.generatePresignedUrl(bucketName, fileKey, expiration)`（标准S3签名） |
| 图片处理 | **无内置图片处理**，需在代码层或前端自行处理 |
| 端点配置 | endpoint 需配置为内网地址（优先）或公网地址 |
| 依赖 | `software.amazon.awssdk:s3` |

### 5.6 差异对比矩阵

| 能力项 | 本地存储 | 阿里云OSS | 天翼云ZOS |
|--------|---------|-----------|-----------|
| SDK依赖 | 无（JDK NIO） | aliyun-sdk-oss | aws-java-sdk-s3 |
| 上传方式 | 文件流写入磁盘 | putObject | putObject（S3标准） |
| 删除方式 | deleteIfExists | deleteObject | deleteObject |
| 预览URL生成 | 返回静态路径 | 阿里私有签名URL | S3预签名URL |
| 图片处理能力 | 无（需额外库） | ✅ 内置 | ❌ 无 |
| 签名时效配置 | N/A | sign.expire-seconds | sign.expire-seconds |
| 多租户隔离 | file_key 前缀 company_id | 同 | 同 |
| 成本 | 服务器磁盘成本 | 按量计费 | 按量计费 |

### 6.2 文件上传统一校验规则

| 校验项 | 校验逻辑 | 错误码 |
|--------|----------|--------|
| 文件非空 | `file.isEmpty()` | FILE_EMPTY |
| 文件大小 | `file.getSize() > maxFileSize`（读自 sys_config） | FILE_SIZE_OVER_LIMIT |
| 后缀白名单 | 提取后缀，与 `file.whitelist` 比对 | FILE_SUFFIX_NOT_ALLOW |
| 危险后缀黑名单 | 永久禁止：`.exe,.html,.htm,.js,.jsp,.php,.py,.sh,.bat,.cmd` | FILE_SUFFIX_DANGER |

| 文件名非法字符 | 过滤 `/ \ : * ? " < > \|` 等 | FILE_PATH_ILLEGAL |
| 文件名长度 | 不超过 256 字符 | FILE_PATH_ILLEGAL |

## 八、无缝切换机制详解

### 8.1 切换原理

1. **file_key 是唯一桥梁**：三套驱动使用完全相同的 file_key 规则，切换驱动不影响已有 file_key
2. **sys_file 记录存储 file_key，不存储 URL**：URL 由驱动在预览时动态生成
3. **storage_type 快照字段**：记录每次上传时的存储类型，便于审计追溯

### 8.2 切换前准备检查清单

| 检查项 | 说明 |
|--------|------|
| 目标存储配置完整 | sys_config 中目标驱动全套参数已配置（含加密的 AK/SK） |
| 目标存储连通性 | 执行一次测试上传，确认 AK/SK 和 endpoint 正确 |
| 历史文件迁移（如需要） | 若从本地切至OSS，需先执行迁移工具将文件全部上传至OSS |
| 迁移完成校验 | 对比重定向数量和 OSS 对象数量，确认一致 |
| 回滚方案确认 | 保留原存储驱动配置，切换失败可随时回滚 |

### 8.3 切换操作流程

```
Step 1：配置目标存储参数（sys_config 写入）
Step 2：执行存储迁移工具（本地→OSS，或 OSS→ZOS）
Step 3：验证迁移结果（抽样检查文件可访问）
Step 4：修改 file.storage.type 配置值
Step 5：调用 FileStorageFactory.refresh() 刷新驱动
Step 6：执行一次测试上传，确认新驱动生效
Step 7：更新 WebConfig 静态映射（仅本地→云存储切换时需要）
```

### 8.4 不回滚的情况

若未执行迁移直接切换存储类型，历史文件的 file_key 在目标存储中不存在，预览时返回 404。因此**迁移必须在切换配置之前完成**。

## 九、安全规范

### 9.1 AK/SK 加密存储方案

- 使用项目现有 AES 加密工具（参考 `PasswordConfig` 中的加密逻辑）
- 写入 sys_config 时：明文 AK/SK → AES加密 → config_value
- 读取时：config_value → AES解密 → 构建 SDK 客户端
- **禁止**：日志打印完整 AK/SK、VO 返回 AK/SK、前端传递 AK/SK

### 9.2 文件安全红线

| 禁止行为 | 说明 |
|----------|------|
| 禁止允许 exe/html/js 等可执行文件上传 | 黑名单永久生效 |
| 禁止前端直接获取文件存储路径 | 统一走 `/file/preview/{fileId}` |
| 禁止明文存储 AK/SK | sys_config 加密存储 |
| 禁止物理删除 sys_file 记录 | 仅逻辑删除（is_delete=1） |
| 禁止无权限上传 | 所有接口需 JWT + RBAC 校验 |

### 9.3 预览 URL 安全

- 私有 OSS/ZOS 桶统一使用**临时签名URL**，有效期默认 1 小时
- 签名 URL 不可重复利用（每次预览重新生成）
- 本地存储文件可通过 Nginx 限制 Referer 防盗链
