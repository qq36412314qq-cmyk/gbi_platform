# 组织架构-岗位-员工体系升级方案

> 版本：v1.0  
> 日期：2026-09-17  
> 状态：待审核

## 一、现状分析与问题定位

### 1.1 当前架构缺陷

| 维度 | 现状 | 问题 |
|------|------|------|
| **组织层级** | `sys_org` 仅有集团(1)→子公司(2)→部门(3) | 缺少科室/班组级节点，岗位无法精细化挂载 |
| **岗位归属** | `hr_post.dept_id` 字段存在但为 NULL，未关联 `sys_org` | 岗位与组织脱节，无法统计部门人员配置 |
| **岗位页面** | `org/index.vue` 表格缺少「所属部门」列，表单缺少「所属组织」选择器 | 岗位管理功能不完整，无法指定岗位挂靠的 org_type=4 节点 |
| **员工档案** | `hr_employee` 表已存在，字段结构基本完整 | 需补充 `sys_user.employee_id` 关联字段 |
| **用户-员工关联** | `hr_employee.user_id` 已存在（关联sys_user.id）；`sys_user` 缺少 `employee_id` 反向关联 | 双向关联不完整，需补全 |
| **身份证号** | `id_card_no VARCHAR(64)` | 文档误写为 VARCHAR(18) |
| **调岗流程** | `transfer/index.vue` 仅入职申请完整，转正/调岗/离职为占位 | 人事异动流程未闭环 |

### 1.2 数据模型现状

```
sys_user (id=2, username='admin')
    ↓ employee_id（待补充）
hr_employee (user_id=已存在, id_card_no=VARCHAR(64))
    ↓
hr_post (id=5, post_name='Java开发', dept_id=NULL)
    ↓ dept_id 未指向 sys_org
sys_org (id=100, org_name='技术部', org_type=3)
```

## 二、升级目标

1. **完善组织架构层级**：增加科室/班组级别（org_type=4）
2. ✅ `hr_employee` 表已存在，字段结构与实体类对齐
3. **补全用户-员工双向关联**：`sys_user.employee_id` 关联 `hr_employee.id`
4. **修复岗位-组织关联**：`hr_post.dept_id` 指向 `sys_org.id`
5. **完善人事异动流程**：转正、调岗、离职申请表单及审批逻辑

## 二.五、账号管理策略

**决策**：员工离职审批通过后，自动停用关联的 `sys_user` 账号。

**执行逻辑**：
```java
// 离职申请审批通过回调
if (employee.getSysUserId() != null) {
    SysUser user = sysUserService.getById(employee.getSysUserId());
    user.setStatus(0); // 停用账号
    sysUserService.updateById(user);
}
```

**注意事项**：
- 账号停用不影响审计日志追溯（`sys_user` 记录仍存在）
- 管理员可在员工管理页面手动恢复账号（用于特殊场景）

### 3.5 数据初始化脚本（可选）

```sql
-- 为每个部门创建虚拟科室节点（org_type=4）
INSERT INTO sys_org (company_id, parent_id, org_name, org_type, sort_order, create_time, is_delete)
SELECT 
  company_id,
  id AS parent_id,
  CONCAT(org_name, '科室'),
  4 AS org_type,
  999 AS sort_order,
  NOW() AS create_time,
  0 AS is_delete
FROM sys_org
WHERE org_type = 3 AND is_delete = 0;

-- 将岗位关联到对应的科室节点
UPDATE hr_post p
INNER JOIN sys_org o ON p.dept_id = o.id AND o.org_type = 3
SET p.dept_id = (
  SELECT id FROM sys_org 
  WHERE parent_id = p.dept_id AND org_type = 4 AND is_delete = 0 
  LIMIT 1
)
WHERE p.dept_id IS NOT NULL;
```

## 九、附录：完整 SQL 脚本

```sql
-- =============================================
-- 组织架构-岗位-员工体系升级脚本 v1.1（修正版）
-- 执行前请确认：hr_employee 表已存在，以下仅执行缺失部分
-- =============================================

-- 1. 扩展 sys_org.org_type 枚举（新增 org_type=4 科室/班组）
ALTER TABLE sys_org 
  MODIFY COLUMN org_type TINYINT NOT NULL COMMENT '组织类型：1=集团 2=子公司 3=部门 4=科室/班组';

-- 2. sys_user 新增 employee_id 反向关联字段
ALTER TABLE sys_user 
  ADD COLUMN employee_id BIGINT DEFAULT NULL COMMENT '关联hr_employee.id' AFTER status;

ALTER TABLE sys_user 
  ADD INDEX idx_employee_id (employee_id);

-- 3. 修复 hr_post.dept_id 注释
ALTER TABLE hr_post 
  MODIFY COLUMN dept_id BIGINT DEFAULT NULL COMMENT '所属组织节点ID（关联sys_org.id，建议org_type=4）';

-- 4. 初始化：为每个部门创建虚拟科室节点（org_type=4）
INSERT INTO sys_org (company_id, parent_id, org_name, org_type, sort_order, create_time, is_delete)
SELECT 
  company_id,
  id AS parent_id,
  CONCAT(org_name, '科室'),
  4 AS org_type,
  999 AS sort_order,
  NOW() AS create_time,
  0 AS is_delete
FROM sys_org
WHERE org_type = 3 AND is_delete = 0;

-- 5. 修复：将岗位关联到对应的科室节点
UPDATE hr_post p
INNER JOIN sys_org o ON p.dept_id = o.id AND o.org_type = 3
LEFT JOIN sys_org k ON k.parent_id = p.dept_id AND k.org_type = 4 AND k.is_delete = 0
SET p.dept_id = IFNULL(k.id, p.dept_id)
WHERE p.dept_id IS NOT NULL;
```

> ⚠️ **执行说明**：`hr_employee` 表已存在且结构完整，无需执行建表语句。上述 SQL 仅需执行步骤 1-5。
