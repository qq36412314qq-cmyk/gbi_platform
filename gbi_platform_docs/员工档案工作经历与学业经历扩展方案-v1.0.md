## 一、升级背景与需求

### 1.1 现状

当前员工档案（hr_employee）采用扁平字段设计，仅支持单条基础信息录入，无法记录员工的历史工作经历和学业经历。这类数据天然是一对多关系，需要独立子表管理。

### 1.2 目标

- 为员工档案增加工作经历和学业经历两个一对多多值字段
- 支持增删改查完整生命周期管理
- 在前端员工档案列表页，以展开子表形式展示，保持现有 UI 交互一致性
- 所有子表数据遵循多租户 company_id 隔离规范

### 1.3 不做项

- 不与入职申请流程打通（后续迭代评估）
- 不自动关联第三方招聘系统

## 二、数据库模型设计

### 2.1 新增表：hr_employee_work_exp（工作经历）

| 字段名 | 类型 | 可空 | 说明 |
|--------|------|------|------|
| id | BIGINT | NOT NULL | 主键，自增 |
| company_id | BIGINT | NOT NULL | 多租户隔离，关联 hr_employee.company_id |
| employee_id | BIGINT | NOT NULL | 关联 hr_employee.id |
| company_name | VARCHAR(128) | NOT NULL | 公司名称 |
| position | VARCHAR(64) | YES | 职位 |
| department | VARCHAR(64) | YES | 部门 |
| start_date | DATE | NOT NULL | 入职时间 |
| end_date | DATE | YES | 离职时间（当前在职可为空） |
| is_current | TINYINT(1) | NOT NULL | 是否仍在职：1=是，0=否，默认0 |
| reason_for_leaving | VARCHAR(255) | YES | 离职原因 |
| deleted | TINYINT(1) | NOT NULL | 逻辑删除：0=未删，1=已删 |
| create_time | DATETIME | NOT NULL | 创建时间 |
| update_time | DATETIME | NOT NULL | 更新时间 |

**索引：**
CREATE INDEX idx_work_exp_emp ON hr_employee_work_exp(company_id, employee_id);

### 2.2 新增表：hr_employee_edu_exp（学业经历）

| 字段名 | 类型 | 可空 | 说明 |
|--------|------|------|------|
| id | BIGINT | NOT NULL | 主键，自增 |
| company_id | BIGINT | NOT NULL | 多租户隔离 |
| employee_id | BIGINT | NOT NULL | 关联 hr_employee.id |
| school_name | VARCHAR(128) | NOT NULL | 学校名称 |
| degree | VARCHAR(32) | YES | 学历：本科/硕士/博士/大专/其他 |
| major | VARCHAR(128) | YES | 专业 |
| education_level | VARCHAR(32) | YES | 教育形式：全日制/在职/自考/成人教育等 |
| start_date | DATE | NOT NULL | 入学时间 |
| graduation_date | DATE | YES | 毕业时间 |
| is_graduated | TINYINT(1) | NOT NULL | 是否已毕业：1=是，0=否 |
| certificate_no | VARCHAR(64) | YES | 学位证书号 |
| deleted | TINYINT(1) | NOT NULL | 逻辑删除 |
| create_time | DATETIME | NOT NULL | 创建时间 |
| update_time | DATETIME | NOT NULL | 更新时间 |

**索引：**
CREATE INDEX idx_edu_exp_emp ON hr_employee_edu_exp(company_id, employee_id);

## 三、后端代码方案（Java）

### 3.1 新增文件清单

| 类型 | 类名 | 路径 |
|------|------|------|
| 实体 | HrEmployeeWorkExp.java | entity/hr/ |
| 实体 | HrEmployeeEduExp.java | entity/hr/ |
| Mapper | HrEmployeeWorkExpMapper.java | mapper/hr/ |
| Mapper | HrEmployeeEduExpMapper.java | mapper/hr/ |
| XML | HrEmployeeWorkExpMapper.xml | mapper/hr/ |
| XML | HrEmployeeEduExpMapper.xml | mapper/hr/ |
| VO | WorkExpVO.java | vo/hr/ |
| VO | EduExpVO.java | vo/hr/ |
| DTO | WorkExpDTO.java | dto/hr/ |
| DTO | EduExpDTO.java | dto/hr/ |

### 3.2 实体类要点

- 两个实体均继承 BaseEntity（含 id/createTime/updateTime）
- 自行声明 companyId、employeeId、deleted 字段
- 使用 @TableName 注解指定表名
- 使用 @TableLogic 注解实现逻辑删除（参考 HrEmployeeFile.java 已有模式）

### 3.3 Mapper XML 核心 SQL

按员工ID批量查询（带多租户过滤）：
SELECT * FROM hr_employee_work_exp
WHERE company_id = #{companyId} AND employee_id = #{employeeId} AND deleted = 0
ORDER BY start_date DESC

edu_exp 同理。

### 3.4 Controller 新增接口

在 EmployeeController.java 中追加以下 8 个接口：

| HTTP | 路径 | 说明 | 权限标识 |
|------|------|------|----------|
| GET | /hr/employee/{id}/workExps | 查询工作经历列表 | hr:employee:list |
| POST | /hr/employee/workExp/add | 新增工作经历 | hr:employee:add |
| PUT | /hr/employee/workExp/update | 修改工作经历 | hr:employee:edit |
| DELETE | /hr/employee/workExp/{id} | 删除工作经历 | hr:employee:delete |
| GET | /hr/employee/{id}/eduExps | 查询学业经历列表 | hr:employee:list |
| POST | /hr/employee/eduExp/add | 新增学业经历 | hr:employee:add |
| PUT | /hr/employee/eduExp/update | 修改学业经历 | hr:employee:edit |
| DELETE | /hr/employee/eduExp/{id} | 删除学业经历 | hr:employee:delete |

### 3.5 Service 层变更

在 HrEmployeeService.java 接口中新增方法：

工作经历：getWorkExps、addWorkExp、updateWorkExp、deleteWorkExp
学业经历：getEduExps、addEduExp、updateEduExp、deleteEduExp

删除联动逻辑：
删除员工时（delete(id) 方法内），需在事务中同步逻辑删除该员工名下所有工作经历和学业经历记录。

## 四、前端改造方案（Vue3 + TypeScript）

### 4.1 API 文件变更（src/api/hr.ts）

新增以下 TypeScript 接口和 API 函数：

工作经历：WorkExpVO、WorkExpDTO、getWorkExpsApi、addWorkExpApi、updateWorkExpApi、deleteWorkExpApi
学业经历：EduExpVO、EduExpDTO、getEduExpsApi、addEduExpApi、updateEduExpApi、deleteEduExpApi

### 4.2 页面组件变更（src/views/hr/employee/index.vue）

改动范围：仅修改 index.vue，不新建组件。

#### 4.2.1 表格展开区域改造

现有表格无展开列，需新增 type=expand 列，展开后展示两个 Tab：
- Tab 1：工作经历（增删改表格）
- Tab 2：学业经历（增删改表格）

#### 4.2.2 新增弹窗

- 工作经历弹窗：公司名称、职位、部门、起止时间、是否在职、离职原因
- 学业经历弹窗：学校名称、学历、专业、教育形式、起止时间、是否毕业、学位证书号

#### 4.2.3 Script 部分变更

新增 state：workExpMap、eduExpMap、activeTab（reactive Record 类型）
新增函数：loadWorkExps、loadEduExps、openWorkExpDialog、editWorkExp、delWorkExp 等

#### 4.2.4 事件绑定

在 el-table 上绑定 @expand-change 事件，触发懒加载。

## 六、风险评估与注意事项

| 风险点 | 影响 | 缓解措施 |
|--------|------|----------|
| 删除员工时子记录未同步删除 | 孤儿数据残留 | Service.delete() 内开启事务，同时逻辑删除两类子记录 |
| 前端展开时重复请求 | 性能浪费 | 使用 reactive<Record> 缓存，已加载则跳过 |
| 列表页加载变慢 | 用户体验下降 | 工作经历/学业经历采用懒加载（展开时才请求） |
| 前端弹窗与现有风格不一致 | UI 不统一 | 复用现有 el-dialog + el-form 组件模式 |
| 权限粒度 | 操作不可控 | 沿用现有 hr:employee:edit 权限 |
| 历史数据迁移 | 无 | 本次为纯新增功能，不涉及存量数据迁移 |
