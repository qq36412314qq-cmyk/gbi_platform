# 文件上传存储模块使用规范

> **版本**：v1.3
> **生效日期**：2026-09-23
> **适用范围**：所有需要文件上传、预览、删除功能的页面
> **参考示例**：`src/views/hr/transfer/index.vue`（入职申请表单+列表）

---

## 一、模块概述

文件模块提供统一的文件上传、预览、删除能力，支持本地磁盘和云存储（阿里云OSS / 天翼云ZOS）两种驱动，通过 `sys_config.file.storage.type` 配置项动态切换，业务代码无感知。

**核心设计原则**：
- 所有上传接口自动携带 `company_id`（多租户隔离），前端无需传入
- 后端 VO 中直接填充 `photoPreviewUrl` 等可直访 URL，前端避免跨域权限问题
- 上传校验（大小、类型、MD5查重）全部在 `FileService.upload()` 中完成

## 二、后端使用规范

### 2.1 在实体 VO 中暴露照片字段

在业务实体 VO 中，必须同时暴露两个字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `photoFileId` | `Long` | `sys_file.id`，数据库存储用 |
| `photoPreviewUrl` | `String` | 完整可访问预览URL，**前端图片直接绑定此字段** |

```java
@Schema(description = "免冠照片对应的sys_file.id")
private Long photoFileId;

@Schema(description = "免冠照片可直访预览URL（本地/云存储均返回绝对路径）")
private String photoPreviewUrl;
```

### 2.2 在 toVO() 方法中填充预览URL

在 Service 的转换方法中，对 `photoFileId > 0` 的记录调用 `fileService.getPreviewUrl()`，**异常时降级为 null**（不阻断主流程）：

```java
if (entity.getPhotoFileId() != null && entity.getPhotoFileId() > 0) {
    try {
        vo.setPhotoPreviewUrl(fileService.getPreviewUrl(entity.getPhotoFileId()));
    } catch (Exception e) {
        log.warn("[toEntryVO] 获取照片预览URL失败 - photoFileId={}", entity.getPhotoFileId(), e);
        vo.setPhotoPreviewUrl(null);
    }
}
```

### 2.3 上传接口入参规范

业务 DTO 中照片字段统一命名为 `photoFileId`（`Long` 类型），值为上传后返回的 `fileId`：

```java
// EntryApplyDTO.java
@Schema(description = "免冠照片文件ID")
private Long photoFileId;
```

### 2.4 bizType 命名规范

`bizType` 用于区分不同业务场景的文件归属，命名规则为 `{模块}_{子业务}`，小写+下划线：

| 场景 | bizType |
|------|---------|
| 入职申请照片 | `hr_entry` |
| 合同附件 | `contract` |
| OA 审批附件 | `oa_approval` |
| 财务凭证 | `finance_voucher` |
| 审计附件 | `audit_attachment` |

> **注意**：`bizType` 由后端 Controller 接收，前端通过 `uploadFileApi(file, bizType)` 传入，**禁止在 SQL 中硬编码**。

### 2.5 权限常量定义

在 `PermissionConst.java` 中追加文件模块权限标识：

```java
/** ------------------------------ 文件上传存储 ------------------------------ */
public static final String FILE_UPLOAD = "base:file:upload";
public static final String FILE_PREVIEW = "base:file:preview";
public static final String FILE_DELETE = "base:file:delete";
public static final String FILE_LIST = "base:file:list";
```

Controller 中使用双参数 `@PreAuthorize` 写法（三参数写法会导致 SpEL 解析失败）：

```java
@PreAuthorize("hasPermission(T(com.gbi.platform.common.constant.PermissionConst).FILE_UPLOAD, '')")
```

### 2.6 审计日志模块标识

文件操作审计日志使用固定模块名 `MODULE_FILE = "file"`，操作类型见 `CommonConst`：

```java
auditLogUtil.record(CommonConst.MODULE_FILE, CommonConst.OPER_TYPE_FILE_UPLOAD,
        String.valueOf(fileId), sysFile, null);
```

## 三、前端使用规范

### 3.1 导入 API

在 Vue 组件顶部引入文件模块接口：

```typescript
import * as fileApi from '@/api/file'
```

### 3.2 上传组件写法（表单内）

使用 `<el-upload>` + `:auto-upload="false"` 手动触发上传，上传成功后保存 `fileId`：

```vue
<el-form-item label="免冠照片" prop="photoFileId">
  <el-upload
    ref="photoUploadRef"
    action=""
    :auto-upload="false"
    :on-change="handlePhotoChange"
    :show-file-list="false"
    accept="image/jpeg,image/png,image/jpg"
  >
    <el-image
      v-if="entryPhotoUrl"
      :src="entryPhotoUrl"
      fit="cover"
      style="width:120px;height:160px;border-radius:4px;border:1px solid #dcdfe6"
    />
    <el-button v-else type="primary" size="small">
      <el-icon><Plus /></el-icon> 上传照片
    </el-button>
  </el-upload>
  <div style="color:#909399;font-size:12px;margin-top:4px">支持 JPG/PNG，不超过 5MB</div>
</el-form-item>
```

### 3.3 上传回调逻辑

```typescript
const entryPhotoFile = ref<File | null>(null)
const entryPhotoUrl = ref<string>('')
const entryPhotoFileId = ref<number | undefined>(undefined)

function handlePhotoChange(uploadFile: any) {
  const file = uploadFile.raw
  if (!file) return
  if (file.size > 5 * 1024 * 1024) {
    ElMessage.warning('照片大小不能超过 5MB')
    return
  }
  if (!['image/jpeg', 'image/png'].includes(file.type)) {
    ElMessage.warning('仅支持 JPG/PNG 格式')
    return
  }
  entryPhotoFile.value = file
  entryPhotoUrl.value = URL.createObjectURL(file)
  entryPhotoFileId.value = undefined
}
```

### 3.4 提交时上传图片

在表单提交逻辑中，**先上传图片，再组装业务数据**：

```typescript
let photoFileId: number | undefined = entryPhotoFileId.value
if (entryPhotoFile.value) {
  try {
    const uploadResult = await fileApi.uploadFileApi(entryPhotoFile.value, 'hr_entry')
    photoFileId = uploadResult.fileId
    entryPhotoFileId.value = photoFileId
  } catch (e: any) {
    ElMessage.error('照片上传失败：' + (e?.message || '请稍后重试'))
    entrySubmitLoading.value = false
    return
  }
}
const submitData = { ...entryForm, photoFileId, ... } as any
await api.submitEntryApi(submitData)
```

### 3.5 列表图片列写法

列表中使用后端返回的 `photoPreviewUrl`（完整可访问URL），**不要用 `/base/file/preview/{id}` 路径**（会触发权限拦截）：

```vue
<el-table-column prop="photoFileId" label="免冠照片" width="80" align="center">
  <template #default="{ row }">
    <el-image
      v-if="row.photoPreviewUrl"
      :src="row.photoPreviewUrl"
      fit="cover"
      style="width:44px;height:56px;border-radius:3px"
      :preview-src-list="[row.photoPreviewUrl]"
      preview-teleported
    />
    <span v-else style="color:#c0c4cc;font-size:12px">—</span>
  </template>
</el-table-column>
```

### 3.6 禁止的前端用法

| ❌ 错误写法 | 原因 |
|-----------|------|
| `:src="'/base/file/preview/' + row.photoFileId"` | 触发 `@PreAuthorize`，浏览器直链不带 token，返回 403 |
| `:src="fileApi.getPreviewUrlApi(row.photoFileId)"` | 异步函数不能用于模板绑定 |
| 前端自行拼接 `/upload/{fileKey}` | `fileKey` 不对外暴露，且 OSS 模式下路径无效 |

## 四、Vite 代理配置

开发环境中，若使用本地存储模式，需在 `vite.config.ts` 中添加 `/upload` 代理规则（否则静态资源 404）：

```typescript
proxy: {
  '/api': {
    target: 'http://127.0.0.1:8080',
    changeOrigin: true,
    rewrite: (path) => path.replace(/^\/api/, ''),
  },
  // 静态资源代理：本地存储模式下 /upload/** 透传到后端
  '/upload': {
    target: 'http://127.0.0.1:8080',
    changeOrigin: true,
  }
}
```

> OSS 模式下 `photoPreviewUrl` 为完整 CDN URL，不走 Vite 代理，此配置不影响 OSS 切换。

## 五、文件上传完整流程图

```
[前端] el-upload :on-change
       → handlePhotoChange() 校验大小/类型 → entryPhotoFile.value = file

[前端] 提交表单 handleSubmitEntry()
       → fileApi.uploadFileApi(file, bizType)
       → POST /base/file/upload
       → [后端] FileService.upload()
          ├─ 校验非空 / 大小 / 后缀白名单 / MIME
          ├─ 计算 MD5 → 查重提示
          ├─ 生成 fileKey: {companyId}/{bizType}/{yyyyMMdd}/{UUID}.{ext}
          ├─ LocalStorageService.upload() → 写入磁盘
          ├─ SysFileMapper.insert() → 入库
          └─ 返回 FileUploadVO { fileId, previewUrl, md5, ... }

[前端] 收到上传结果 → entryPhotoFileId.value = uploadResult.fileId
       → 组装 submitData 提交业务表单

[后端] toEntryVO() 中调用 fileService.getPreviewUrl(photoFileId)
       → 返回完整可访问 URL 给前端

[前端] 列表渲染 <el-image :src="row.photoPreviewUrl" />
```

### 6.3 核心配置示例

```typescript
const editorInstance = shallowRef<any>(null)
const editorReady = ref(false)
const attachmentHtml = ref('')

const editorConfig = {
  placeholder: '请输入附件内容，支持文字编辑与图片上传…',
  height: '320px',  // 必须 >= 300px，否则 hoverbar 定位异常
  MENU_CONF: {
    uploadImage: {
      // ✅ 使用 customUpload（推荐）
      customUpload(file: File, insertFn: (url: string) => void) {
        const formData = new FormData()
        formData.append('file', file)
        formData.append('bizType', 'hr_entry')  // 按业务场景命名
        const token = getStorage('token')  // ✅ 使用 getStorage，key 为 gbi_admin_token

        fetch('/api/base/file/upload', {
          method: 'POST',
          headers: { 'Authorization': `Bearer ${token}` },
          body: formData
        })
        .then(resp => resp.json())
        .then(res => {
          if (res.code === 200 || res.code === 0) {
            // ✅ 直接使用后端返回的 previewUrl（本地模式: /upload/{fileKey}，OSS模式: 完整CDN URL）
            insertFn(res.data?.previewUrl)
          } else {
            ElMessage.error(res.msg || '图片上传失败')
          }
        })
        .catch(err => {
          console.error('[wangEditor] 上传错误:', err)
          ElMessage.error('图片上传失败，请重试')
        })
      }
    }
  }
}

const handleEditorCreated = (inst: any) => {
  editorInstance.value = inst
  editorReady.value = true
}
const handleEditorDestroyed = () => {
  editorInstance.value = null
  editorReady.value = false
}
```

### 6.6 常见问题排查

| 现象 | 原因 | 解决 |
|------|------|------|
| 图片上传后不插入编辑器 | 使用 `onSuccess` 模式，某些版本存在兼容问题 | 改用 `customUpload` |
| 图片URL为 `/api/base/file/preview/{id}` | 手动拼接URL，未使用后端返回的 `previewUrl` | 使用 `res.data.previewUrl` |
| 上传返回 401 | 使用 `localStorage.getItem('token')`，key名错误 | 改用 `getStorage('token')`（实际key为 `gbi_admin_token`） |
| 编辑区高度警告 | CSS 设置高度 < 300px | 调整为 320px 或更高 |
| 工具栏灰色不可点击 | 编辑器实例为 null 时挂载 | 先创建实例再打开弹窗，或用 `v-if="editorReady"` 控制 Toolbar 显示 |
| 图标全灰/无响应 | `editorInstance` 使用 `ref` 而非 `shallowRef` | 改用 `shallowRef<any>(null)` |
| 弹窗打开后编辑器有时空白/不加载 | Dialog 未加 `destroy-on-close`，手动置空 `editorInstance` 导致组件残留状态冲突，`@onCreated` 时序异常 | ①主弹窗添加 `destroy-on-close`；②`resetEditor()` 和 `openEditDialog` 中移除对 `editorReady` / `editorInstance` 的手动重置 |
| `Editor` 组件上误加 `v-if="editorReady"` | 导致死锁：Editor 不渲染 → `@onCreated` 不触发 → `editorReady` 永远为 false → Editor 永远不渲染 | 移除 Editor 上的 `v-if` 条件，仅 Toolbar 保留 `v-if="editorReady"` |

#### 6.8.6 HTML 源码编辑功能

wangEditor v5 默认工具栏不包含「查看源码」按钮。推荐方案：**独立的 HTML 编辑弹窗**（不切换 Editor 显示模式，不销毁实例）。

**模板**：
```vue
<div class="wang-editor-wrapper">
  <!-- 工具栏行：Toolbar + HTML 编辑按钮 -->
  <div class="wang-editor-toolbar-row">
    <Toolbar v-if="editorReady" :editor="editorInstance" />
    <el-button v-if="editorReady" size="small" @click="openHtmlEditor"
               title="编辑 HTML 源码" style="margin-left:auto;border-radius:0;border-bottom:1px solid #ccc">
      <el-icon><EditPen /></el-icon> HTML
    </el-button>
  </div>
  <!-- Editor 始终挂载，不销毁实例 -->
  <Editor
    v-model="attachmentHtml"
    :defaultConfig="editorConfig"
    @onCreated="handleEditorCreated"
    @onDestroyed="handleEditorDestroyed"
  />
</div>

<!-- HTML 源码编辑弹窗 -->
<el-dialog v-model="htmlDialogVisible" title="编辑 HTML 源码" width="720px"
           :close-on-click-modal="false" destroy-on-close>
  <el-input v-model="htmlContent" type="textarea" :rows="16"
            placeholder="在此编辑 HTML 源码…"
            spellcheck="false" resize="vertical"
            style="font-family:Consolas,Monaco,'Courier New',monospace;font-size:13px" />
  <template #footer>
    <el-button @click="htmlDialogVisible = false">取消</el-button>
    <el-button type="primary" @click="applyHtmlEdit">应用到编辑器</el-button>
  </template>
</el-dialog>
```

**脚本**：
```typescript
/** 打开 HTML 编辑弹窗：读取当前编辑器 HTML 内容 */
const openHtmlEditor = () => {
  if (!editorInstance.value) return
  htmlContent.value = editorInstance.value.getHtml()
  htmlDialogVisible.value = true
}

/** 应用 HTML 修改：写回编辑器并同步 v-model */
const applyHtmlEdit = () => {
  if (!editorInstance.value) return
  editorInstance.value.setHtml(htmlContent.value)
  attachmentHtml.value = htmlContent.value
  htmlDialogVisible.value = false
  ElMessage.success('HTML 源码已应用')
}
```

#### 6.8.7 弹窗打开时重置

> **⚠️ 关键前提**：包含 Editor 的 `<el-dialog>` 必须添加 `destroy-on-close` 属性。
> 这确保每次打开弹窗时 Editor 组件全新挂载，彻底避免残留状态导致的加载异常。

```vue
<!-- ❌ 错误：无 destroy-on-close，Editor 组件持久存在但实例被手动置空，导致状态混乱 -->
<el-dialog v-model="dialogVisible" width="1200px" :close-on-click-modal="false">

<!-- ✅ 正确：关闭时销毁组件，下次打开全新挂载 -->
<el-dialog v-model="dialogVisible" width="1200px" :close-on-click-modal="false" destroy-on-close>
```

每次打开新增/编辑弹窗时，仅重置业务数据和 HTML 内容即可，**无需手动操作 `editorReady` / `editorInstance`**：

```typescript
const openAddDialog = () => {
  Object.assign(form, { id: undefined, employeeNo: '', name: '', employmentType: 1, remark: '' })
  resetEditor()
  dialogVisible.value = true  // Editor 随 dialog 打开自动重新挂载
}

const openEditDialog = (row: api.EmployeeVO) => {
  Object.assign(form, { id: row.id, employeeNo: row.employeeNo, ... })
  photoFileId.value = row.photoFileId
  photoUrl.value = row.photoPreviewUrl || ''
  attachmentHtml.value = row.attachmentContent || ''  // 赋值已有内容
  dialogVisible.value = true
}

const resetEditor = () => {
  photoFile.value = null
  photoUrl.value = ''
  photoFileId.value = undefined
  attachmentHtml.value = ''
  htmlContent.value = ''
  htmlDialogVisible.value = false
  // ✅ 不要重置 editorReady / editorInstance，由组件生命周期管理
}
```

> **原理说明**：`destroy-on-close` 关闭弹窗时销毁 Editor 组件及内部实例；下次打开时组件重新挂载，`@onCreated` 正常触发，`editorReady` 自然变为 `true`。如果不开 `destroy-on-close`，手动置空 `editorInstance` 会导致组件仍在 DOM 中但引用丢失，`@onCreated` 时序异常，出现编辑器空白或工具栏不显示的问题。

#### 6.8.10 完整生命周期图解

```
[弹窗打开 openAddDialog / openEditDialog]
  ├─ attachmentHtml.value = '' 或 row.attachmentContent
  └─ dialogVisible.value = true
     └─ (destroy-on-close 确保每次全新挂载)

[Editor 组件挂载（每次打开时）]
  └─ @onCreated → editorInstance.value = inst, editorReady.value = true
      └─ Toolbar 显示（v-if="editorReady"）

[用户点击 HTML 按钮]
  ├─ openHtmlEditor()
  ├─ htmlContent.value = editorInstance.value.getHtml()
  └─ htmlDialogVisible.value = true

[用户点击「应用到编辑器」]
  ├─ applyHtmlEdit()
  ├─ editorInstance.value.setHtml(htmlContent.value)
  ├─ attachmentHtml.value = htmlContent.value
  └─ htmlDialogVisible.value = false

[用户点击「确定」提交]
  └─ attachmentHtml.value  ← 完整 HTML 内容，存入 attachmentContent 字段

[弹窗关闭（destroy-on-close 触发）]
  └─ Editor 组件及内部实例自动销毁，资源释放
```

## 七、常见错误及排查

| 现象 | 原因 | 解决 |
|------|------|------|
| 照片"加载失败" | 使用了 `/base/file/preview/{id}` 路径，浏览器直链无 token | 改用后端返回的 `photoPreviewUrl` |
| 照片"加载失败" | Vite 代理未配置 `/upload` 转发 | 在 `vite.config.ts` 中添加 `/upload` proxy |
| 上传后文件找不到 | `upload-dir` 配置路径与启动 CWD 不一致 | 使用绝对路径配置，参考 `application-dev.yml` |
| 编译报错 BOM | 文件含 UTF-8 BOM 标记 | 用 edit_file 重写文件，禁止直接粘贴含 BOM 内容 |
| `hasPermission` 表达式报错 | 使用了单参数写法 | 必须使用双参数：`hasPermission('perm', '')` |
| 富文本图片不插入 | 使用 `onSuccess` 模式 | 改用 `customUpload` 并调用 `insertFn(url)` |
| 富文本上传 401 | 使用 `localStorage.getItem('token')` | 改用 `getStorage('token')` |
| 工具栏无源码按钮 | wangEditor v5 默认不显示源码编辑入口 | 添加独立 HTML 编辑弹窗，用 `getHtml()` / `setHtml()` 实现 |
| 编辑器不显示 | Editor 被 `v-if` 卸载后未正确重建 | Editor 始终挂载，通过重置 `editorReady`/`editorInstance` 触发重新初始化 |
