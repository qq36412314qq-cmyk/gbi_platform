# 环境部署文档

## 文档描述

本文档为集团多业态一体化管控系统（gbi_platform）完整部署教程，覆盖：环境要求、标准 Linux 部署（Nginx + JDK + MySQL + Redis）、**宝塔面板部署**（含各部分上传路径指导）、**前后端编译指导**、**前后端对接配置说明**、常见问题与上线检查清单。适用于单人开发后交付部署场景。

---

# 一、环境要求

| 组件 | 版本要求 | 说明 |
|---|---|---|
| JDK | 21 | 后端运行（SpringBoot 3.5 + Java 21） |
| Maven | 3.9+ | 后端打包 |
| Node.js | 18+ | 前端打包（含 npm） |
| MySQL | 8.0 | 数据库，库名 `group_rent_db`，字符集 utf8mb4 |
| Redis | 6+ | 缓存（字典/幂等） |
| Nginx | 1.20+ | 静态托管 + 反向代理 |

> 部署产物只有两个：后端 `gbi_platform_server.jar` + 前端 `dist/` 静态目录。

# 二、方案A：标准 Linux 部署

## 2.1 数据库初始化（按顺序执行，顺序不能乱）

```bash
# 先建库（如已存在跳过）
mysql -uroot -p -e "CREATE DATABASE group_rent_db DEFAULT CHARSET utf8mb4;"

# 依次导入 11 个脚本（位于 gbi_platform_docs/attachments/sql/）
mysql -uroot -p你的密码 --default-character-set=utf8mb4 group_rent_db < install.sql
mysql -uroot -p你的密码 --default-character-set=utf8mb4 group_rent_db < init_platform_menu.sql
mysql -uroot -p你的密码 --default-character-set=utf8mb4 group_rent_db < upgrade_v1.1_waterElec_finance.sql
mysql -uroot -p你的密码 --default-character-set=utf8mb4 group_rent_db < upgrade_v1.2_property_lease.sql
mysql -uroot -p你的密码 --default-character-set=utf8mb4 group_rent_db < upgrade_v1.3_market.sql
mysql -uroot -p你的密码 --default-character-set=utf8mb4 group_rent_db < upgrade_v1.7_fee.sql
mysql -uroot -p你的密码 --default-character-set=utf8mb4 group_rent_db < upgrade_v1.8_fee_rule_stall_rel.sql
mysql -uroot -p你的密码 --default-character-set=utf8mb4 group_rent_db < upgrade_v1.9_fee_period_none.sql
mysql -uroot -p你的密码 --default-character-set=utf8mb4 group_rent_db < upgrade_v1.10_bill_fee_category.sql
mysql -uroot -p你的密码 --default-character-set=utf8mb4 group_rent_db < upgrade_v2.0_recvpay_flow.sql
mysql -uroot -p你的密码 --default-character-set=utf8mb4 group_rent_db < upgrade_v2.1_fee_bill_resume.sql
```

> 脚本存在前后依赖（表结构 + 菜单 ID 衔接），必须按上述顺序执行；重复执行 upgrade 脚本前注意其含 `DROP TABLE IF EXISTS`，会清空对应业务数据。
> ⚠️ v1.7~v1.10 为财务收费规则相关升级：v1.7 建收费类型/规则表 + 菜单 72-79（收费类型管理、收费规则管理）；v1.8 建规则-摊位绑定表；v1.9 周期支持 0 不使用；v1.10 收费类型类别编码 + 账单单价快照列。**若服务器此前已执行过 v1.7/v1.8，仅需补执行 v1.9、v1.10**。漏执行 v1.7 会导致财务管理菜单下缺少"收费类型管理/收费规则管理"且接口报表不存在。
> ⚠️ v2.0/v2.1 为应收应付计划 + 统一审批引擎 + 优惠管理升级：v2.0 建 9 张新表（biz_recv_pay_plan / biz_finance_writeoff / bill_plan_rel / flow_definition / flow_instance / flow_task / flow_record / biz_discount_policy / biz_discount_apply）+ 现有表 ALTER 4 处 + 菜单 80-102 + 初始流程定义/阈值参数/优惠模板；v2.1 为中断恢复脚本（仅当 v2.0 在 10.3 biz_fee_bill 建表处中断过的库需要执行，全新环境执行修补后的 v2.0 即可，v2.1 全部语句幂等可重复执行）。

## 2.2 后端启动（prod 配置全部由环境变量注入，无需改代码）

```bash
mkdir -p /opt/gbi_platform/upload    # 上传目录

nohup java -jar /opt/gbi_platform/gbi_platform_server.jar \
  --spring.profiles.active=prod \
  -DMYSQL_URL="jdbc:mysql://127.0.0.1:3306/group_rent_db?useUnicode=true&characterEncoding=utf8&useSSL=true&serverTimezone=Asia/Shanghai" \
  -DMYSQL_USERNAME=root \
  -DMYSQL_PASSWORD=数据库密码 \
  -DREDIS_HOST=127.0.0.1 \
  -DREDIS_PASSWORD=Redis密码 \
  -DJWT_SECRET=至少32位的自定义随机密钥 \
  -DUPLOAD_DIR=/opt/gbi_platform/upload \
  > /opt/gbi_platform/server.log 2>&1 &
```

验证：`curl http://127.0.0.1:8080/base/dict?type=stall_status`，返回 401（无 token）或 JSON 都说明服务已通。

## 2.3 前端与 Nginx

前端构建产物 `dist/` 上传至 `/opt/gbi_platform/dist`，Nginx 配置：

```nginx
server {
    listen 80;
    server_name 你的域名或IP;

    root /opt/gbi_platform/dist;
    index index.html;
    location / {
        try_files $uri $uri/ /index.html;    # SPA 路由回退
    }

    # 接口反代：去 /api 前缀转发到后端 8080（后端无 /api 上下文）
    location /api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        client_max_body_size 20m;            # 底图等文件上传
    }

    # 上传文件访问（后端本地存储模式）
    location /upload/ {
        proxy_pass http://127.0.0.1:8080/upload/;
    }
}
```

```bash
nginx -t && systemctl reload nginx
```

# 三、方案B：宝塔面板部署（推荐新手）

## 3.0 部署架构总览（先看这个再动手）

本项目部署后形成 **1 个数据库 + 2 个宝塔应用**，前端和后端是两个完全独立的部署形态，**需要两个目录**：

| 部署物 | 宝塔中的载体 | 端口 | 目录 |
|---|---|---|---|
| MySQL 数据库 `group_rent_db` | 宝塔 → 数据库 | 3306（仅本机） | — |
| Java 后端 `gbi_platform_server.jar` | 宝塔 → 网站 → **Java 项目**（Java 项目管理器） | 8080（仅本机） | `/www/wwwroot/gbi_platform/server/` |
| Vue3 前端 `dist/` 静态资源 | 宝塔 → 网站 → **静态站点** | 80/443（对外） | `/www/wwwroot/gbi_platform/admin/dist/` |

目录结构总览（宝塔"文件"管理器中按此创建）：

```
/www/wwwroot/gbi_platform/
├─ server/                          ← 后端目录（Java 项目管理器指向）
│  ├─ gbi_platform_server.jar         后端 jar（本地 mvn package 产物）
│  └─ upload/                         上传文件目录（UPLOAD_DIR 环境变量指向）
├─ admin/                           ← 前端目录（静态站点根目录指向）
│  └─ dist/                           前端构建产物（index.html 必须在此层）
└─ sql/                             ← SQL 脚本目录（临时，导完可删）
   ├─ install.sql
   ├─ init_platform_menu.sql
   └─ upgrade_v1.1 ~ v1.10.sql（共 8 个 upgrade 脚本，全部按顺序导入）
```

> **一句话理解**：用户浏览器只访问静态站点（80/443），页面里的接口请求走 Nginx 的 `/api/` 反向代理转发到本机 8080 后端——两个应用目录分开、互不影响，升级时替换 jar 或 dist 各自独立操作。

2. 软件商店安装：
   - **Nginx**（任意稳定版）
   - **MySQL 8.0**（切换版本安装 8.0，不要装 5.x）
   - **Redis**（默认 127.0.0.1:6379）
   - **Java 项目管理器**（插件，内含 JDK 安装；若无 JDK 21 选项，手动安装 OpenJDK 21 后在插件里配置自定义 JDK 路径）

| 内容 | 上传到宝塔路径 | 说明 |
|---|---|---|
| 后端 jar 包 | `/www/wwwroot/gbi_platform/server/gbi_platform_server.jar` | Java 项目管理器指向此 jar |

## 3.3 数据库初始化

1. 宝塔 → 数据库 → 添加数据库：
   - 名称：`group_rent_db`
   - 字符集：`utf8mb4`
   - 设置访问密码（记下来，后端环境变量要用）

3. 或命令行方式：


1. 宝塔 → 网站 → Java 项目 → 添加 Java 项目：

```

```

   - 环境变量（JVM 参数 `-D` 或面板环境变量栏，二者等效）：


## 3.5 前端部署（静态站点）

1. 宝塔 → 网站 → 添加站点：
   - 域名：填你的域名或 `服务器IP`
   - 根目录：`/www/wwwroot/gbi_platform/admin/dist`
   - 纯静态（不选 PHP）
2. 站点设置 → 配置文件，在 `server { }` 内加入：

```nginx
    # SPA 路由回退（覆盖默认 404）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 接口反代：去 /api 前缀（proxy_pass 结尾的 / 必须保留）
    location /api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        client_max_body_size 20m;
    }

    # 上传文件访问
    location /upload/ {
        proxy_pass http://127.0.0.1:8080/upload/;
    }
```

3. 保存后自动 reload；浏览器访问域名/IP 验证登录页出现。

> ⚠️ 不建议用宝塔"反向代理"按钮配置 `/api`：该功能默认保留 `/api` 前缀转发，会导致后端 404。直接按上述方式编辑配置文件最可靠。

## 3.6 安全与 HTTPS（宝塔操作）

1. 宝塔 → 安全：仅放行 `80`、`443`（及面板端口）；**不放行** 8080/3306/6379；
2. 站点设置 → SSL：申请 Let's Encrypt 证书或上传证书，开启**强制 HTTPS**；
3. 站点设置 →防火墙可开启 CC 防护基础规则。

# 四、前后端编译指导

## 4.1 后端编译（产出 gbi_platform_server.jar）

**前置环境**：JDK 21（配置 JAVA_HOME）、Maven 3.9+。

**Windows（PowerShell）**：

```powershell

# 产物：target\gbi_platform_server.jar
```

**Linux**：

```bash
export JAVA_HOME=/usr/lib/jvm/jdk-21
cd gbi_platform_server

# 产物：target/gbi_platform_server.jar
```

**Maven 加速（可选）**——编辑 `~/.m2/settings.xml`（Windows 为 `C:\Users\当前用户\.m2\settings.xml`）添加阿里云镜像：

```xml
<mirror>
    <id>aliyunmaven</id>
    <mirrorOf>*</mirrorOf>
    <name>阿里云公共仓库</name>
    <url>https://maven.aliyun.com/repository/public</url>
</mirror>
```

**Profile 说明**：

| Profile | 用途 | 特征 |
|---|---|---|
| dev（默认） | 本地开发调试 | 打印 SQL、连接本地库、密钥明文 |
| prod | 生产部署 | 关闭 SQL 日志、数据库/Redis/JWT 密钥全部走环境变量注入 |

> 打包产物同时包含 dev/prod 两套配置，启动时通过 `--spring.profiles.active=prod` 指定生效环境，jar 本身无需区分。

**注意**：
- Windows 下重新打包前必须**先停止正在运行的 java 进程**（运行中的 jar 被锁定，打包会报 `Unable to rename ... .jar`）；
- `-DskipTests` 跳过测试加速打包；编译校验可用 `mvn compile -q`（EXIT=0 即通过）。

# 五、前后端对接配置说明（基于当前项目实际代码）

## 5.1 对接原理（先理解链路）

前后端**同源部署、无跨域问题**。所有接口请求统一走 `/api` 前缀，由代理层转发到后端 8080（后端接口本身**没有** `/api` 上下文）：

```
【开发环境】浏览器 http://localhost:5173
    └─ 请求 /api/base/login
        └─ Vite dev server 代理（vite.config.ts）
            └─ 去掉 /api 前缀 → http://127.0.0.1:8080/base/login

【生产环境】浏览器 http://你的域名
    └─ 请求 /api/base/login
        └─ Nginx 反向代理（location /api/）
            └─ 去掉 /api 前缀 → http://127.0.0.1:8080/base/login
```

> 关键点：`/api` 前缀**在代理层被去掉**（`proxy_pass` 结尾带 `/`），后端收到的路径是 `/base/login` 而非 `/api/base/login`。前端所有 api 文件只写 `/base/login`、`/property/tenant/page` 等后端真实路径。

## 5.2 前端侧配置文件（3 个）

### ① `src/utils/request.ts` —— axios 统一封装（对接核心）

```ts
const service = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '/api',   // 读取环境变量，默认 /api
  timeout: 15000
})

// 请求拦截：自动携带 token（后端 JWT 鉴权约定 Header）
service.interceptors.request.use((config) => {
  const token = getStorage<string>('token')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})
```

对接约定（与后端 `Result` / `PageVO` 结构对齐）：
- 统一返回体：`{ code, msg, data }`，`code === 200` 才返回数据；401 清 token 跳登录、403 无权限提示；
- 分页结构：`{ records, total, pageNum, pageSize, pages }`；
- **一般不需要改动此文件**，除非后端返回结构变更。

### ② `.env.development` / `.env.production` —— 接口前缀

```bash
# 两个文件内容相同
VITE_API_BASE_URL=/api
```

| 文件 | 生效场景 | `/api` 由谁转发 |
|---|---|---|
| `.env.development` | `npm run dev` | Vite dev server 代理（见③） |
| `.env.production` | `npm run build` | Nginx 反向代理（见 5.3） |

### ③ `vite.config.ts` —— 开发环境代理规则（仅开发时生效）

```ts
server: {
  host: '0.0.0.0',
  port: 5173,
  proxy: {
    [env.VITE_API_BASE_URL || '/api']: {
      target: 'http://127.0.0.1:8080',        // 后端地址：本地开发指向本机 8080
      changeOrigin: true,
      rewrite: (path) => path.replace(/^\/api/, ''),   // 去掉 /api 前缀
      timeout: 10000
    }
  }
}
```

**联调改后端地址**：若后端不在本机（如联调测试服务器），只需改 `target` 为 `http://测试机IP:8080`，其余不动。

## 5.3 后端侧配置文件（2 个）

### ① `application.yml` —— 服务端口（公共配置）

```yaml
server:
  port: 8080          # 后端服务端口，与前端代理 target、Nginx proxy_pass 保持一致
```

### ② `application-dev.yml` / `application-prod.yml` —— 环境差异

| 配置项 | dev（本地开发） | prod（生产，环境变量注入） |
|---|---|---|
| 数据库 | 直连本地 group_rent_db | `${MYSQL_URL}` / `${MYSQL_USERNAME}` / `${MYSQL_PASSWORD}` |
| Redis | 127.0.0.1:6379 | `${REDIS_HOST}` / `${REDIS_PASSWORD}` |
| JWT 密钥 | 默认值即可 | `${JWT_SECRET}`（必须覆盖，至少 32 位） |
| SQL 日志 | 开启（StdOutImpl） | 关闭（NoLoggingImpl） |

> 后端**未配置 CORS 跨域**（无需配置）：开发走 Vite 代理、生产走 Nginx 反代，浏览器视角始终同源。

## 5.4 生产 Nginx 对接配置（部署时必配）

```nginx
# 接口反代：/api/ → 后端 8080（proxy_pass 结尾的 / 必须保留，作用是去前缀）
location /api/ {
    proxy_pass http://127.0.0.1:8080/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    client_max_body_size 20m;      # 与后端 spring.servlet.multipart.max-file-size=20MB 对齐
}

# 上传文件访问（后端本地存储模式的静态文件映射）
location /upload/ {
    proxy_pass http://127.0.0.1:8080/upload/;
}
```

## 5.5 对接配置速查表（排查问题时看这里）

| 环节 | 文件位置 | 关键配置 | 必须一致的值 |
|---|---|---|---|
| 前端请求前缀 | `gbi_platform_admin/.env.*` | `VITE_API_BASE_URL=/api` | 与 Nginx/Vite 代理的监听前缀一致 |
| 开发代理 | `gbi_platform_admin/vite.config.ts` | `target: http://127.0.0.1:8080` | 与后端 `server.port` 一致 |
| 后端端口 | `gbi_platform_server/src/main/resources/application.yml` | `server.port: 8080` | 与代理 target / Nginx proxy_pass 一致 |
| 生产反代 | Nginx 站点配置 | `location /api/` + `proxy_pass ...:8080/` | 结尾 `/` 决定去前缀，漏了必 404 |
| token 鉴权 | 前端 request.ts ↔ 后端 JwtAuthFilter | `Authorization: Bearer ${token}` | 双方约定，不需配置 |

# 六、常见问题速查

| 现象 | 原因与解决 |
|---|---|
| 登录接口 500 | 后端未启动或数据库连接失败，查后端日志（循环依赖/密码错误均有明确日志） |
| 接口 404 | Nginx 缺 `/api/` 反代，或 `proxy_pass` 结尾缺 `/` 未去前缀 |
| 页面刷新 404 | 缺 `try_files $uri $uri/ /index.html;` SPA 回退 |
| Windows 打包报 Unable to rename jar | jar 被运行中进程锁定，先停服务再打包 |
| Maven 依赖下载慢 | 配置阿里云镜像（见 4.1） |
| npm install 慢/失败 | 切换 npmmirror 镜像源，删除 `node_modules` 与 `package-lock.json` 重装 |
| SQL 导入后中文乱码 | 导入命令漏了 `--default-character-set=utf8mb4`，或宝塔导入未选 utf8mb4 |
| 上传图片无法访问 | Nginx 缺 `/upload/` 反代，或 UPLOAD_DIR 与实际目录不一致 |
