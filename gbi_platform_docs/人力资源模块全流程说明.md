## 二、员工全生命周期流程

### 2.1 入职流程（审批驱动）

```
【发起】HR进入「人事异动 → 入职申请」页面
  ↓ 填写入职申请表单：
     - 基本信息：工号、姓名、身份证号、手机号、性别、出生日期
     - 用工信息：入职日期、用工类型（正式/试用期/劳务派遣/临时工）
     - 组织信息：所属组织、岗位、薪酬级别（P1~P5）
     - 薪资信息：基本工资、工资卡号
     - 其他：邮箱、备注
  ↓ 点击「提交」
  ↓ flowEngineService.submit()
     bizType = "hr_entry"
     流程定义：部门负责人审批 → HR审批
  ↓
【审批中】申请状态 = 1（审批中）
  前端显示：查看 / 撤销（草稿或审批中可撤销）
  ↓
  ├─【驳回】onReject()
  │     申请状态 = 3（已驳回）
  │     不生成员工档案，不生成薪资档案
  │     流程结束
  │
  └─【通过】onPass() → HrEntryFlowHandler.onPass()
        ↓
        1. 申请状态改为 2（已通过）
        2. createFromEntry(entryApplyId)
           a. 防重检查：同公司+同工号已存在则跳过
           b. 创建 hr_employee 员工档案
              - 复制所有字段（工号/姓名/身份证/手机/入职日期等）
              - employeeStatus = 1（在职）
              - orgId/postId 写入
              - basicSalary 写入
           c. 写入审计日志
        3. 自动生成 hr_salary_archive V1版本
           - sourceType = 1（模板自动生成）
           - versionNo = 1
           - 基本工资从入职申请带入
           - 津贴/绩效从匹配的工资模板带入
           - salaryGradeCode 快照当前薪级
           - isCurrent = 1
        4. 流程结束
```

> **关键设计**：入职申请审批通过后自动建档，无需HR手动新增员工档案。

### 2.2 转正流程

```
【发起】HR进入「人事异动 → 转正申请」页面
  ↓ 填写：员工ID、转正日期
  ↓ 提交审批（flowEngineService.submit）
  ↓
  ├─【驳回】状态 = 3，无变更
  │
  └─【通过】onRegularApproved()
        ↓
        1. 更新 hr_employee.employeeStatus = 2（试用期转正）
        2. 更新 hr_employee.regularDate = 申请转正日期
        3. 申请状态改为 2（已通过）
```

```
【发起】HR进入「人事异动 → 调岗申请」页面

  ↓ 提交审批
```

### 2.4 离职流程

```
【发起】HR进入「人事异动 → 离职申请」页面
  ↓ 填写：员工ID、离职日期、离职原因
  ↓ 提交审批
  ↓
```

## 三、考勤管理流程

### 3.1 数据流向

```
【数据来源】打卡设备 / 小程序 / OA系统
  ↓ 实时写入 oa_clock_record（OA时钟记录表）
  ↓
【每月同步】HR点击「同步考勤」按钮
  ↓ HrAttendanceService.syncMonthly(attendanceMonth)
  ↓ 从 oa_clock_record 聚合为 hr_attendance_record
     - 每日打卡时间（clockInTime / clockOutTime）
     - 迟到分钟数（lateMinutes）
     - 早退分钟数（earlyMinutes）
     - 缺勤标记（absent）
     - 工作日数（workDays）
     - 实际出勤天数（actualDays）
  ↓
【查询展示】考勤管理页面（/hr/attendance）
  - 可按员工ID + 考勤月份筛选
  - 支持导出Excel
```

### 3.2 考勤与算薪联动

```
月度算薪时，从 hr_attendance_record 读取：
  - actualDays → 计算日薪系数
  - lateMinutes / absent → 扣款金额
  叠加到 hr_salary_month 的 deductionAmount 字段
```

## 四、薪酬管理流程

### 4.1 薪酬级别配置（前置准备）

```
HR进入「薪酬级别」页面
  ↓ 配置各薪级带宽：
     P1：最低2000 / 中位3000 / 最高4000
     P2：最低3000 / 中位4500 / 最高6000
     P3：最低4000 / 中位6000 / 最高8000
     P4：最低6000 / 中位9000 / 最高12000
     P5：最低8000 / 中位12000 / 最高18000
  ↓ 保存 → 用于入职匹配和调薪带宽校验
```

### 4.2 薪资模板管理

```
HR进入「薪资模板」页面
  ↓ 创建模板，填写：
     - 模板名称
     - 绑定方式：绑定岗位 / 绑定薪级 / 岗位+薪级组合
     - 基本工资 / 绩效基数 / 岗位津贴 / 其他补贴
     - 社保个人比例（可为空，空则继承城市配置）
     - 公积金个人比例（可为空，空则继承城市配置）
  ↓ 点击「提交审批」
  ↓ flowEngineService.submit(bizType="salary_rule")
  ↓
  ├─【驳回】applyStatus = 2，可重新编辑
  │
  └─【通过】applyStatus = 1，模板生效
        → 可用于入职匹配、批量调薪筛选
```

### 4.3 薪资档案（版本化管理）

```
hr_salary_archive 表：每个员工多条版本记录共存

版本来源：
  sourceType=1  模板自动生成（入职时）
  sourceType=2  人工录入（HR手动调整）
  sourceType=3  批量调薪生成
  sourceType=4  晋升调级生成

版本控制逻辑：
  - 每次变更：旧版本 isCurrent=0，新版本 isCurrent=1
  - 旧版本 effective_end_date = 新版本 effective_date - 1天
  - 查询当前档案：WHERE isCurrent=1 AND company_id=?
  - 历史回溯：按 version_no 排序，可追溯任意历史版本
```

### 4.4 单人调薪流程

```
HR进入「薪资档案」页面，点击某员工「编辑」
  ↓ 修改基本工资/津贴等字段
  ↓ 保存 → 触发审批（flowEngineService.submit）
  ↓
  ├─【驳回】可重新编辑
  │
  └─【通过】SalaryArchiveFlowHandler.onPass()
        ↓
        1. 旧版本 isCurrent=0，effective_end_date = 生效前一日
        2. 生成新版本 isCurrent=1
           - versionNo = 旧版本 + 1
           - effective_date = 调薪生效日期
           - salaryGradeCode 快照当前薪级
           - adjustReason 记录调薪原因
        3. 写入审计日志
```

### 4.5 批量调薪流程

```
HR进入「批量调薪」页面
  ↓ 选择调薪方式：
     - 单员工
     - 勾选一批员工
     - 按部门筛选
     - 按岗位筛选
     - 按薪酬级别筛选（如全部P3员工）
     - 全员普调
  ↓ 填写调薪方式：
     - 固定值调整（如每人涨500元）
     - 百分比调整（如全员涨8%）
  ↓ 预览影响人数
  ↓ 保存草稿（status=0）
  ↓ 点击「提交审批」
  ↓ flowEngineService.submit(bizType="salary_batch_adjust")
  ↓
  ├─【驳回】status=2，可重新编辑
  │
  └─【通过】BatchAdjustFlowHandler.onPass()
        ↓
        遍历每个受影响员工：
          1. 带宽校验：新薪资是否在薪级带宽内（warnOnly=1则警告，=0则拦截）
          2. 旧版本 isCurrent=0
          3. 生成新版本 isCurrent=1
          4. 记录调薪原因
        ↓
        返回统计：总数 / 成功数 / 失败数
```

### 4.6 月度算薪流程

```
HR进入「薪酬管理 → 月度薪资」页面
  ↓ 选择核算月份（如 2026-09）
  ↓ 点击「生成薪资」
  ↓ HrSalaryServiceImpl.generateMonth()
     ↓
     遍历目标员工列表：
       1. 读取当前生效薪资档案（isCurrent=1）
          → basicSalary / performanceSalary / positionAllowance / otherAllowance
       2. 读取员工申报基数
          → hr_employee.social_declare_base / housing_fund_declare_base
       3. 读取城市费率配置
          → hr_social_param_config（按 city_code + 当月查询）
          → hr_housing_fund_config
       4. clamp 基数到上下限
          socialBase = clamp(declareBase, baseMin, baseMax)
          housingFundBase = clamp(declareBase, baseMin, baseMax)
       5. 计算各险种分项金额（个人+单位）
       6. 计算个税
          grossAmount = basic + perf + allowance
          socialTotal = sum(各险种个人部分)
          housingFundTotal = housingFundPersonal
          taxableIncome = grossAmount - socialTotal - housingFundTotal - 5000
          taxAmount = 累计预扣法查表计算
          netAmount = grossAmount - socialTotal - housingFundTotal - taxAmount
       7. 写入 hr_salary_month（月度核算单）
       8. 写入 hr_social_calc_detail（分项明细，含费率快照）
     ↓
HR查看月度薪资列表
  ↓ 逐条点击「发放」→ payMonth()
     - payStatus = 1（已发放）
     - 记录 payTime
     - 关联财务应收应付计划（planId）
     - 推送财务流水（finance_pay_flow）
```

> **现状问题**：当前 `generateMonth()` 直接读档案静态社保字段，未调用 `HrSocialCalcService.generateMonthSalary()`，导致 `hr_social_calc_detail` 表为空。

### 4.7 年终奖流程

```
HR进入「年终奖」页面
  ↓ 新增年终奖记录：
     - 员工 + 奖金年度 + 奖金类型 + 金额 + 原因
  ↓ 保存（applyStatus=1 草稿态，payStatus=0 未发放）
  ↓ 点击「提交审批」

  └─【通过】applyStatus=1 生效

        次年算薪时，年终奖叠加到对应月份：
          hr_salary_month.bonusAmount += yearBonus.bonusAmount
          grossAmount 相应增加
```

## 五、社保公积金流程

### 5.1 参数配置（平台菜单）

```
【城市字典】→ 录入各城市编码（BJ/GZ/SZ等）
【险种字典】→ 维护法定五险+长护险+补充福利
【行业字典】→ 维护行业分类（工伤保险按行业浮动）
  ↓
【社保参数配置】（/platform/socialParam）
  选择：城市 + 险种 + 行业（可选）
  填写：基数上下限 + 个人比例 + 单位比例
  点击「激活」→
    1. 关停旧记录（is_active=0）
    2. 新增新记录（is_active=1，period_start=今日）
    3. 审计日志记录两条操作
  ↓
【公积金参数配置】（/platform/housingFundConfig）
  选择：城市
  填写：基数上下限 + 个人比例 + 单位比例
  点击「激活」→ 同上逻辑
```

### 5.2 年度基数重算（每年7月）

```
HR进入「年度基数重算」页面
  ↓ 选择重算年度（如2025）
  ↓ 点击「执行重算」
  ↓ HrSocialCalcServiceImpl.triggerAnnualRecalc()
     遍历所有在职员工（employeeStatus IN 1,2）：
       1. 查询上年1-12月全部税前工资（hr_salary_month.grossAmount求和）
       2. 统计实际发薪月份数（payStatus=1的月份数）
       3. 月均工资 = 应发总额 / 实际发薪月份数
       4. 查询员工 city_code 对应的社保/公积金基数上下限
       5. 新社保基数 = clamp(月均工资, ss_min, ss_max)
       6. 新公积金基数 = clamp(月均工资, hf_min, hf_max)
       7. 更新 hr_employee：
          social_declare_base = 新社保基数
          housing_fund_declare_base = 新公积金基数
          base_effective_year = '2025'（有效期2025-07至2026-06）
       8. 写入审计日志
     ↓
     返回：总数 / 成功数 / 失败数 / 员工ID列表
```

> **新入职员工特殊处理**：首月无上年度数据，以首月税前应发工资作为临时基数。

## 六、关键数据关系

```
hr_employee（员工主档案）
  ├── 1:N → hr_salary_archive（薪资档案，版本化）
  │         查询当前档案：WHERE employee_id=? AND isCurrent=1
  │         查询历史版本：ORDER BY version_no DESC
  ├── 1:N → hr_attendance_record（考勤记录）
  ├── 1:N → hr_salary_month（月度薪资核算单）
  ├── 1:N → hr_social_calc_detail（社保核算明细）
  ├── 1:1 → hr_social_security（社保台账，已废弃）
  └── 1:1 → sys_user（系统账号，离职时禁用）

hr_salary_rule（薪资模板）
  └── N:1 → hr_salary_archive（员工档案引用模板ruleId）

hr_social_param_config（社保费率配置）
  └── 算薪时按 city_code + 当月日期查询（取is_active=1的记录）

hr_salary_grade（薪酬级别）
  └── 用于入职匹配和调薪带宽校验

hr_entry_apply / hr_regular_apply / hr_transfer_apply / hr_resign_apply
  └── 统一走 flow_engine 审批流
```

| 调岗申请 | hr_transfer | HR | HrTransferFlowHandler |
| 离职申请 | hr_resign | HR → 财务 | HrResignFlowHandler |
| 薪资模板 | salary_rule | HR负责人 | SalaryRuleFlowHandler |
| 单人调薪 | salary_archive | 部门负责人 → HR | SalaryArchiveFlowHandler |
| 批量调薪 | salary_batch_adjust | HR负责人 | BatchAdjustFlowHandler |
| 年终奖 | salary_year_bonus | HR负责人 | YearBonusFlowHandler |

> 审批中心统一入口：`/flow/task/page`（待办列表）

## 八、当前断点与问题汇总

| 环节 | 状态 | 问题描述 |
|------|------|---------|
| 入职→建档 | ✅ 正常 | 审批通过后自动创建员工档案 |
| 入职→自动生成V1薪资档案 | ⚠️ 缺失 | `createFromEntry()` 未生成薪资档案V1 |
| 月度算薪 | ⚠️ 不完整 | `generateMonth()` 不调用核算服务，社保字段来自档案静态快照 |
| 社保分项明细 | ❌ 空 | `generateMonthSalary()` 是 TODO，`hr_social_calc_detail` 无数据 |
| 社保台账 | ⚠️ 废弃中 | `hr_social_security` 手工台账与自动核算并行，数据不一致 |
| 年终奖→月度叠加 | ⚠️ 未验证 | 年终奖审批通过后是否自动并入当月薪资待确认 |
| 档案含动态字段 | ⚠️ 设计缺陷 | `hr_salary_archive` 含 socialSecurityPersonal/housingFundPersonal 静态字段，应与核算分离 |

## 九、标准业务场景示例

### 场景A：新员工入职到首次发薪

```
Day 1：HR提交入职申请（P3薪级，基本工资8000）
Day 3：审批通过 → 自动创建员工档案 + 薪资档案V1
Day 15：员工开始打卡
Month end：HR同步考勤 → 生成月度考勤记录
Next month 5日：HR执行年度基数重算（首年无数据，以首月工资8000为基数）
Next month 10日：HR生成月度薪资
  → 读取档案V1：basicSalary=8000
  → 查城市费率：养老8%/医疗2%/失业0.5%/公积金12%
  → 计算社保个人=8000×10.5%=840，公积金个人=8000×12%=960
  → 应纳税所得额=8000-840-960-5000=200
  → 个税=200×3%=6
  → 实发=8000-840-960-6=6194
  → 写入 hr_salary_month + hr_social_calc_detail
Next month 15日：HR点击发放 → 推送财务流水
```

### 场景B：员工调岗+调薪

```
HR提交调岗申请（新岗位+新组织）
  → 审批通过 → 更新 hr_employee.orgId/postId
HR提交调薪申请（基本工资8000→9000）
  → 带宽校验：9000在P3带宽[4000,8000]外 → 警告但允许（warnOnly=1）
  → 审批通过 → 生成薪资档案V2（isCurrent=1），V1（isCurrent=0）
次月算薪 → 读取V2档案，基本工资9000
```

### 场景C：年度基数重算

```
每年7月1日，HR手动触发年度基数重算
  → 取2025年全年12个月税前工资求和
  → 月均 = 总和 / 12
  → clamp到城市上下限
  → 更新所有在职员工的 social_declare_base / housing_fund_declare_base
  → base_effective_year = '2025'
8月算薪 → 使用新的申报基数计算社保公积金
```
