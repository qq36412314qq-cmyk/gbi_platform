## 一、需求背景与现状分析

### 1.1 当前页面现状

**文件路径：** `gbi_platform_admin/src/views/business/property/stallCanvas.vue`

| 维度 | 现状描述 |
|------|---------|
| 数据源 | 硬编码常量 `sampleStalls`（14条示例数据），无真实业务数据接入 |
| 交互能力 | 仅支持缩放、平移、点击查看详情，无编辑/绘制能力 |
| 持久化 | 无任何保存接口，刷新页面数据全部丢失 |
| 渲染方式 | 纯 SVG `<rect>` 渲染矩形铺位 |
| 通道支持 | 通道为硬编码 `<rect>` + `<text>`，不可配置 |
| 颜色配置 | 铺位颜色按 status 状态固定映射，无自定义能力 |

**当前代码结构（核心片段）：**

```typescript
// 硬编码示例数据（第xx行）
const sampleStalls: SampleStall[] = [
  { id: 1, number: 'A-001', x: 120, y: 120, w: 180, h: 100, ... },
  // ... 共14条
]

// 无API调用，无保存逻辑
```

### 1.2 核心诉求

用户希望通过页面鼠标手绘方式，实现以下能力：

1. **新增铺位**：在画布上拖拽绘制矩形，填写基本信息后保存
2. **编辑铺位**：拖拽移动位置、调整尺寸、修改颜色、绑定链接
3. **删除铺位**：选中后删除（逻辑删除）
4. **通道配置**：可添加/移动通道元素，支持自定义颜色名称
5. **自定义配色**：支持单个铺位自定义背景色、画布全局背景色
6. **数据持久化**：所有布局变更保存到数据库，下次打开自动恢复
7. **状态驱动配色**：铺位颜色根据租赁使用状态（空置/已租/欠费/即将到期）自动配置不同颜色
8. **关联业务数据**：点击铺位可快速查看租户、合同、水电费、物业费、缴费记录等关联信息

## 二、技术方案选型

### 2.1 方案对比

| 方案 | 技术栈 | 优点 | 缺点 | 适用场景 |
|------|--------|------|------|---------|
| **Fabric.js** | fabric@^5.3.0（项目已有依赖） | 功能完整，支持矩形/多边形/自由绘制/顶点编辑 | 需引入组件库，学习成本中等 | 不规则形状支持需求明确 |
| SVG原生 + 鼠标事件 | 无额外依赖 | 轻量，与现有代码无缝衔接 | 不规则形状需自行实现 | 仅矩形铺位 |
| Konva.js | konva@^9.x | 性能好，2D交互强 | 需替换现有SVG渲染层 | 大型画布（>500元素） |

### 2.2 选型结论

**推荐方案：Fabric.js（项目已有依赖规范）**

依据：
1. 《前端视图页面开发规范》第十三章明确规定：**固定依赖 `fabric:^5.3.0`，禁止接入高德/百度GIS地图**
2. 现有规范已定义 `MarketCanvas.vue` 组件架构和 `fabricUtil.ts` 工具类
3. Fabric.js 原生支持顶点编辑、自由绘制、撤销重做、导出PNG等能力
4. 项目目录结构中已规划 `src/components/business/MarketCanvas.vue`

### 2.3 混合渲染策略

为兼容现有 SVG 渲染层，采用**渐进式迁移**策略：

- **Phase 1**：保持 SVG 渲染，增加拖拽/缩放/删除交互（快速上线）
- **Phase 2**：引入 Fabric.js 替换渲染层，支持不规则形状和顶点编辑（按需升级）

## 三、数据库设计

### 3.1 状态驱动配色配置方案

**设计理念：** 铺位颜色以 `status` 状态为核心驱动，支持全局默认配色 + 单个铺位覆盖，实现「业务状态 → 视觉颜色」的自动映射。

**颜色配置优先级：**
```
canvas_color（铺位自定义色）> default_stall_colors[status]（状态默认色）> 硬编码兜底色
```

**状态颜色映射表（默认值，可配置）：**

| status | 状态名称 | 默认背景色 | 默认边框色 | 语义说明 |
|--------|---------|-----------|-----------|---------|
| 0 | 空置 | #1a3a2a | #2d8a5f | 绿色系，表示空闲可用 |
| 1 | 已租 | #3a2a1a | #c88a3a | 橙色系，表示已出租 |
| 2 | 欠费 | #3a1a1a | #c83a3a | 红色系，表示费用拖欠 |
| 3 | 即将到期 | #2a2a3a | #5a5ac8 | 蓝色系，表示合同临近到期 |

**`property_canvas_config` 表新增颜色配置字段：**

```sql
-- 在 property_canvas_config 表中增加以下字段（如表不存在则新建）
ALTER TABLE property_canvas_config
  ADD COLUMN default_stall_colors json NOT NULL DEFAULT '{"0":"#1a3a2a","1":"#3a2a1a","2":"#3a1a1a","3":"#2a2a3a"}' COMMENT '状态默认颜色映射JSON',
  ADD COLUMN status_stroke_colors json NOT NULL DEFAULT '{"0":"#2d8a5f","1":"#c88a3a","2":"#c83a3a","3":"#5a5ac8"}' COMMENT '状态边框颜色映射JSON';
```

**颜色计算逻辑（后端 VO 层）：**

```java
/**
 * 计算铺位渲染颜色（优先级：自定义 > 状态默认 > 兜底）
 */
public String resolveStallColor(StallCanvasVO stall, CanvasConfig config) {
    // 1. 优先使用铺位自定义颜色
    if (StringUtils.isNotBlank(stall.getCanvasColor())) {
        return stall.getCanvasColor();
    }
    
    // 2. 使用状态默认颜色
    String statusKey = String.valueOf(stall.getStatus());
    Map<String, String> defaultColors = config.getDefaultStallColors();
    if (defaultColors != null && defaultColors.containsKey(statusKey)) {
        return defaultColors.get(statusKey);
    }
    
    // 3. 兜底色（灰色）
    return "#1a2a3a";
}

public String resolveStallStrokeColor(StallCanvasVO stall, CanvasConfig config) {
    if (StringUtils.isNotBlank(stall.getCanvasColor()) && isStrokeColorConfigured(stall)) {
        return stall.getCanvasStrokeColor();
    }
    String statusKey = String.valueOf(stall.getStatus());
    Map<String, String> strokeColors = config.getStatusStrokeColors();
    return strokeColors != null && strokeColors.containsKey(statusKey) 
        ? strokeColors.get(statusKey) 
        : "#3a6a8a";
}
```

**前端颜色应用：**

```typescript
// stallCanvas.vue - 颜色解析逻辑
function getStallFill(stall: StallCanvasVO, config: CanvasConfig): string {
  // 优先使用自定义颜色
  if (stall.canvasColor) return stall.canvasColor
  // 其次使用状态默认颜色
  return config.defaultStallColors[String(stall.status)] ?? '#1a2a3a'
}

function getStallStroke(stall: StallCanvasVO, config: CanvasConfig): string {
  if (stall.canvasStrokeColor) return stall.canvasStrokeColor
  return config.statusStrokeColors[String(stall.status)] ?? '#3a6a8a'
}
```

**实时颜色更新场景：**

| 业务操作 | 触发动作 | 颜色变化 |
|---------|---------|---------|
| 合同签订生效 | `stall_contract` 状态变更 → `stall_info.status=1` | 空置绿 → 已租橙 |
| 合同到期 | `stall_contract` 到期 → `stall_info.status=0` | 已租橙 → 空置绿 |
| 产生欠费 | `property_fee_bill.payStatus=0` 且超期 | 已租橙 → 欠费红 |
| 缴费完成 | `finance_pay_flow` 写入 → 账单已缴 | 欠费红 → 已租橙 |
| 合同临近到期 | `stall_contract.endTime` 距今天数 ≤ 30 | 已租橙 → 即将到期蓝 |

> **说明：** 颜色由后端在查询时实时计算，不存储冗余颜色字段到 `stall_info`，确保颜色与业务状态始终一致。

### 3.2 方案A：扩展 `property_stall_info` 表（推荐一期采用）

**理由：** 铺位坐标属于铺位属性，与业务主数据强耦合，存储在主体表中最符合单一职责原则。

```sql

  ADD COLUMN canvas_width      int         NOT NULL DEFAULT 0  COMMENT '画布宽度(px)',
  ADD COLUMN canvas_height     int         NOT NULL DEFAULT 0  COMMENT '画布高度(px)',
```

#### 3.5.3 后端查询逻辑

```java
/**
 * 获取铺位画布详情（聚合租户/合同/账单/缴费记录）
 */
public StallCanvasDetailVO getStallCanvasDetail(Long stallId, Long companyId) {
    // 1. 查询铺位基础信息
    StallInfo stall = stallInfoMapper.selectById(stallId);
    if (stall == null || !companyId.equals(stall.getCompanyId())) {
        throw new BizException("铺位不存在或无权限访问");
    }
    
    // 2. 查询租户信息
    StallTenant tenant = stallTenantMapper.selectOne(
        new LambdaQueryWrapper<StallTenant>()
            .eq(StallTenant::getCompanyId, companyId)
            .eq(StallTenant::getStatus, 1)
            .orderByDesc(StallTenant::getCreateTime)
            .last("LIMIT 1")
    );
    
    // 3. 查询生效中合同
    StallContract contract = stallContractMapper.selectOne(
        new LambdaQueryWrapper<StallContract>()
            .eq(StallContract::getStallId, stallId)
            .eq(StallContract::getCompanyId, companyId)
            .in(StallContract::getContractStatus, 0, 1) // 签约中/生效中
            .orderByDesc(StallContract::getCreateTime)
            .last("LIMIT 1")
    );
    
    // 4. 计算欠费汇总
    BillSummaryDTO billSummary = calcBillSummary(stallId, companyId);
    
    // 5. 查询近期缴费记录（finance_pay_flow）
    List<BizFinanceFlow> recentPayments = financeFlowMapper.selectList(
        new LambdaQueryWrapper<BizFinanceFlow>()
            .eq(BizFinanceFlow::getStallId, stallId)
            .eq(BizFinanceFlow::getCompanyId, companyId)
            .eq(BizFinanceFlow::getFlowType, 1) // 仅收入
            .eq(BizFinanceFlow::getStatus, 1)
            .orderByDesc(BizFinanceFlow::getCreateTime)
            .last("LIMIT 10")
    );
    
    // 6. 查询未缴账单（统一账单表）
    List<BizFeeBill> unpaidBills = feeBillMapper.selectList(
        new LambdaQueryWrapper<BizFeeBill>()
            .eq(BizFeeBill::getStallId, stallId)
            .eq(BizFeeBill::getCompanyId, companyId)
            .in(BizFeeBill::getPayStatus, 0, 1) // 待缴/部分缴费
            .orderByDesc(BizFeeBill::getBillMonth)
            .last("LIMIT 3")
    );
    
    // 7. 组装 VO
    return buildDetailVO(stall, tenant, contract, billSummary, recentPayments, unpaidBills);
}

/**
 * 计算欠费汇总
 */
private BillSummaryDTO calcBillSummary(Long stallId, Long companyId) {
    // 从 finance_fee_pay_bill 汇总未缴金额
    BigDecimal totalUnpaid = feeBillMapper.selectSum(
        "SELECT COALESCE(SUM(real_amount), 0) FROM finance_fee_pay_bill " +
        "WHERE stall_id = #{stallId} AND company_id = #{companyId} " +
        "AND pay_status IN (0, 1) AND is_delete = 0"
    );
    
    Integer unpaidCount = feeBillMapper.selectCount(
        "SELECT COUNT(*) FROM finance_fee_pay_bill " +
        "WHERE stall_id = #{stallId} AND company_id = #{companyId} " +
        "AND pay_status = 0 AND is_delete = 0"
    );
    
    // 计算最晚逾期天数
    Integer overdueDays = calculateMaxOverdueDays(stallId, companyId);
    
    return BillSummaryDTO.builder()
        .totalUnpaidAmount(totalUnpaid)
        .unpaidBillCount(unpaidCount)
        .overdueDays(overdueDays)
        .build();
}
```

```typescript
// stallCanvas.vue 核心逻辑

// 页面加载时获取数据
async onMounted() {
  // 1. 获取画布配置
  canvasConfig.value = await getCanvasConfigApi(marketId)
  
  // 2. 获取铺位坐标数据
  const stalls = await getCanvasStallsApi(marketId)
  canvasStalls.value = stalls
  
  // 3. 初始化视图
  initCanvasView(stalls)
}

// 拖拽移动逻辑
function onMouseDown(e: MouseEvent, stall: StallCanvasVO) {
  if (e.button !== 0) return // 仅左键
  
  selectedStall.value = stall
  isDragging.value = true
  dragOffset.value = {
    x: e.clientX - stall.canvasX,
    y: e.clientY - stall.canvasY
  }
}

function onMouseMove(e: MouseEvent) {
  if (!isDragging.value || !selectedStall.value) return
  
  const newX = e.clientX - dragOffset.value.x
  const newY = e.clientY - dragOffset.value.y
  
  // 边界限制
  const boundedX = Math.max(0, Math.min(maxX, newX))
  const boundedY = Math.max(0, Math.min(maxY, newY))
  
  // 实时更新显示（不立即保存）
  selectedStall.value.canvasX = boundedX
  selectedStall.value.canvasY = boundedY
}

function onMouseUp() {
  if (!isDragging.value) return
  
  isDragging.value = false
  
  // 保存变更
  if (selectedStall.value) {
    saveStallCanvasApi({
      stallId: selectedStall.value.id,
      canvasX: selectedStall.value.canvasX,
      canvasY: selectedStall.value.canvasY,
      canvasWidth: selectedStall.value.canvasWidth,
      canvasHeight: selectedStall.value.canvasHeight
    })
    
    // 压入撤销历史
    pushHistory()
  }
}

// 删除逻辑
function deleteSelectedStall() {
  if (!selectedStall.value) return
  
  ElMessageBox.confirm(
    `确定删除铺位「${selectedStall.value.stallNumber}」吗？`,
    '提示',
    { type: 'warning' }
  ).then(async () => {
    await deleteStallApi(selectedStall.value!.id)
    canvasStalls.value = canvasStalls.value.filter(s => s.id !== selectedStall.value!.id)
    selectedStall.value = null
    ElMessage.success('删除成功')
  }).catch(() => {})
}

// 撤销/重做逻辑
function undo() {
  if (historyIndex.value <= 0) return
  
  historyIndex.value--
  const prevState = history.value[historyIndex.value]
  restoreState(prevState)
}

function redo() {
  if (historyIndex.value >= history.value.length - 1) return
  
  historyIndex.value++
  const nextState = history.value[historyIndex.value]
  restoreState(nextState)
}
```

```
│  │  - canvas_rotation                                      │   │
│  │  - canvas_color                                         │   │
│  │  - canvas_link_url                                      │   │
│  │  - canvas_layout_json                                   │   │
│  └─────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────┘
```

### 6.2 数据同步策略

| 场景 | 同步策略 | 说明 |
|------|---------|------|
| 页面加载 | 全量拉取 | 获取当前市场全部铺位坐标 + 配置 |
| 拖拽结束 | 实时单条保存 | 每次松手后立即调用 `save-single` |
| 批量调整 | 延迟批量保存 | 用户明确点击「保存布局」后调用 `save-batch` |
| 新建铺位 | 事务内创建+保存 | 一次API调用完成创建和初始化 |
| 删除铺位 | 逻辑删除 | 调用现有 `deleteStallApi`，同时从画布移除 |

## 七、风险评估与注意事项

### 7.1 技术风险

| 风险项 | 风险等级 | 影响 | 应对方案 |
|--------|---------|------|---------|
| 并发编辑冲突 | 低 | 两个用户同时编辑同一市场布局，后者覆盖前者 | 采用最后写入覆盖策略，铺位布局非核心财务数据，不强一致性 |
| 坐标数据溢出 | 低 | canvas_width/height 过大导致数据库存储异常 | 字段类型 int，限制最大 10000px，前端校验范围 |
| JSON 注入攻击 | 中 | 前端传入恶意 JSON 脚本 | 后端对 `canvas_layout_json` 字段进行 XSS 过滤，使用 Jackson 序列化 |
| 撤销历史内存泄漏 | 低 | 长时间操作导致 history 数组无限增长 | 限制 maxHistory=50，超过后自动清理旧记录 |
| 大数据量渲染性能 | 中 | 铺位超过300个时 SVG 渲染卡顿 | 启用分页渲染或虚拟滚动，或切换到 Canvas 渲染 |

### 7.2 业务风险

| 风险项 | 风险等级 | 影响 | 应对方案 |
|--------|---------|------|---------|
| 坐标与面积单位不一致 | 低 | 画布坐标(px)与实际面积(㎡)无换算关系，可能导致误解 | 明确标注坐标单位为像素，面积独立存储，两者无换算关系 |
| 删除铺位后坐标残留 | 低 | 逻辑删除后坐标字段仍保留 | 删除时清空坐标字段（设为默认值0）或保留以便恢复 |
| 通道与铺位重叠 | 中 | 拖拽通道时可能覆盖铺位 | 增加碰撞检测，重叠时提示用户或自动吸附 |
| 多版本布局冲突 | 中 | 若采用方案B，多版本之间可能存在数据不一致 | 版本切换时校验铺位数量一致性，不一致时提示 |

### 7.3 安全合规风险

| 风险项 | 风险等级 | 影响 | 应对方案 |
|--------|---------|------|---------|
| 跨租户数据泄露 | 高 | 未正确隔离 company_id，用户可访问其他公司数据 | MyBatis-Plus 自动填充 company_id，后端强制校验 |
| 敏感操作无审计 | 中 | 坐标修改未记录操作日志 | 所有保存操作写入 `sys_audit_log`，记录操作人/IP/前后快照 |
| XSS 脚本注入 | 中 | 前端传入含 `<script>` 的 JSON | 后端使用 `StringEscapeUtils.escapeJson()` 过滤特殊字符 |
| 未授权访问 | 高 | 无权限用户调用编辑接口 | 接口增加 `@PreAuthorize("hasAuthority('property:canvas:edit')")` |

## 八、不足之处与待确认事项

### 8.1 设计不足之处

| 不足项 | 说明 | 改进方向 |
|--------|------|---------|
| **不规则形状支持不完整** | 当前方案仅通过 `canvas_layout_json` 预留字段支持，未实现顶点编辑UI | Phase 2 引入 Fabric.js，原生支持多边形顶点拖拽 |
| **撤销历史未持久化** | 当前历史栈仅存于内存，刷新页面后丢失 | 可选：将最近N步操作序列化为 JSON 存入 localStorage，页面加载时恢复 |
| **通道元素未数据化** | 当前方案中通道仍为独立元素，未与铺位统一存储 | 建议纳入 `property_canvas_layout` 表统一管理（方案B） |
| **实时协作不支持** | 当前设计无 WebSocket 实时同步能力，多人同时编辑会冲突 | 如需实时协作，需引入 WebSocket + 操作增量同步协议（CRDT） |
| **画布底图不支持** | 当前方案未考虑上传 Floor Plan 图片作为底图 | 可扩展：增加 `market_canvas_background` 字段存储底图 URL |
| **移动端不支持** | 当前交互依赖鼠标事件，移动端无法使用 | 可后续适配触摸事件，或引导用户使用 PC 端编辑 |

### 8.2 待确认疑问清单

| 序号 | 问题 | 影响范围 | 优先级 |
|------|------|---------|--------|
| Q1 | 是否需要支持不规则形状（L型、U型等多边形铺位）？ | 数据库字段设计、前端渲染方案 | 高 |
| Q2 | 是否需要同一市场保存多个布局版本（如装修前后对比）？ | 方案A vs 方案B 表结构设计 | 中 |
| Q3 | 通道元素是否需要与铺位统一存储，还是保持独立？ | 数据库表设计、查询逻辑 | 中 |
| Q4 | 画布底图是否需要支持上传（如建筑平面图）？ | 前端资源管理、后端存储 | 低 |
| Q5 | 是否需要实时多人协作编辑？ | 架构复杂度大幅上升 | 低 |
| Q6 | 新建铺位时，坐标是手动输入还是拖拽绘制？ | 前端交互设计 | 高 |
| Q7 | 铺位删除后，是否保留坐标数据以便恢复？ | 数据清理策略 | 低 |
