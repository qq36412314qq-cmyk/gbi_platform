## 二、关键节点详细说明

### 节点1 创建订单（合同签订）

触发入口 LeaseContractController.add()
触发时机 操作人员签订租赁合同
数据产出 stall_contract 主表, biz_fee_bill 待缴账单
关键逻辑 根据铺位绑定的收费规则计算金额, 自动生应收应付计划

状态 biz_fee_bill.pay_status = 0 待缴

### 节点2 未支付订单展示

触发入口 unpaidBill.vue
数据来源 PropertyFeeController.getUnpaidBillPage() biz_fee_bill 查询
展示字段 业务类型, 账单月份, 绑定铺位, 金额, 缴费状态, 创建时间
操作按钮 单条缴费, 合并缴费

### 节点3 合并缴费（创建缴费单）

触发入口 用户勾选多条账单 点击合并缴费
接口 POST /property/payBill/create
请求参数 bizFeeBillIds 选中的 biz_fee_bill ID 列表

处理逻辑
1. 批量查询 biz_fee_bill 验证 pay_status=0 1
2. 校验同一铺位 同一公司
3. 生成缴费单编号 PY+公司编码+日期+序号
4. 创建 biz_pay_bill total_amount = Sigma(real_amount - paid_amount)
5. 为每条 biz_fee_bill 创建 biz_pay_bill_item 快照固化 fee_item_name rule_name
6. 更新 biz_fee_bill.pay_bill_id = 新缴费单ID
7. 返回缴费单ID和编号

前端交互
创建成功后 弹出缴费单预览弹窗
展示 缴费单编号, 总金额, 各收费明细列表
用户确认 跳转缴费页或内联展开缴费表单

### 节点4 支付确认（缴费）

触发入口 用户操作员点击确认支付

4.1 旧接口兼容 单条缴费
接口 POST /property/unifiedPay/pay
请求参数 billId=biz_fee_bill.id, billType=rent, payType=3, requestId 幂等ID
处理流程 幂等检查 -> findOrCreateBizBill -> payRent/payDeposit -> 创建 biz_finance_flow -> 更新 biz_fee_bill.pay_status=1 -> 核销计划

4.2 新接口 缴费单聚合缴费
接口 POST /property/payBill/pay
请求参数 payBillId=biz_pay_bill.id, payType=3, requestId
处理流程
1. 查询 biz_pay_bill 校验 pay_status in 0,1
2. 幂等检查
3. 创建 biz_finance_flow pay_bill_id=缴费单ID
4. 更新 biz_pay_bill paid_amount unpaid_amount pay_status
5. 更新各 biz_pay_bill_item paid_amount 按比例分摊
6. 更新各 biz_fee_bill pay_status
7. 核销应收应付计划
8. 返回流水单号

### 节点5 完成支付（状态确认）

状态流转
biz_fee_bill 0待缴 -> 1部分缴费 -> 2已缴
biz_pay_bill 0待缴 -> 1部分缴费 -> 2已缴 -> 3已退费
biz_finance_flow 创建收入流水 flow_type=1
biz_finance_writeoff 创建核销记录

前端反馈
缴费成功 toast提示 缴费成功
跳转刷新未支付订单列表
已缴费记录标记为已缴或隐藏

## 五、数据流向总结

合同创建
stall_contract -> LeaseContractService.add()
-> biz_fee_bill pay_status=0
-> biz_recv_pay_plan 生成应收计划

未支付订单展示
biz_fee_bill -> PropertyFeeController.getUnpaidBillPage()
-> unpaidBill.vue 列表展示

合并缴费
用户勾选 biz_fee_bill[] -> POST /payBill/create
-> biz_pay_bill 聚合创建
-> biz_pay_bill_item[] 快照固化
-> biz_fee_bill.pay_bill_id = 新ID

支付确认
用户点击确认支付 -> POST /payBill/pay 或 /unifiedPay/pay
-> biz_finance_flow 收入流水
-> biz_pay_bill.paid_amount += 支付金额
-> biz_pay_bill.pay_status 更新
-> biz_pay_bill_item.paid_amount += 分摊金额
-> biz_fee_bill.pay_status = 1/2

退费
用户点击退费 -> POST /payBill/refund
-> biz_finance_flow 支出流水 flow_type=2
-> biz_pay_bill.paid_amount -= 退费金额
-> biz_pay_bill.pay_status 回退
-> biz_fee_bill.pay_status 回退

冲红
操作员申请冲红 -> POST /payBill/redFlush
-> biz_finance_flow 反向流水 flow_status=2
-> 原流水 flow_status=3 red_flush_flow_id=新流水ID
-> biz_pay_bill 状态回退

作废
操作员作废 -> POST /payBill/void
-> biz_pay_bill.pay_status=5 仅待缴状态
-> 逻辑删除 item 记录

## 七、关键设计决策说明

7.1 为什么缴费单不提前创建

决策 缴费单在用户点击合并缴费时动态聚合创建 而非合同签订时创建
原因
1. 合同签订时可能只生成单条账单 用户可能只缴单条
2. 合并缴费是用户行为驱动的 不应预生成
3. 避免大量空缴费单占用数据空间
4. 缴费单是支付载体 不是业务单据

7.2 为什么保留 biz_fee_bill 独立存在

决策 不删除 biz_fee_bill 仅新增 pay_bill_id 关联字段
原因
1. biz_fee_bill 是收费规则的产物 具有独立的业务语义
2. 历史数据兼容 存量 biz_fee_bill 无 pay_bill_id NULL
3. 单条缴费场景仍需 biz_fee_bill 作为载体
4. 双表并行保证平滑迁移

7.3 为什么财务流水关联缴费单而非账单

决策 biz_finance_flow.pay_bill_id 指向缴费单
原因
1. 用户感知的是 我缴了一张单 而非 我缴了N条账单
2. 聚合支付时 一条流水对应一个缴费动作
3. 便于对账 缴费单编号 = 用户凭证编号
4. 旧流水 pay_bill_id=NULL 过渡期兼容

## 八、测试用例清单

8.1 正常流程

TC01 单条缴费 未支付订单勾选1条 缴费 确认
预期 biz_fee_bill.pay_status=2 生成1条流水

TC02 合并缴费 勾选3条 合并缴费 确认
预期 生成1张缴费单 3条item 1条流水

TC03 部分缴费 缴费单总金额5000 先缴2000 再缴3000
预期 pay_status=1->2 unpaid_amount=0

TC04 全额退费 已缴费单 退费全额
预期 pay_status=3 生成支出流水

TC05 部分退费 已缴费单 退费部分金额
预期 pay_status=1 unpaid_amount恢复

8.2 异常流程

TC06 重复缴费 同一 requestId 重复提交
预期 返回幂等错误 不生成重复流水

TC07 已缴清再缴费 缴费单已缴清 再次缴费
预期 提示 该缴费单已缴清

TC08 已退费再缴费 缴费单已退费 再次缴费
预期 提示 该缴费单已退费

TC09 跨公司合并 勾选不同公司的账单 合并
预期 提示 不能跨公司合并缴费

TC10 已缴账单合并 勾选已缴账单 合并
预期 提示 已缴账单不可合并

8.3 冲红作废

TC11 冲红申请 正常流水 申请冲红
预期 原流水flow_status=3 新反向流水flow_status=2

TC12 冲红审批 冲红中流水 审批通过
预期 反向流水flow_status=1 缴费单状态回退

TC13 作废待缴 待缴费单 作废
预期 pay_status=5 item逻辑删除

TC14 已缴不可作废 已缴费单 尝试作废
预期 提示 已缴费单不可作废
