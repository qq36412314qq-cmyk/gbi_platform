# 移动端二维码部署方案

> 版本：v1.1  
> 日期：2026-09-08  
> 适用范围：gbi_platform 集团多业态一体化管控系统

---

## 一、背景与目标

当前系统已具备完善的 PC 管理后台（Vue3 + Element Plus），但一线运维人员缺少移动端触达入口。  
本方案通过在铺位/巡检设备上贴附二维码，实现 **扫码即用**，覆盖两大核心场景：

1. **铺位信息查看**：扫码获取铺位基础信息、租赁状态、欠费提醒等只读数据。
2. **巡检记录查看**：扫码查看该巡检点的历史巡检记录（只读，不提交新数据）。

---

## 二、技术选型

| 层 | 方案 | 选型说明 |
|---|---|---|
| 后端二维码生成 | Hutool `QrCodeUtil` | Hutool 已引入，零依赖新增 |
| 移动端展示页 | PWA 页面（Vue3 + Vant），内嵌于现有前端项目 | 无需开发独立 App，微信/浏览器均可访问 |
| 二维码内容格式 | `https://域名/m/stall/{stallId}` 或 `/m/inspect/{equipmentId}` | 短路径，易解析 |

**推荐**：不引入新框架，复用现有 `gbi_platform_admin` 项目，新增移动端路由模块，PWA 渐进增强。

## 四、方案一：铺位二维码

### 4.1 二维码内容

- **格式**：`https://{域名}/m/stall/{stallId}`
- **示例**：`https://gbi.example.com/m/stall/15`
- **生成方式**：PC 管理后台「铺位管理」页新增「生成二维码」按钮，批量导出打印

### 4.2 后端接口设计

**新增 Controller**：`MobileStallController`  
路径前缀：`/m/stall`

| 接口 | 方法 | 说明 | 权限 |
|---|---|---|---|
| `/m/stall/{id}` | GET | 获取铺位详情（公开） | 无需登录 |

**返回 VO**（精简版，不含敏感信息）：

```java
public class StallMobileVO {
    private Long id;
    private String stallNumber;   // 铺位编号
    private String stallName;     // 铺位名称
    private String marketName;    // 市场名称
    private String categoryName;  // 分类名称（商铺/仓库/车位）
    private BigDecimal stallArea; // 面积（平方米）
    private Integer status;       // 0空置 1已租 2欠费 3即将到期
    private String statusText;    // 状态文字
    private String remark;        // 备注
    private Integer hasContract;  // 是否有有效合同（1有/0无）
}
```

**安全策略**：
- 该接口为**公开接口**，不校验 token，但强制携带 `company_id` 上下文（从 JWT 解析，若无可查 DB 中该铺位的 companyId）
- 防止越权：查询时强制按铺位自身的 `company_id` 过滤，不允许跨公司访问

### 4.3 前端移动端页面设计

**新增路由**：`/m/stall/:id`  
**技术**：复用 `gbi_platform_admin`，新增 `src/views/mobile/` 目录，使用 Vant 组件库替代 Element Plus（移动端更轻量）

**页面结构**：
```
┌─────────────────────┐
│  ← 返回              │
├─────────────────────┤
│   [铺位编号] 商铺A-101 │  ← 顶部状态色块（空置=绿色/已租=蓝色/欠费=红色）
├─────────────────────┤
│ 基本信息              │
│  市场：XX商业广场      │
│  分类：商铺           │
│  面积：85.30㎡        │
│  状态：已租           │
├─────────────────────┤
│ 合同信息（有合同才展示） │
│  租户：张三           │
│  合同期：2025-01-01   │
│            至 2026-12-31│
├─────────────────────┤
│ 备注                 │
│  无                  │
└─────────────────────┘
```

### 4.4 批量生成与导出

- PC 后台新增「批量生成二维码」功能：选中多个铺位 → 点击生成 → 下载 PNG 批量打印
- 技术方案：前端使用 `qrcode` npm 包，传入 URL 生成独立图片，多张打包为 PDF 或 zip 导出

## 五、方案二：巡检记录查看（只读）

> 注：本方案仅支持扫码查看历史巡检记录，不包含巡检数据提交功能。巡检数据由 PC 后台统一管理。

### 5.1 二维码内容

- **格式**：`https://{域名}/m/inspect/{equipmentId}`
- **示例**：`https://gbi.example.com/m/inspect/88`
- **设备码生成**：按设备序列号或 UUID 生成，贴在设备机身/巡检点

### 5.2 后端接口设计

**新增 Controller**：`MobileInspectController`  
路径前缀：`/m/inspect`

| 接口 | 方法 | 说明 | 权限 |
|---|---|---|---|
| `/m/inspect/{id}` | GET | 获取巡检点信息及历史巡检记录列表（公开） | 无需登录 |

**返回 VO**：

```java
public class InspectMobileVO {
    private Long equipmentId;
    private String equipCode;       // 设备二维码码值
    private String equipName;       // 设备名称
    private String equipType;       // 设备类型（消防/电力/安防/其他）
    private String location;        // 安装位置
    private LocalDateTime lastInspectTime;  // 上次巡检时间
    private Integer lastInspectResult;      // 上次巡检结果（1正常/2异常）
    private List<InspectRecordVO> history;  // 历史巡检记录列表
}

public class InspectRecordVO {
    private LocalDateTime inspectTime;  // 巡检时间
    private String inspectorName;       // 巡检人姓名
    private Integer result;             // 结果（1正常/2异常）
    private String remark;              // 异常描述
    private List<String> photoUrls;     // 现场照片
}
```

**安全策略**：
- 公开接口，不校验 token
- 强制按设备自身的 `company_id` 过滤，跨公司无法访问
- 仅返回脱敏后的只读信息

### 5.3 前端移动端页面设计

**新增路由**：`/m/inspect/:equipmentId`

**页面结构**（只读查看）：


## 六、PWA 技术方案

### 6.1 为什么选 PWA 而非小程序

| 对比项 | PWA（本方案） | 微信小程序 |
|---|---|---|
| 开发成本 | 复用 Vue3 项目，改动最小 | 需独立小程序项目，两套代码 |
| 部署方式 | 随现有前端部署，零额外成本 | 需审核发布，周期长 |
| 扫码入口 | 任意浏览器/微信内置浏览器 | 仅微信 |
| 离线能力 | Service Worker 缓存 | 有限 |
| 本项目适配度 | ★★★★★ | ★★☆☆☆ |

### 6.2 PWA 接入步骤

1. **新增 Vant 依赖**（仅移动端路由使用）：
   ```json
   // gbi_platform_admin/package.json
   "vant": "^4.9.0"
   ```

2. **新增移动端路由模块** `src/router/mobile.ts`：
   ```ts
   import { createRouter, createWebHistory } from 'vue-router'
   import StallMobileView from '@/views/mobile/StallMobileView.vue'
   import InspectMobileView from '@/views/mobile/InspectMobileView.vue'

   export default createRouter({
     history: createWebHistory(),
     routes: [
       { path: '/m/stall/:id',    name: 'MobileStall',    component: StallMobileView },
       { path: '/m/inspect/:id',  name: 'MobileInspect',  component: InspectMobileView },
     ]
   })
   ```

3. **注册到主路由**（仅在非 PC 端环境加载）：
   - 通过 `window.location.pathname.startsWith('/m/')` 判断
   - 或使用 Vite `import.meta.env` 区分构建模式

4. **PWA Manifest** 新增 `public/manifest.json`：
   ```json
   {
     "name": "GBI 移动助手",
     "short_name": "GBI",
     "start_url": "/m",
     "display": "standalone",
     "background_color": "#ffffff",
     "theme_color": "#409EFF",
     "icons": [{ "src": "/logo.png", "sizes": "192x192", "type": "image/png" }]
   }
   ```

5. **服务注册**：在 `index.html` 添加 manifest 链接，注册 Service Worker。

## 七、二维码生成与打印流程

### 7.1 PC 端批量生成

**位置**：`gbi_platform_admin/src/views/business/property/leaseStall.vue`

新增操作：
1. 表格新增「二维码」列，显示单条记录二维码缩略图（点击可放大）
2. 顶部新增「批量生成二维码」按钮
3. 点击后弹出对话框，展示所有选中铺位的二维码（每个铺位一张图，可自定义排版：每行 N 个）
4. 提供「下载 PDF」按钮，调用后端批量生成接口，返回 PDF 流

### 7.2 后端批量生成接口

**新增接口**：`POST /property/lease/stall/qrcode/batch`

入参：`List<Long> stallIds`  
返回：`byte[]`（PDF 或 PNG 压缩包）

实现方案：
- 后端使用 Hutool `QrCodeUtil.generate()` 生成每张 PNG
- 使用 iText 或 Apache PDFBox 将多张图合并为 PDF（A4 纸张，每页 6 个二维码，预留边距）
- 若无需 PDF，直接返回 zip 压缩包

## 八、接口权限与安全说明

### 8.1 公开接口说明

移动端 `/m/` 路径下的接口**不强制登录**，但需遵守以下安全约束：

1. **数据隔离**：所有查询强制按铺位/设备自身的 `company_id` 过滤，跨公司无法获取数据
2. **不返回敏感信息**：移动端 VO 不含密码、手机号等敏感字段（如需展示，手机号脱敏为 `136****8278`）
3. **CORS**：允许任意来源（移动端由浏览器直接访问），但建议生产环境限制为白名单域名

### 8.2 后端实现要点

```java
// MobileInspectController 示例（只读）
@GetMapping("/{id}")
public Result<InspectMobileVO> getMobileDetail(@PathVariable Long id) {
    InspectEquipment equipment = equipmentService.getById(id);
    if (equipment == null || equipment.getIsDelete() == 1) {
        return Result.error(404, "巡检点不存在");
    }
    // 不校验 token，仅返回脱敏后的只读信息
    InspectMobileVO vo = toMobileVO(equipment);
    return Result.success(vo);
}
```

## 十、风险与注意事项

| 风险点 | 说明 | 缓解措施 |
|---|---|---|
| 二维码被恶意扫描 | 公开接口可被任意访问 | 仅返回脱敏只读信息，无写操作；生产加 IP 限流 |
| 移动端页面在微信中打开异常 | 微信内置浏览器对 PWA 支持有限 | 使用标准 HTML5 开发，不依赖 Service Worker 核心功能；微信内直接用浏览器打开即可 |
| 批量生成 PDF 性能 | 铺位数量多时生成耗时 | 异步生成 + 任务队列；或前端批量生成（小批量 ≤ 50 个） |
| 二维码粘贴后磨损 | 物理磨损导致无法扫描 | 建议塑封或使用耐久标签 |

## 十二、总结

本方案采用 **PWA + 公开接口** 的技术路线，核心优势如下：

1. **零额外成本**：复用现有 `gbi_platform_admin` 项目，无需新建独立应用
2. **快速落地**：铺位二维码功能 2-3 天可上线，巡检记录查看随巡检模块同步接入
3. **易扩展**：`/m/` 路径作为统一移动端入口，未来新增扫码场景只需新增路由和接口
4. **二维码即入口**：一线人员无需安装任何 App，微信扫码即可使用
5. **数据主权明确**：巡检数据仅由 PC 后台写入，移动端只读查看，避免数据混乱
