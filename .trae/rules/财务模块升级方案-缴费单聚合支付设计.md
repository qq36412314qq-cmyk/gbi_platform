# 财务模块升级方案：缴费单（biz_pay_bill）聚合支付设计

## 一、现状分析

### 1.1 当前表结构关系

```
┌──────────────────┐     ┌──────────────────┐     ┌──────────────────┐
│ biz_fee_bill     │◄────│ biz_fee_bill     │────►│ biz_recv_pay_plan│
│ (统一收费账单)    │     │ (规则快照)        │     │ (应收应付计划)    │
└────────┬─────────┘     └──────────────────┘     └────────┬─────────┘
         │                                                  │
         │ 1:N                                              │ N:1
         ▼                                                  ▼
┌──────────────────┐     ┌──────────────────┐     ┌──────────────────┐
│ biz_finance_flow │────►│ biz_finance_     │────►│ bill_plan_rel    │
│ (财务资金流水)    │     │ writeoff         │     │ (账单-计划关联)   │
└──────────────────┘     └──────────────────┘     └──────────────────┘
         ▲
         │
┌──────────────────┐     ┌──────────────────┐
│ water_elec_pay   │     │ property_fee     │
│ record           │     │ bill             │
│ (水电缴费记录)    │     │ (物业费账单)      │
└──────────────────┘     └──────────────────┘
```

### 1.2 核心问题

| 问题 | 描述 | 影响 |
|------|------|------|
| **无聚合支付载体** | biz_fee_bill 按单一规则生成，一个账单=一个收费项目 | 无法一次支付多个收费项目（如水费+电费+物业费） |
| **缴费粒度错配** | 财务流水(biz_finance_flow)关联单条 biz_fee_bill.id | 合并支付时流水粒度太细，无法体现"一次支付"语义 |
| **缺少缴费单编号** | 前端展示无统一缴费凭证，用户无法感知"我缴了一张单" | 用户体验差，对账困难 |
| **部分支付不支持** | pay_status 仅 0/1/2，无已缴金额/未缴金额跟踪 | 无法支持分期缴、部分退款 |
| **水费电费重复** | water_elec_bill 按类别分多行（水/电各一行），缴费需手动合并 | 无聚合层，多类别需多次支付 |
| **状态值异常** | 数据中 flow_status=6 超出定义范围(1-4) | 状态机不规范，逻辑混乱 |
| **源数据分散** | 旧数据在 water_elec_bill/property_bill，新数据在 biz_fee_bill | 两张表并行，查询复杂 |

### 1.3 数据库现状（2026-09-03）

- biz_finance_flow: 37条（含历史冲红流水）
- biz_fee_bill: 3条（仅新创建，pay_status=2表示部分缴费）
- water_elec_pay_record: 4条
- 数据问题：flow_status 存在值 6（应为 1-4），flow_no 早期记录为 NULL

## 二、设计方案

### 2.1 核心设计思想

**引入「缴费单」(biz_pay_bill) 作为聚合支付载体：**

- 一张缴费单 = 用户可以一次支付的对象
- 缴费单包含 N 条收费明细（biz_pay_bill_item）
- 缴费单级别的状态机：待缴 → 部分缴费 → 已缴 → 已退费/已冲红
- 财务流水关联缴费单（而非单条收费账单）

### 2.2 新增表结构

#### 表1：biz_pay_bill（缴费单主表）

```sql
DROP TABLE IF EXISTS `biz_pay_bill`;
CREATE TABLE `biz_pay_bill` (
  `id` bigint(20) UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `company_id` bigint(20) NOT NULL DEFAULT 0 COMMENT '所属子公司ID',
  `pay_bill_no` varchar(64) NOT NULL COMMENT '缴费单编号（PY+公司编码+日期+序号）',
  `source_type` varchar(32) NOT NULL COMMENT '来源类型 contract=租赁合同 fee_bill=收费账单',
  `source_id` bigint(20) NOT NULL COMMENT '来源单据ID',
  `stall_id` bigint(20) NOT NULL COMMENT '铺位ID',
  `merchant_id` bigint(20) NULL DEFAULT NULL COMMENT '商户ID',
  `total_amount` decimal(12,2) NOT NULL DEFAULT 0.00 COMMENT '缴费单总金额',
  `paid_amount` decimal(12,2) NOT NULL DEFAULT 0.00 COMMENT '已缴金额',
  `unpaid_amount` decimal(12,2) NOT NULL DEFAULT 0.00 COMMENT '未缴金额',
  `pay_status` tinyint(4) NOT NULL DEFAULT 0 COMMENT '缴费状态 0待缴 1部分缴费 2已缴 3已退费 4已冲红 5已作废',
  `pay_time` datetime NULL DEFAULT NULL COMMENT '缴费完成时间',
  `remark` varchar(500) NULL DEFAULT NULL COMMENT '备注',
  `create_by` bigint(20) NOT NULL DEFAULT 0 COMMENT '创建人用户ID',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by` bigint(20) NULL DEFAULT NULL COMMENT '更新人用户ID',
  `update_time` datetime NULL DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `is_delete` tinyint(4) NOT NULL DEFAULT 0 COMMENT '逻辑删除 0正常 1删除',
  PRIMARY KEY (`id`) USING BTREE,
  UNIQUE INDEX `uk_pay_bill_no`(`pay_bill_no` ASC, `is_delete` ASC) USING BTREE,
  INDEX `idx_company_id_is_delete`(`company_id` ASC, `is_delete` ASC) USING BTREE,
  INDEX `idx_stall_id`(`stall_id` ASC) USING BTREE,
  INDEX `idx_source`(`source_type` ASC, `source_id` ASC) USING BTREE,
  INDEX `idx_pay_status`(`pay_status` ASC, `is_delete` ASC) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='缴费单主表（聚合多个收费明细，用户一次支付）';
```

### 2.4 状态机设计

#### biz_pay_bill 状态机

```
          ┌──────────────────────────────────────────┐
          │                                          │
     0 待缴 ──支付──► 1 部分缴费 ──全额支付──► 2 已缴  │
          │                                          │     │
          │                    ┌─────────┐          │     │
          │                    │         │          │     │
          └──► 5 已作废 ◄──────┘         │          └─────┼──► 3 已退费
                  (未缴费作废)            │                     (全额退费)
                                         │
                                   ┌─────┴─────┐
                                   │           │
                              3 已退费      4 已冲红
                              (部分退费)    (财务审批冲红)
```

#### flow_status 规范（修正）

| 值 | 含义 | 说明 |
|---|------|------|
| 1 | 正常 | 正常有效流水 |
| 2 | 冲红中 | 冲红申请已提交，待审批 |
| 3 | 已冲红 | 冲红审批通过，反向流水已生成 |
| 4 | 已作废 | 作废审批通过 |

### 2.5 核心业务流程

#### 流程1：生成缴费单（新建）

**触发时机**：用户在"未支付订单"页面勾选多个待缴账单，点击"合并缴费"

**步骤**：
1. 查询选中的 biz_fee_bill 列表（pay_status=0 或 1）
2. 计算 total_amount = Σ(real_amount - paid_amount)
3. 创建 biz_pay_bill 记录
4. 为每个 biz_fee_bill 创建 biz_pay_bill_item（固化 fee_item_name, rule_name 等快照）
5. 更新各 biz_fee_bill.pay_bill_id
6. 返回缴费单编号

#### 流程2：缴费（全额支付）

**步骤**：
1. 前端传入 pay_bill_id + payType + requestId
2. 幂等检查（requestId 唯一键）
3. 创建 biz_finance_flow（flow_type=1, pay_bill_id=缴费单ID, pay_bill_no=缴费单编号）
4. 更新 biz_pay_bill：paid_amount += 支付金额，unpaid_amount -= 支付金额，pay_status=2
5. 更新各 biz_pay_bill_item.paid_amount
6. 更新各 biz_fee_bill.pay_status=1，pay_time=now
7. 创建核销记录（biz_finance_writeoff）
8. 返回流水单号

#### 流程3：部分支付

**步骤**：
1. 创建 biz_finance_flow（flow_type=1, pay_bill_id=缴费单ID）
2. 更新 biz_pay_bill.paid_amount += 本次金额，unpaid_amount -= 本次金额
3. 如果 unpaid_amount <= 0：pay_status=2（已缴），否则 pay_status=1（部分缴费）
4. 按比例分摊更新各 biz_pay_bill_item.paid_amount
5. 更新对应 biz_fee_bill.pay_status
6. 创建核销记录

#### 流程4：退费

**步骤**：
1. 校验 biz_pay_bill.pay_status ∈ {1,2}（部分缴费/已缴）
2. 创建 biz_finance_flow（flow_type=2, pay_bill_id=缴费单ID）
3. 更新 biz_pay_bill.paid_amount -= 退费金额
4. 如果 paid_amount <= 0：pay_status=3（已退费），否则 pay_status=1
5. 按比例扣减各 biz_pay_bill_item.paid_amount
6. 更新对应 biz_fee_bill.pay_status（如有剩余则改回0）
7. 创建核销记录（writeoff_type=2）

#### 流程5：冲红

**步骤**：
1. 校验 biz_finance_flow.flow_status=1（正常）
2. 创建冲红反向流水（flow_type=1 但金额为负，flow_status=2）
3. 原流水 flow_status=3（已冲红），red_flush_flow_id=新流水ID
4. 更新 biz_pay_bill 回退状态
5. 创建核销记录（writeoff_type=3）

#### 流程6：作废

**步骤**：
1. 校验 biz_pay_bill.pay_status=0（待缴）
2. 更新 biz_pay_bill.pay_status=5
3. 逻辑删除各 biz_pay_bill_item
4. 不产生财务流水

### 2.6 数据迁移方案

#### 迁移阶段（存量数据）

```sql
-- 1. 将已缴费的 water_elec_pay_record 回填 pay_bill_id（暂无缴费单，标记为 NULL）
-- 2. 将 biz_fee_bill 中已关联的流水更新 pay_bill_id
-- 3. flow_status 异常值修正
UPDATE biz_finance_flow SET flow_status = 1 WHERE flow_status NOT IN (1,2,3,4);

-- 4. 创建迁移视图（过渡期兼容）
CREATE OR REPLACE VIEW v_pay_bill_compat AS
SELECT 
  f.id, f.company_id, f.business_type, f.bill_id as fee_bill_id,
  f.stall_id, f.original_amount, f.real_amount,
  f.flow_type, f.flow_status, f.flow_no,
  f.pay_bill_id, f.pay_bill_no,
  'legacy' as source
FROM biz_finance_flow f
WHERE f.pay_bill_id IS NULL;
```

## 六、风险评估

| 风险 | 等级 | 应对措施 |
|------|------|----------|
| 存量数据关联断裂 | 高 | Phase 1 先回填 pay_bill_id，保持向后兼容 |
| 缴费单编号冲突 | 低 | 唯一索引 uk_pay_bill_no，分布式 ID 生成 |
| 部分支付金额精度 | 中 | 使用 BigDecimal，分摊时保留两位小数 |
| 冲红状态机复杂 | 中 | 严格校验 flow_status，仅允许 1→2→3 流转 |
| 前端缓存旧接口 | 低 | 接口路径不变，仅新增字段 |
